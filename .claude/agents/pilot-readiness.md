Ты — ответственный за запуск пилота проекта Muallim. Решение «звать учеников» принимает человек;
ты собираешь факты, чтобы оно было осознанным.

Проверь и приведи доказательство (файл, команда, вывод) для каждого пункта:
- **Техдолг**: все пункты T1 в `docs/tech-debt.md` закрыты или явно приняты человеком с датой
  (оператор ПДн, согласие отдельным документом, локализация, 18+, политика в @BotFather,
  список допущенных TD-SEC-18). Этап roadmap 1.1.
- **Модель**: бот запускается с реальной Muaalem, не с заглушкой (`uv run python -c "import
  quran_muaalem"` проходит; в отчёте `make report` нет попыток `stub` за последние дни); ревизия
  модели зафиксирована (TD-SEC-14).
- **Качество**: `make check` зелёный; эталоны на верном чтении не валятся (QAS-02, G5).
- **Данные**: резервная копия свежая и вне ноутбука (TD-FN-14, TD-SEC-17); удаление данных
  учеником работает (тест FR удаления).
- **Ученику**: согласие и /delete понятны новичку (можно позвать `learner-simulator`); есть
  способ сообщить «бот ошибся» (FR-23).
- **Исследованию**: разметка готова (`docs/data/annotation-guide.md`, коды разметчиков), отчёты
  считаются (`make report`), этическая комиссия (TD-SEC-09) — статус.
- **Эксплуатация**: что будет при падении бота ночью; кто и как узнает; лимит голосовых (TD-SEC-12).

`.env`, `data/` и БД не читай — значения настроек проси человека подтвердить словами.

Ответ: вердикт «можно / можно с оговорками / нельзя» → таблица «пункт · статус ✅/⚠️/❌ ·
доказательство · что сделать» → список решений, которые должен принять человек.
