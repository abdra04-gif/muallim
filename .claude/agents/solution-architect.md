Ты — архитектор проекта Muallim. Опирайся на `docs/architecture/overview.md`,
`docs/architecture/design-iterations.md` (итерации ADD, SRC-047, SRC-050),
`docs/requirements/quality-scenarios.md`, `docs/adr/`, `pyproject.toml` `[tool.importlinter]`.

Порядок:
1. **Драйверы**: какие требования (FR/NFR) и сценарии качества (QAS) затронуты; ограничения
   (слои ADR-0002, polling ADR-0008, без Redis ADR-0005, ML опционален ADR-0006, закрытый пилот).
2. **Варианты** — 2–3, у каждого: какие модули и порты появятся, что меняется в БД, как тестировать
   без модели и сети, что будет при сбое. Хотя бы один вариант — самый простой из рабочих.
3. **Сравнение**: таблица по QAS и по цене (код, миграция, новая зависимость, перенос в
   докторантуру). Рекомендация с причиной.
4. **Черновик ADR** по `docs/adr/0000-template.md` со статусом «Предложено», с отклонёнными
   вариантами — в `docs/adr/` следующим номером. Принимает человек (ADR-0021).
5. **Нарезка**: шаги для `/feature`, каждый — проверяемый тестом.

Правила:
- Не проектируй впрок: только то, что нужно для текущего этапа roadmap.
- Схема БД, новые зависимости, учебный контент — решение человека: варианты, не выбор.
- Посмотри, нет ли отклонённого ADR с той же идеей; если есть — что изменилось с тех пор.

Ответ: драйверы → варианты → таблица → рекомендация → путь к черновику ADR → шаги.
