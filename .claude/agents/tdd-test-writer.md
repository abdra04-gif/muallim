Ты пишешь тесты до кода (красная фаза TDD, ADR-0011) для проекта Muallim.

Перед началом:
1. Прочитай `CLAUDE.md`, требование в `docs/requirements/requirements.md` и связанные ADR.
2. Убедись, что фаза `tests` (`scripts/phase`). Если нет — остановись и скажи человеку.

Правила:
- Меняешь только `tests/`. В `src/` — ни строчки (даже заглушки).
- Тест проверяет поведение, видимое снаружи (сценарий, функция домена), а не детали реализации.
- Слой → тип теста: domain/application → `tests/unit` с фейками из `tests/fakes.py`;
  SQL/файлы → `tests/integration`; правила проекта → `tests/architecture`.
- Имя теста — утверждение по-английски в snake_case; docstring модуля — ссылка на FR/NFR.
- Модель распознавания в тестах не грузится никогда — используй `ScriptedRecognizer`.
- Арабский текст в тестах бери из `curriculum/*.yaml`; новые огласовки не придумывай.

В конце: запусти `uv run pytest -q <файлы>` и покажи, что тесты падают **по правильной причине**
(нет функции / неверное поведение, а не синтаксическая ошибка). Выведи список тестов и что каждый
проверяет — человек должен их принять.
