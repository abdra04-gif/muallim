# ADR-0003: Внедрение зависимостей через контейнер dishka

- **Статус:** Принято
- **Дата:** 2026-10-17
- **Кто решил:** Исмаилов
- **Связано:** ADR-0002, NFR-MNT-02, SRC-008

## Контекст
Сценарии (`application/use_cases`) зависят от портов: хранилищ, распознавателя, часов. Кто-то должен
создавать реализации и передавать их сценариям — по одной сессии БД на апдейт Telegram и по одному
экземпляру модели на всё приложение.

## Решение
Контейнер **dishka** (SRC-008): области `APP` (модель, движок БД, учебная программа) и `REQUEST`
(сессия БД, репозитории, сценарии). Вся «склейка» — в одном файле `bootstrap/di.py`; обработчики
получают сценарии через `FromDishka[...]`.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Глобальные объекты, как в прототипе | просто | нельзя подменить в тестах, модель грузится при импорте | Отклонено |
| Ручная сборка в `main.py` | без зависимостей | сессия БД на запрос требует своей middleware | Отклонено |
| dependency-injector | популярный | синхронный, тяжелее в настройке | Отклонено |
| dishka | async, области видимости, интеграция с aiogram | ещё одна зависимость | **Принято** |

## Как проверить
`tests/integration/test_di.py` — контейнер собирается и разрешает все сценарии;
`tests/architecture/test_layers.py::test_every_use_case_is_wired_in_di`.
