# ADR-0007: Два допустимых эталона — с остановкой (вакф) и слитно (васл)

- **Статус:** Принято (методическое решение, перенесено из прототипа)
- **Дата:** 2026-10-17 (решение принято в прототипе, коммит 695ce27)
- **Кто решил:** Исмаилов
- **Связано:** `docs/pedagogy/methodology.md`, FR-04

## Контекст
Ученик читает отдельное слово. Его можно прочитать с остановкой на конце (огласовка не произносится)
или так, будто чтение продолжается (огласовка произносится). Оба варианта правильные.

## Решение
Распознаватель строит два эталона: с вакфом (`quran_phonetizer(текст)`) и слитный — фонетизация
`текст + " مَ"` без последнего символа. Оценка берётся по лучшему из двух.

## Дополнение 2026-10-23 (аудит карточек, TD-FN-10)
Текст программы хранится после нормализации Unicode NFC: огласовка стоит перед шаддой и перед хамзой над
татвилем, «ا + ٓ» склеено в «آ». Шрифт рисует оба порядка одинаково, а фонетизатор — нет: на 31 карточке
эталон терял удвоение шадды, на 36 падал (голосовое не проверялось). Поэтому:
1. Перед фонетизатором текст переводится в порядок мусхафа — `infrastructure/asr/script.py`
   (`for_phonetizer`); начальный «اِ/اَ/اُ» книги — хамзой («إِ/أَ/أُ»): так слово читают, начиная с него.
2. Из обоих вариантов эталона убираются знаки вне алфавита фонем модели (`alphabet.phonetics`) — например
   «ٓ» над словом, вырезанным из аята: модель его не выдаёт, а в «Как читается» он виден арабским значком.

**Отклонено:** хранить программу в порядке мусхафа без NFC (правка `scripts/book/` и всей программы — зона
человека, а NFC вернёт любой редактор или копирование); чинить только в `scripts/book/build.py` (не защищает
от текста, пришедшего другим путём). Исправление в адаптере покрывает любой вход; тест — по всей книге
(`tests/integration/test_reading_guide.py`).

## Ограничения
Приём с добавлением «مَ» — инженерный; его корректность для всех слов книги нужно проверить
с преподавателем (вопрос OQ-03 в `docs/research/open-questions.md`).
