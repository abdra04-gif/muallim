# ADR-0051: Адаптация модели на собственном наборе — часть цели магистерской; RQ перестроены

- **Статус:** Принято автором; тема, гипотезы и пороги — **[утвердить]** с руководителем; **частично заменено:** адаптация модели — теперь один из компонентов RQ-2, ADR-0064 (2026-10-22); разметка теста — с ответом бота, ADR-0065 (2026-10-22)
- **Дата:** 2026-10-18
- **Кто решил:** автор («цель — также обучение модели на моём датасете; задел на PhD, крепкая магистерская»;
  выбрал B1 + B2, 4 RQ с новым центральным RQ-2, переписать всё сразу); дизайн предложил агент
- **Связано:** ADR-0006 (заменяемый распознаватель), ADR-0019 (сырой выход модели), ADR-0036 (предрегистрация),
  ADR-0044 (самоисправления), TD-FN-02 («не уверен»), R-02, R-14; SRC-002, SRC-067, SRC-111…SRC-123

## Контекст
Было: дообучение модели вынесено в докторантуру, вклад магистерской — оценка готовой модели (B0).
Для программы «Программная инженерия» и как основа докторской этого мало: работа измеряет чужую
модель, но не улучшает её. Набор, который соберёт пилот, — чтение русскоязычных начинающих с разметкой
учителей по фонемам — сам просит обучения. Данных будет немного (20–40 учеников, порядка тысяч коротких
попыток), поэтому способ обучения должен работать на малых данных и иметь честный запасной результат.

## Решение
1. **Цель** — не только измерить Muaalem, но и адаптировать её к русскоязычным начинающим на собранном наборе
   и измерить, сколько разрыва с учителем закрывает адаптация.
2. **Три системы на одних и тех же записях:**
   - **B0** — Muaalem как есть + правила + пороги (сейчас в боте);
   - **B1** — обученный верификатор поверх выходов Muaalem (признаки GOP, SRC-115; уверенность по фонемам,
     SRC-062) с калибровкой (SRC-112) и исходом «не уверен»; порог выбирается конформным контролем риска
     так, чтобы доля ложных отклонений не превышала ε (SRC-113, SRC-114, SRC-117). Работает на сотнях
     примеров и на CPU;
   - **B2** — дообучение Muaalem методом LoRA (SRC-111, SRC-116) на фонемах, исправленных учителями, с
     пополнением данных: верное чтение карточки одной буквы минимальной пары книги — пример ошибки для
     карточки другой (SRC-119), изменение скорости (SRC-120).
3. **Разбиение по ученикам, тест заморожен.** До обучения ≈ 30 % учеников (стратифицировано по L1 и
   активности) уходят в тест; их попытки размечаются **вслепую** (разметчик не видит ответ бота) двумя
   учителями с согласованием. Гиперпараметры — только кросс-валидацией по ученикам внутри обучающей части
   (SRC-121). Тест считается один раз замороженным оценщиком (SHA-256), агенту чтение меток теста запрещено
   хуком — правила R1–R5 группы руководителя (SRC-067) и таксономия утечек (SRC-122).
4. **Четыре RQ:** RQ-1 — B0 против учителей + профиль ошибок (бывший RQ-2 влит сюда); **RQ-2 — адаптация
   (новый, центральный)**; RQ-3 — объяснения; RQ-4 — обвязка, теперь включая защиту экспериментов обучения.
5. **Теневой запуск.** Адаптированная модель работает в боте в тени (ученик видит B0, вердикт B1/B2
   пишется рядом) — эксперимент RQ-3 не смешивается со сменой модели; переключение — после защиты.

|---|---|---|
| RQ-1 | RQ-1 | согласие B0 с учителями |
| RQ-2 | RQ-1 (вторая часть) | профиль ошибок, ошибки ученика vs модели |
| — | **RQ-2** | адаптация модели (B1, B2) |
| H2.2 | H1.4 | твёрдость vs место образования |

## Рассмотренные варианты
| Вопрос | Выбрано | Отклонено и почему |
|---|---|---|
| Что обучать | B1 + B2 | только B2 — на сотнях попыток дообучение может ничего не дать, и главного результата не будет; только B1 — надёжно, но слабо как «обучение модели на своём наборе» |
| RQ | 4, новый RQ-2 центральный | 5 RQ — перегруз для магистерской; обвязку в приложение — для программы «Программная инженерия» рискованно |
| Оценка | замороженный тест по ученикам, слепая разметка | случайное разбиение по попыткам — утечка диктора (SRC-122); только CV по всем ученикам — экономнее, но нет «одного взгляда на тест» и слепой разметки всего набора не хватит |
| Развёртывание | тень до конца пилота | сразу заменить B0 — смешало бы RQ-3 со сменой модели |
| Обучение с нуля / другая архитектура | нет | данных на порядки меньше нужного; вклад — адаптация открытой модели |

## Последствия
- **Нужно до пилота (человек):** согласие ученика должно явно разрешать обучение модели на его голосе и
  публикацию весов (TD-SEC-02, TD-SEC-16; текст согласия — только человек); слепой режим разметки в
  руководстве (`annotation-guide.md`, решает человек); вычислительный ресурс для B2 (GPU ≥ 24 ГБ — кластер
  университета или облако) **[утвердить]**; новые зависимости (`peft`, `scikit-learn`) — через `dep_check`.
- **Ноябрь–декабрь 2026:** конвейер обучения и оценки отлаживается на открытых данных (Iqra'Eval, RetaSy —
  лицензии проверить), чтобы в апреле на данных пилота он только запускался.
- **Запасной путь:** если к 15.04.2027 в обучающей части меньше ≈ 1 500 размеченных попыток, B2 подаётся как
  проверка осуществимости (разведка), H2.2–H2.3 снимаются новой версией предрегистрации, RQ-2 отвечает B1.
- **Лицензии:** модель и код Muaalem — MIT, база `facebook/w2v-bert-2.0` — MIT (проверено 2026-10-18): R-14 снижен.
- Исторические документы (ADR, CHANGELOG, журналы) не переписываются: старая нумерация в них остаётся,
  соответствие — в таблице выше.
