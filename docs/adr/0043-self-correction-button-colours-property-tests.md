# ADR-0043: Самоисправление — отдельная категория разметки; цвет кнопок; свойства оценки (Hypothesis)

- **Статус:** Принято; в части метрик RQ-1 заменено ADR-0044
- **Дата:** 2026-10-18
- **Кто решил:** Исмаилов — «Hypothesis да», «самоисправления считай отдельной категорией»,
  «новые возможности Telegram давай», «задания на слух и напоминания — потом, не забыть».
  Устройство (признак, а не статус; где цвет; какие свойства) предложил агент.
- **Связано:** ADR-0040, ADR-0041, ADR-0042, FR-17, TD-FN-18, TD-FN-59, TD-FN-63, TD-FN-64,
  TD-FN-66, TD-FN-68, SRC-068, SRC-070, SRC-080, SRC-088, SRC-096

## Контекст
У научрука в таксономии ошибок чтения есть исправленные события (`substitution_corrected`,
`omission_corrected`, SRC-068): чтец ошибся и сам перечитал верно. У новичков это частое
явление, а разметка проекта (руководство 2.0) его не различала. Bot API 9.4 добавил цвет кнопок
(aiogram 3.31 поддерживает, SRC-088). Оценка чтения проверялась только примерами.

## Решение
1. **`self_corrected` — признак рядом с меткой**, а не новый статус: `status` по-прежнему
   отвечает «верно ли услышал бот» (`agree`/`fix`), признак — «ученик сам исправился». Только при
   `agree`/`fix`. Руководство 2.1; колонка `annotations.self_corrected` (миграция 0006; `NULL` —
   прежние метки, «не спрашивали»); Excel — колонка `self_corrected` («да»/пусто; старые пакеты
   без неё загружаются); Telegram — переключатель «🔁 Сам исправился» до ответа; отчёт 05 и
   датасет показывают признак отдельно.
2. **Метрики RQ-1 не меняются**: оценщик заморожен (ADR-0042), правила — в предрегистрации.
   Как учитывать самоисправления — решить до анализа (TD-FN-68).
3. **Цвет кнопок:** в ответе викторины варианты остаются на экране — верный зелёный, выбранный
   неверный красный, «Дальше» синий; удаление данных — красное. **Согласие на исследование не
   окрашено**: оба ответа равны, цвет не подталкивает к «да» (этика, TD-SEC-02).
4. **Свойства оценки (Hypothesis 6.168.3, только dev):** точное чтение — 100 и «отлично»;
   балл 0–100; ошибки указывают в эталон и не пустые; детерминизм; «отлично» только без ошибок;
   «не дочитал» — существующий слог; лучший эталон — ближайший, при равенстве первый.
5. **Отложено, записано в `docs/roadmap.md` («⏰ Не забыть»):** напоминания (TD-FN-18), задания на
   слух (TD-FN-64), звуки букв научрука (TD-FN-65), эталон внутри разбора (TD-FN-66).

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Новый статус `self_corrected` вместо признака | одна колонка | теряется главное — прав ли бот; метрики RQ-1 потеряли бы эти попытки | Отклонено |
| Признак на каждую ошибку (как события SRC-068) | точнее | разметка по событиям — другой формат, вдвое дольше для разметчика | Отклонено для магистратуры; кандидат для докторантуры |
| Сразу исключить самоисправления из метрик | «чище» RQ-1 | меняет предрегистрацию и замороженный оценщик без данных | Отложено (TD-FN-68) |
| Индикатор «распознаю…» через `sendMessageDraft` | новинка API | уже есть сообщение `LISTENING`, которое удаляется после ответа | Не нужно |
| Эталон в разборе через rich messages (Bot API 10.1–10.2) | слушать, не уходя из разбора | переписать экран результата; старые клиенты могут не показать сообщение | Отложено (TD-FN-66) |
| Зелёная «Да» в согласии | заметнее | подталкивает к согласию — нарушает добровольность | Отклонено |
| Hypothesis последней версии (6.170.1) | свежая | вышла за 2 дня до решения — риск цепочки поставок | Отклонено; 6.168.3 |

## Последствия
- Разметчику +1 кнопка в Telegram и +1 колонка в Excel; метки версии 2.0 остаются валидными.
- Сравнение разметчиков (κ, α) по признаку `self_corrected` возможно после пилота.
- Тесты +~3 с на свойства (300 примеров на свойство).
