# ADR-0028: Практики из командного проекта: что взято, что отклонено

- **Статус:** Принято
- **Дата:** 2026-10-17
- **Кто решил:** автор («бери всё, что стоит взять, и то, что не обязательно»); отказ от проверки грамматики выбрал автор; способ проверки ссылок предложил агент по поручению автора
- **Связано:** NFR-TR-02, NFR-TR-05, NFR-SEC-07, TD-FN-06, TD-FN-21, TD-FN-28, ADR-0026, ADR-0027, R-15

## Контекст
Автор участвовал в командном проекте Иннополиса — платформе калькуляторов для «Газпром автоматизации»
(Java/Spring, React, GitLab CI). Его код к боту не подходит: другая область и другой стек. Зато в нём
есть приёмы процесса и документации, которых в этом проекте не было. Что сравнивали: реестр рисков,
E2E-тесты (Playwright), проверку ссылок (lychee), проверку грамматики (LanguageTool), user stories,
протоколы встреч с заказчиком, ADD-итерации, карту контекстов, статусы в матрице трассировки,
стратегию логирования, SonarCloud, RASCI и story points.

## Решение
Взяли, но переделали под один автор + ИИ-агент. Где можно, правило проверяет тест, а не только документ:

| Практика | У них | У нас | Чем проверено |
|---|---|---|---|
| Реестр рисков | P × I, статусы, закрытые с доказательством, процесс пересмотра | `docs/risks.md`: риски целей диссертации со ссылками на TD/OQ/QAS; пересмотр перед встречей с руководителем | — (документ) |
| E2E | Playwright, браузер | `tests/integration/test_bot_flow.py`: настоящий диспетчер aiogram и DI, фейковая сессия Telegram | сам тест; закрывает TD-FN-06 |
| Логирование | ADR о логах | ADR-0027 + фильтры и тесты | `test_logging.py`, `test_logs.py` |
| Ссылки | lychee по всем `*.md` в CI | внутренние ссылки — pytest (офлайн, локально и в CI, блокирует); внешние URL — lychee раз в неделю на GitHub, не блокирует | `test_docs.py`; закрывает TD-FN-28 |
| User stories | US-U/US-A | `requirements/user-stories.md`: ученик с нуля, учитель, исследователь; ссылки на FR | `test_user_stories_reference_existing_requirements` |
| Встречи с заказчиком | протоколы по спринтам | `journal/meetings/`: встречи с руководителем и преподавателями, шаблон, связь с OQ и рисками | — |
| ADD-итерации | файл на итерацию | `architecture/design-iterations.md`: строка на итерацию, подробности в ADR; 1–7 восстановлены по ADR | — |
| Карта контекстов | context map | `architecture/overview.md` §2.1 + схема `07-contexts` | `test_diagrams_rendered` |
| Статусы трассировки | ✅ ⏳ ❌ | колонка «Проверка» ✅ 🟡 ❌ | `test_traceability_rows_have_honest_status` |

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Проверка ссылок только lychee в CI | проверяет и внешние URL | нужна сеть; падает из-за чужих сайтов; локально не работает; репозитория на GitHub пока нет (TD-FN-27) | отклонён как единственная проверка; оставлен для внешних URL, без блокировки |
| Проверять все пути в `…` | максимум охвата | ~80 ложных тревог: короткие записи (`db/`, `drafts/`), шаблоны (`ГГГГ-ММ-ДД`), отклонённые варианты в ADR | отклонён; проверяются ссылки `[…](…)` и пути от корня (`src/`, `docs/`, …) |
| LanguageTool в CI | ловит опечатки | русский текст с арабским и терминами таджвида даёт много ложных тревог; нужны Java и новая зависимость | **отклонён автором** |
| SonarCloud | дашборд качества | дублирует ruff, mypy --strict, import-linter и покрытие; у них Java-анализ работал без байткода (`dummy-binaries`) | отклонён |
| RASCI, story points, спринты | распределение работы в команде | один автор; время и так видно в журнале сессий | отклонён |
| Swagger, мок внешнего API | контракт фронта и бэка | у бота нет HTTP API; мок модели уже есть — `StubRecognizer` (ADR-0006) | не применимо |
| Полные документы ADD-итераций | подробно | для одного автора бюрократия; всё уже есть в ADR | отклонён; строка на итерацию |

## Последствия
- Добавлены NFR-SEC-07 (логи) и NFR-TR-05 (ссылки); закрыты TD-FN-06, TD-FN-21, TD-FN-28.
- Перед встречей с руководителем — пересмотр рисков и протокол встречи (процесс в `docs/risks.md`).
- Внешние ссылки начнут проверяться, когда проект будет на GitHub (TD-FN-27).
- `presentation/telegram/*` по-прежнему исключён из подсчёта покрытия, хотя сквозной тест проходит через 61 % `handlers.py`.
  Включить модуль в подсчёт — решение автора: общий процент упадёт.

## Как проверить
`make check`: тесты из таблицы «Решение» и `tests/architecture/test_docs.py` целиком.
