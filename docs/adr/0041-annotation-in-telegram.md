# ADR-0041: Разметка в Telegram наравне с Excel и доступ только разметчикам

- **Статус:** Принято
- **Дата:** 2026-10-18
- **Кто решил:** автор (варианты предложил агент)
- **Связано:** FR-17, ADR-0040, ADR-0024, NFR-SEC-02, TD-SEC-20, TD-SEC-21, TD-FN-48, TD-FN-49

## Контекст
Пакет Excel (ADR-0040) требует флешки, отдельного плеера и ручной передачи файлов. Автор хочет,
чтобы проверяющему было легко открывать и просматривать ответы учеников, видеть ошибки бота и
только подтверждать, но иметь возможность прослушать и записи, которые бот засчитал. При этом
никто, кроме разметчиков, не должен попасть в разметку и нажимать кнопки.

## Решение
- **Telegram и Excel на равных** (решение автора): одна очередь (`queue_query`), одни правила
  (`domain/annotation.py`: `check_phonemes`, `check_label`), одна таблица `annotations` с полем
  `source` и временем ответа `seconds_spent` (только Telegram).
- **Исправление точное по фонемам** (автор: «пусть будет сложно, но правильно — обучаем модель»):
  разметчик присылает фонемы сообщением, бот проверяет их так же, как загрузка Excel, с подсказками.
- **Доступ двумя путями** (автор: «оба варианта»): список `ANNOTATOR_IDS` (`код:Telegram ID`,
  отдельно от `TEACHER_IDS`) и одноразовое приглашение на сутки (`muallim-research
  annotator-invite`): в БД хранится SHA-256 кода, приглашение гасится одним UPDATE с условием;
  после 5 неверных кодов за час вход закрыт. `annotator-revoke` закрывает доступ сразу, в том числе
  разметчику из настроек, и гасит невошедшие приглашения.
- **Защита**: права проверяет сценарий при каждом действии (подделанная или старая кнопка без
  доступа ничего не делает); без доступа `/annotate` уходит обработчику ученика — посторонний не
  узнаёт о разметке; только личный чат; записи с `protect_content`; кто ученик — не показывается;
  действия — в `interaction_events`.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Только список в настройках | проще, добавить себя нельзя | каждый раз узнать ID и перезапустить бота | принято вместе со вторым |
| Только приглашение | без перезапуска | таблица в БД; код может утечь в первые сутки | принято вместе с первым |
| Ловушки (записи с известным ответом) | видно, кто нажимает не слушая | записи-ловушки, сложнее | **отклонено автором**: «доверяю своим разметчикам» |
| Кнопки только после длительности записи | нельзя ответить быстрее записи | Telegram не сообщает, прослушано ли; раздражает | отклонено автором (вместе с ловушками) |
| Слепая разметка в Telegram | честнее κ «бот — учитель» | дольше; противоречит ADR-0040 | отклонено автором (угроза — `preregistration.md` §5) |
| Исправление кнопками «буква → как прозвучала» | легче учителю | неточно для огласовок, мадда, лишних звуков | отложено; точность важнее (данные для обучения) |
| Label Studio | готовый интерфейс | сервер, голоса на сервере | отложено (как в ADR-0040) |

## Последствия
- Миграция 0005: `annotations.source`, `annotations.seconds_spent`, таблицы `annotators`,
  `annotator_invites` (`docs/data/data-dictionary.md`).
- Тексты разметчику — черновик агента (`presentation/telegram/annotator_texts.py`, TD-FN-49).
- До пилота: согласие ученика должно упоминать прослушивание разметчиком (TD-SEC-20),
  разметчик подписывает обязательство (TD-SEC-21).
- Ожидание исправления и время показа — в памяти процесса (TD-FN-48).

## Как проверить
`tests/unit/test_annotation.py` (правила, доступ, приглашения, сценарии),
`tests/integration/test_annotators_sql.py` (приглашение в БД — отпечаток, отзыв, очередь как в Excel,
источник метки), `tests/integration/test_annotator_bot.py` (посторонний ничего не видит, подделанная
кнопка не работает, запись без пересылки, «бот прав», исправление с подсказкой, вход по приглашению,
отзыв сразу).
