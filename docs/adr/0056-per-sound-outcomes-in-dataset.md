# ADR-0056: Итог по каждому звуку в выгрузке датасета — где именно и как ошиблась модель

- **Статус:** Принято
- **Дата:** 2026-10-20
- **Кто решил:** автор (вариант А из предложенных); реализацию предложил агент
- **Связано:** FR-14, RQ-1, RQ-2, ADR-0040, ADR-0055, SRC-043, SRC-063, SRC-064

## Контекст
Главная цель — разметить датасет с учителем и обучать на нём модель. Учитель проверяет, что
сказал ученик, и видит, где модель нашла ошибку верно, где не ту, где пропустила и где решила, что
ученик ошибся, хотя он прав. Разметчик записывает, что прозвучало (руководство 2.x, ADR-0040);
сравнение «эталон — модель — учитель» по каждой фонеме уже считалось (`metrics.phoneme_decisions`),
но только в сумме: нельзя было увидеть, в какой попытке и на каком звуке модель ошиблась.
Поле `annotations.detected_error_id` (удалено в ADR-0055) этого не давало: метка привязывалась
только к найденной моделью ошибке, а пропущенную привязать не к чему.

## Решение
- `metrics.phoneme_outcomes(эталон, модель, разметчик)` — строка на каждую фонему: что ждали, что
  услышала модель, что — разметчик, итог MDD (`correct_accept` / `false_rejection` /
  `false_accept` / `true_rejection`), совпал ли диагноз, тип ошибки у модели и у разметчика.
  `phoneme_decisions` (цифры отчёта) — сумма того же разбора: по попытке итоги совпадают (тест);
  по всему файлу — после тех же фильтров (в файле только ученики с согласием; главные цифры — без
  самоисправлений, ADR-0044).
- `dataset-export` пишет `phonemes.csv` (UTF-8 с BOM — для Excel) — по каждому звуку для каждого
  разметчика, с `agrees_with_consensus`, `self_corrected` и `comparison_version`
  (`COMPARISON_VERSION`, меняется с правилом). Столбцы «что услышано» — для показа: вставки на
  своём месте и все, если их несколько у одного звука.
- Не изменено (методика, решает автор): при двух вставках у одного звука `same_diagnosis`
  сравнивает только первую — как и прежняя метрика.
- Схема БД не меняется: итог вычисляется из того, что записал разметчик.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Вычислять при выгрузке, файл `phonemes.csv` + версия правила | не расходится с разметкой; без миграции | итоги не лежат в БД | **принято** |
| Представление в БД | видно в DBeaver | выравнивание строк фонем на чистом SQL (SQLite и PostgreSQL) не написать | отклонено при реализации |
| Отдельная таблица итогов при загрузке разметки | итоги в БД навсегда | дублирует данные; после переразметки устаревает | отложено: если понадобится в DBeaver |
| Вернуть `detected_error_id` | — | не видит пропущенных ошибок, учителю лишняя работа | отклонено |

## Последствия
- Для обучения: запись + `consensus_phonemes` (что прочитано) — цель; `phonemes.csv` — для разбора
  ошибок модели, отбора трудных звуков и сравнения версий модели по звукам.
- Изменение правила сравнения (`phoneme_errors`) — вместе с `COMPARISON_VERSION`.
