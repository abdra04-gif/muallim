# ADR-0073: Параллельные сессии — одна в основной папке, остальные в своих копиях (worktree)

- **Статус:** Принято
- **Дата:** 2026-10-25
- **Кто решил:** автор («нужно универсальное решение», «делай»); устройство — агент
- **Связано:** ADR-0012, ADR-0039, ADR-0071; `docs/process/git.md` → «Параллельные сессии»

## Контекст
2026-10-24 две сессии Claude одновременно работали в одной папке. Что произошло:
- коммит одной сессии забрал подготовленные файлы другой;
- CLAUDE.md попал в коммит пустым в ту секунду, когда его переписывали;
- коммит лёг на старую основу и откатил чужие исправления;
- незаконченные TDD-тесты одной сессии не давали другой закончить работу и сделать push.

Причина одна: у сессий общие индекс git, рабочие файлы, фаза TDD (`.agent-phase`) и проверки хуков.

## Решение
Изоляция включается сама и только тогда, когда сессий больше одной:
1. Хук `session_lock`: метка «чья основная папка» в `.git/claude-main-session.json`. Метку
   получает сессия при первой правке. Вторая сессия при старте получает строку «перейди в
   копию», при правке или git-записи в основной папке — блок; чтение свободно. Метка снимается
   при выходе (SessionEnd) или через 30 минут без действий. Сбой хука не блокирует (fail-open).
2. Вторая сессия переходит в копию `.claude/worktrees/<имя>` инструментом `EnterWorktree`.
   Дальше Claude Code сам не даёт ей править основную папку.
3. `_common.ROOT` берётся из `cwd` события: хуки (фаза, `stop_gate`, `doc_sync`, `git_guard`)
   проверяют копию сессии. Раньше они всегда смотрели в основную папку.
4. `.worktreeinclude` копирует `.env`. `.gitattributes`: журналы и CHANGELOG сливаются
   `merge=union`. `doc_sync` ловит два ADR с одним номером.
5. `/ship` в копии: rebase на `origin/main`, проверки, `git push origin HEAD:main`.
6. Правило «с подтверждения» для `.claude/` сужено до настроек, хуков, агентов, команд и
   скиллов. Иначе каждая правка внутри `.claude/worktrees/<имя>` просила бы подтверждения.

Цена в токенах: одна сессия — ~0 (хук молчит). Вторая сессия — строка при старте и одно
действие `EnterWorktree`; `/ship` — одна лишняя команда.

## Отклонено
- **Копия всегда, для каждой сессии.** Лишняя работа, когда сессия одна, а это обычный случай.
- **Коммит только своих путей (`git commit -- пути`) без изоляции.** Решает только гонку индекса.
  Если обе сессии правят один файл, его правки всё равно смешаются. Чужие красные тесты
  по-прежнему блокируют, фаза TDD по-прежнему общая.
- **Правило «параллельно только код + тексты».** Человек должен его помнить, и оно не защищает
  от общих файлов (журналы, CHANGELOG).
- **Хуки проверяют «только свои файлы» (учёт правок по сессиям).** Сложно, и общие файлы
  всё равно переписываются на лету.
- **Хук `WorktreeCreate` с копиями вне проекта.** Тогда не работает `.worktreeinclude`, и всю
  подготовку копии пришлось бы писать самим.

## Последствия
- Бот с настоящим токеном, миграции и база — только в основной сессии; в копии — `make try`.
- Сессия молчит больше 30 минут и потом продолжает, а метку за это время взяла другая сессия →
  первая получит блок и уйдёт в копию. Обе сразу основную папку не правят.
- Если обе сессии меняют одни и те же строки, при rebase будет конфликт. Его решает человек.
- Не проверено на живых сессиях: срабатывает ли подсказка `SessionStart` в расширении VS Code.
  Блок на `PreToolUse` сработает в любом случае.
