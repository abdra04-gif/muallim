# ADR-0088: Встраивание «вариантов карточки» на MostafaMaroof в бота (вся книга)

- **Статус:** Принято автором 2026-11-19 (вариант Б); в коде — в работе (`/feature`, уровень L)
- **Дата:** 2026-11-19
- **Кто решил:** автор; варианты — агент-архитектор (ADR-0021)
- **Связано:** ADR-0002, ADR-0006, ADR-0019, ADR-0086, ADR-0087 (п. 4, 7–10), NFR-ACC-01, NFR-PERF-01, NFR-REL-02, FR-24, NFR-TR-03, FR-43, FR-54, QAS-01–04, QAS-09, TD-FN-121, SRC-169

## Контекст
ADR-0086/0087 решили, что новичок на уроках 1–41 получает ответ способа «варианты карточки» на
модели MostafaMaroof: верное чтение (wasl/waqf) против типичных ошибок и соперника «другой слог»,
пороги 0/−4 и −6/−3, исход «прочитай ещё раз» (не больше раза подряд), мягкие подсказки про шадду и
мадд, «ясная гласная» на последнем слоге. Прототип — `docs/research/phase3/` (`to_maroof.py`,
`library_check.py::answer`, `words_check.py::ctc_logprob`, `error_rules.py`).

Сейчас бот устроен под одну модель: порт `PronunciationRecognizer.recognize(audio, text) -> Recognition`,
сценарий `AssessRecitation` считает `assess_variants` → балл 0–100 → `GradingPolicy.verdict`
(80/90) → разбор, объяснения, транскрипция. Освоение карточки — `max(score) >= pass_threshold`
(`AttemptRepository.best_scores`). Вердикт в БД ограничен CHECK `verdict_values` (три значения).

Что мешает встроить «в лоб»:
- решение принимается не по строке фонем, а по разнице вероятностей (логарифм) нескольких
  вариантов; балла 0–100 у него нет;
- исхода «ещё раз» нет ни в `Verdict`, ни в БД; правило «не больше раза подряд» требует знать
  прошлый исход этой карточки;
- правила зависят от урока (долгая = короткая на 3–30, мягкие шадда/мадд, последний слог), а порт
  получает только `text`.

## Решения автора (2026-11-19)
- **Вариант Б.** Модель только слушает и даёт баллы вариантов; решение — правило в домене с порогами в
  `policy.py`. Дообучение потом меняет только модель (ревизию), правило и пороги те же — честное «до/после».
- **Только MostafaMaroof — на всю книгу и суры; Muaalem выключена** (код и тесты не удаляются, включение —
  настройка; для будущего режима таджвида). Уточняет ADR-0087 п. 7: порядок «сначала 1–41» отменён.
- **Уроки 42+:** проверяются огласовки, буквы, сукун; где модель слаба (танвин, слияние, долгая «у»
  местоимения, сокращение долгой перед сукуном, ٱللَّهِ — PHASE_3 §11.8i) — верными засчитываются оба
  чтения: по книге (Хафс) и как ждёт модель. Ругать зря там не должна; таджвид для новичков не проверяется.
- **«Прочитай ещё раз» — отдельный вердикт `again` (миграция БД одобрена):** после дообучения видно,
  стал ли бот реже просить повторить.
- **Доступ ко всем урокам без ограничений** (так и сейчас: «освоено» влияет только на «урок пройден ✓»,
  статистику и повторение). Порог для новичков — обсудить позже.
- **Дообучение — позже, на записях учеников с разметкой профессора;** новую модель включаем, только если
  на контрольных записях (`baseline_840.csv`, 200 аятов, 28 записей учителя) она лучше старой. Данные
  Muaalem (профессиональные чтецы) — только как опыт: риск, что модель станет строгой, как Muaalem.

## Устройство
1. **Порт оценки вариантов.** В `application/ports/recognition.py` — `CardListener.listen(audio, text,
   *, long_is_short) -> Listening`: эталоны wasl/waqf в записи бота (Muaalem), длительность,
   `model_version`, сырой выход (`raw`: жадная расшифровка MostafaMaroof) и функция
   `score(variant) -> float` — log P(вариант | запись) для любого варианта в записи бота.
2. **Адаптер** `infrastructure/asr/maroof.py`: ffmpeg → wav2vec2 (MostafaMaroof) → `prepare`
   (твёрдые гласные к простым, долгая к короткой при `long_is_short`) → `to_maroof` → `ctc_logprob`.
   Фонетизатор бота (`_references`) выносится из `muaalem.py` в общий `infrastructure/asr/phonetizer.py`.
   Ревизия модели **закреплена** (`from_pretrained(..., revision=<sha>)`), не только сверяется, как у
   Muaalem; `model_version` = `wav2vec2-arabic-phoneme-asr@<sha7>;to_maroof=<v>`.
3. **Решение — в домене**, `domain/card_check.py` (только stdlib): строит варианты ошибок в записи бота
   (другая огласовка, нет гласной, похожая буква, мягкие — короткий мадд и нет шадды; «другой слог»),
   получает их баллы через переданную функцию и возвращает `CardDecision` (исход, победивший вариант,
   маржи, соперник, подсказки). Таблица похожих букв — в домене, утверждает человек.
4. **Пороги и диапазоны уроков** — `CardPolicy` в `domain/policy.py` (зона человека): 0 / −4, −6 / −3,
   уроки с «долгая = короткая», уроки с мягкими шаддой/маддом, уроки на новой проверке (1–41).
5. **Сценарий** `AssessRecitation`: для всех карточек вызывает `CardListener` (MostafaMaroof); прежний
   `PronunciationRecognizer` (Muaalem) остаётся в коде, выключен настройкой. Суры (FR-57) — тот же
   слушатель по кускам записи, отдельный шаг этой задачи. Для разбора и объяснений строит
   `Assessment(reference=верное, heard=победивший вариант)` — `build_breakdown`, `feedback.*.yaml`,
   транскрипция работают без изменений. Мягкая подсказка — победило верное, подсказка отдельным полем.
6. **«Прочитай ещё раз»** — новый `Verdict.AGAIN`; правило «второй раз подряд → засчитано с мягкой
   подсказкой, учителю» — функция в `domain/policy.py`, прошлый исход сценарий берёт из репозитория.
   Пометка учителю — `model_output["for_teacher"]` (без новой колонки).
7. **Освоение — по вердикту**, а не по `max(score)` (иначе «ошибка» с баллом 85 засчитала бы карточку).
8. **Учитель видит все способы:** в `model_output` — маржи, баллы лучших вариантов, жадная расшифровка,
   версии; Muaalem «в тени» на уроках 1–41 по умолчанию выключена (настройка).
9. **Сбой** MostafaMaroof или перевода эталона → `RecognitionError` (событие `recognition_failed`, QAS-04);
   молча на Muaalem не переключаемся (у неё другие пороги, ученик получил бы другой ответ).

## Последствия
- В памяти одна модель (MostafaMaroof, ~1,2 ГБ fp32); Muaalem не грузится. Откат на Muaalem — настройка.
- Миграция БД: значение `again` в CHECK `verdict_values` и в `docs/data/data-dictionary.md`; старые
  попытки не меняются (у них `verdict != failed` ⇔ `score >= 80` при тогдашних порогах).
- Отчёты `research/metrics.py`, `pilot.py`, `annotation.py` сейчас делят на «failed / не failed» —
  `again` нужно учесть явно.
- Пересчёт попытки (QAS-09) — по записи и закреплённой ревизии; матрица вероятностей не хранится.

## Суры (часть 7, FR-57) — Предложено 2026-11-20, принимает автор (ADR-0021)
- **Статус:** Предложено (агент-архитектор); пункты, помеченные «[автор]», — решение человека.

### Контекст
Сура — одно голосовое на 0,5–3 мин (ADR-0076 п. 14, без ограничения длины). `decide` нужен отрезок
записи одного аята: на всей суре варианты одного аята сравнивались бы с чужим звуком. Сейчас решение
по суре — `assess_sura` по строке Muaalem (выравнивание строк, пороги `GradingPolicy`); у MostafaMaroof
строка расходится с Хафсом (PHASE_3 §11.8i), поэтому строковая проверка на ней дала бы ложные ошибки.
Скорость: `ctc_logprob` — цикл по кадрам на каждый вариант; на аяте из 30 букв ~2,3 тыс. вариантов
(«другой слог» ~75 на букву). NFR-PERF-01 (≤ 10 с) написан для карточки; для суры не утверждён (TD-FN-114).
ADR-0076 отклонил выравнивание через ctc-forced-aligner из-за новой зависимости; теперь выравнивание —
свой Viterbi на numpy по уже посчитанным логитам MostafaMaroof, зависимость не нужна.

### Решение (предлагается вариант 1)
1. **Логиты по кускам.** `quiet_cuts` (6–10 с в тихом месте) → wav2vec2 на каждом куске → логиты
   склеиваются подряд (резали по тишине — шов на «пустом»). Перекрытие кусков (по 0,5 с с краёв,
   отбросить половину) — только если замер покажет, что у шва баллы хуже.
2. **Границы аятов — Viterbi** (`infrastructure/asr/align.py`, numpy) по склейке верных чтений в
   звуках модели: [истиаза?] [басмала?] аят 1 … аят N; необязательные начала и **пропуск аята** — ветви
   графа, конец чтения разрешён после любого аята (`not_reached`). Отрезок аята — его кадры плюс
   по 0,2 с с краёв; из того же пути — паузы (TD-FN-116).
3. **Решение по аяту — `decide` без изменений правил** на отрезке, правила и пороги урока суры
   (`CardPolicy`); соперник «другой слог» сохраняется (цифры §11.8j остаются в силе).
4. **Скорость, числа те же:** батч-CTC — варианты одной длины считаются одной матрицей
   (варианты × состояния) за один проход по кадрам; `decide` получает необязательный
   `score_many(variants)` и заполняет кэш разом; весь подсчёт суры — `asyncio.to_thread`.
5. **Порт** `SuraListener.listen_sura(audio, ayahs, opening, preamble, *, long_is_short) -> SuraListening`
   (`ayahs: tuple[AyahListening]` = `Listening` + `item_id`, `number`, `span_ms | None`; `prefix`
   — какие начала прозвучали; `pauses`, `chunks`, `model_version`, `audio_duration_ms`, `raw`).
   Реализует тот же `MaroofListener` (одна модель в памяти, как ADR-0076 п. 10).
6. **Ответ ученику** — экран суры как сейчас: «чисто N из M», аяты с ошибкой и «ещё раз», у каждого —
   «повторить аят» на обычную карточку. Зачёт «всё или ничего»: `again` у аята — сура не засчитана.
7. **Учителю** — маржи, победивший вариант и жадная расшифровка по каждому аяту.

### Суры — решения автора (2026-11-20)
- **Способ:** вариант 1 — по аяту тем же `decide` с соперником «другой слог», подсчёт пачкой (батч-CTC) в отдельном потоке; цифры §11.8j в силе. Соперник «что модель слышит без подсказки» (вариант 2) считается рядом и сохраняется для учителя и сравнения после дообучения; переход на него — только если на собранных данных он не хуже (выбор агента по просьбе автора «лучше на перспективу»).
- **БД:** у аята суры новый JSON-столбец `model_output` (маржи, соперник) и исход `again` (миграция).
- **«Наизусть», пропущенное слово:** новый вид ошибки — только после замера на записях с вырезанным словом (ловит и не ругает верное чтение).
- **Время:** ответ на суру не дольше 30 с на 2 мин записи; бот пишет «проверяю, займёт ~N с».
- **До кода измерить:** аяты подряд (не по файлам), границы аятов против EveryAyah, время на суре 2 мин, шов кусков, пропущенное слово.
