# ADR-0071: Уровни изменения S/M/L — число субагентов по сложности задачи

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Кто решил:** автор («слишком много тратим токенов на проверки даже для небольших изменений»;
  уровни «смотри по задачам сложности сам»; модели агентов не менять); границы уровней — агент
- **Связано:** ADR-0012, ADR-0039, ADR-0047; `.claude/commands/feature.md`, `.claude/commands/ship.md`

## Контекст
`/feature` для любой задачи запускал 8–11 субагентов, и каждый начинал с нуля: читал CLAUDE.md,
ADR и diff. `/ship` запускал `consistency-auditor` на каждый коммит. Из-за этого даже смена цвета
стоила как новая функция. Хуки (`stop_gate`, `doc_sync`, `git_guard`) почти не тратят токены:
они работают на компьютере и пишут агенту только при ошибке.

## Решение
Агент выбирает уровень задачи и называет его одной строкой. Если сомневается, берёт уровень выше.
Человек может поднять уровень.
- **S** — нет нового поведения (цвет, опечатка, конфиг, документация): `make check`, без субагентов.
- **M** — одно поведение в одном слое, без БД, данных учеников и аудио, зависимостей, экранов и
  текстов ученику, `domain/assessment`. Фазы TDD и принятие тестов человеком остаются. Тесты и код
  пишет основной агент, ревью делает один `code-reviewer` (и `bot-driver`, если менялась кнопка).
- **L** — всё остальное: полный `/feature`, как раньше.

`/ship`: `consistency-auditor` запускается только для L или если в diff есть требования, ADR,
схема данных, CLAUDE.md. `make trace` — только если менялись тесты или требования.
Хуки и зона человека одинаковы на всех уровнях.

## Отклонено
- **Два уровня (мелкое / полный цикл).** Средние задачи всё равно шли бы через 8+ агентов.
- **Перевести проверяющих агентов на Sonnet.** Отклонил автор: модели не менять.
- **Ослабить хуки.** Они почти не тратят токены, а принуждение — суть harness (ADR-0012).

## Последствия
- Мелкие правки обходятся в разы дешевле. Риск: агент занизит уровень. Его снижают правило
  «сомневаешься — бери выше», строка с уровнем, которую видит человек, и хуки, которые
  работают на любом уровне.
- Для Q6.1 (`docs/research/metrics-gqm.md`): поменялось число ревью до и после 2026-10-24.
