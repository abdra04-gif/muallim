# ADR-0055: Защита в самой БД — допустимые значения, одна жалоба на попытку, без лишнего поля

- **Статус:** Принято
- **Дата:** 2026-10-20
- **Кто решил:** автор («защита в самой базе», вариант из предложенных); реализацию предложил агент
- **Связано:** FR-23, NFR-TR-03, ADR-0004, ADR-0020, ADR-0040, ADR-0054, TD-DB-02, TD-DB-04

## Контекст
Допустимые значения вердикта, метки разметки, её источника и причины жалобы проверял только код:
ошибка в коде или ручная правка в обход бота записала бы в БД мусор, который потом молча исказит
метрики. Повторное нажатие «Бот ошибся» создавало вторую жалобу и завышало `disputed`.
`annotations.detected_error_id` с руководства 2.0 не заполнялся (ADR-0040).

## Решение
Миграция 0007:
- CHECK: `attempts.verdict` ∈ {excellent, passed, failed}; `annotations.label` ∈ метки руководства 2.x
  и 1.0 (старые могли остаться в БД); `annotations.source` ∈ {excel, telegram} или NULL;
  `learner_reports.reason` ∈ {read_correctly, wrong_error, other}. Значения в `tables.py` собираются из
  перечислений кода, в миграции заморожены; тест сверяет — новое значение только вместе с миграцией.
- UNIQUE: `detected_errors(attempt_id, ordinal)`; `learner_reports(attempt_id, learner_id)` — повторная
  жалоба не записывается и не считается (бот отвечает как обычно). Двойные жалобы, уже лежащие в БД,
  миграция сливает в первую.
- `annotations.detected_error_id` удалено; `v_errors.label` — последняя метка попытки.
- Найдено попутно: на SQLite batch-миграция пересоздаёт таблицу, и при включённых внешних ключах
  `DROP` старой таблицы каскадом стирал связанные строки (жалобы, ошибки, разметку). `migrations/env.py`
  выключает внешние ключи SQLite на время миграции и после неё проверяет `PRAGMA foreign_key_check`.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| CHECK со списком значений | просто, работает и в SQLite | новое значение — с миграцией | **принято** (это и есть защита) |
| Справочные таблицы + внешние ключи | значения можно менять без миграции | лишние таблицы и соединения для 3–8 значений | отклонено |
| Тип ENUM PostgreSQL | компактно | нет в SQLite (тесты), менять ещё сложнее | отклонено |
| Повторная жалоба — заменить первую | видна последняя причина | теряется исходная реакция ученика | отклонено: остаётся первая |
| Оставить `detected_error_id` | без миграции | лишнее поле путает читающего схему и метрики | отклонено |

## Последствия
- Новое значение вердикта, метки, источника или причины — только вместе с миграцией (тест напомнит).
- Откат 0007 возвращает поле и прежние представления, но слитые двойные жалобы не возвращает.

## Как проверить
`tests/integration/test_constraints.py` (на SQLite и PostgreSQL), `tests/architecture/test_migrations.py`
(значения CHECK = перечисления кода; слияние двойных жалоб), `tests/unit/test_use_cases.py::
test_second_dispute_of_same_attempt_is_not_counted_twice`. 2026-10-20: миграция на PostgreSQL 16 с
данными — вверх, откат, вверх; весь набор на PostgreSQL — 767 пройдено.
