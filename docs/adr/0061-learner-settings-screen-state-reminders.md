# ADR-0061: Настройки ученика и состояние экрана — в таблице `learner_settings`, напоминания — фоновой задачей в процессе бота

- **Статус:** Принято (вариант A, автор 2026-10-21; тексты экранов утверждает автор)
- **Дата:** 2026-10-21
- **Кто решил:** автор — «настройки в новой таблице БД», «блок исследования — настройкой, по умолчанию выкл.»
  (2026-10-20); 2026-10-21: вариант A; напоминания — сейчас, раз в день в выбранный час, не если сегодня уже
  занимался, пауза после 14 дней молчания, по умолчанию выключено; часовой пояс — спросить «который у тебя час?»
  при включении (хранится смещение, до ответа — UTC+3); автозвук по умолчанию выключен; «Как читается» —
  «Закрыта / Видна сразу / Не показывать». Агент сам: одна таблица, окно догоняния 3 ч, журнал `setting_changed`
- **Связано:** FR-51, TD-FN-90, TD-FN-70, TD-FN-18, TD-FN-79, TD-FN-91, NFR-REL-01, NFR-SEC-04, NFR-SEC-07,
  QAS-04, QAS-05, QAS-07, QAS-08, QAS-09, ADR-0005, ADR-0008, ADR-0024, ADR-0029, ADR-0049, ADR-0050,
  ADR-0054, ADR-0055, ADR-0057, ADR-0058, ADR-0059, R-08, SRC-070, SRC-091

## Контекст
1. **FR-51 (пакет Б):** ⚙️ Настройки — напоминание о занятии (время), «🔤 Как читается» (спрятано / сразу /
   скрыто; сейчас всегда спойлер, ADR-0029), автозвук эталона, истиаза в начале дня (сейчас всегда, ADR-0050),
   крупный шрифт (ADR-0059, TD-FN-91), блок исследования (сейчас только staff, ADR-0057). Внутри — «Как
   заниматься», «Мои данные», ID; главная — Продолжить / Уроки, Закрепление / Знаки, Прогресс / ⚙️ Настройки.
2. **TD-FN-90:** «что на экране» (`on_screen.py`) и «идёт начало занятия» (`opening.py`) живут в FSM
   MemoryStorage (ADR-0049). После перезапуска кнопки начала занятия снова двигают «Продолжить», голосовое с
   истиазы оценивается по карточке курсора; день начала занятия — по UTC (в 03:00 МСК / 05:00 Алматы оно
   «устаревает»). Это нарушает NFR-REL-01, хотя он помечен ✅: QAS-05 проверяет только курсор.
3. **Что изменилось с отклонённых и отложенных решений:**
   - ADR-0049 отложил «таблицу в БД для состояния» (TD-FN-70): «изменение схемы — зона человека, для пилота
     лишнее». С тех пор ревью пакета А нашло реальные ошибки из-за потери состояния (TD-FN-90), а автор
     2026-10-20 сам выбрал новую таблицу. ADR-0005 (Redis отклонён, «состояние — в PostgreSQL») не меняется.
   - Напоминания автор отложил 2026-10-18 до отзывов пилота (TD-FN-18), а 2026-10-20 включил их в FR-51.
     Делать ли рассылку уже сейчас или только настройку — вопрос автору (В1).
4. **Ограничения:** слои ADR-0002 (application без aiogram и SQLAlchemy); один процесс, long polling, без
   открытых портов (ADR-0008); без Redis (ADR-0005); тесты без модели и сети (ADR-0006); закрытый пилот,
   5–10 учеников (ADR-0015); бот не меняет схему — миграцию применяет человек (ADR-0054); допустимые значения —
   CHECK (ADR-0055); новая зависимость — проверка `dep_check` и решение человека (ADR-0046).
5. **Telegram:** не сообщает часовой пояс пользователя; не проигрывает звук сам (автозвук = бот присылает
   голосовое, ученик нажимает ▶); разным пользователям — около 30 сообщений в секунду, при 429 ждать
   `retry_after`; ученик, заблокировавший бота, даёт `TelegramForbiddenError`. Поле `learners.blocked_bot`
   есть, но сейчас нигде не выставляется.
6. **Ученики — Россия и Казахстан.** Переход на летнее время отменён в России с 2014 г., Казахстан с 01.03.2024
   живёт в едином UTC+5 (нужен SRC до принятия). Значит, хватает постоянного смещения от UTC.
7. **Влияние на данные исследования (RQ-1, ADR-0052):** «Как читается — сразу» (транскрипция кириллицей) и
   автозвук эталона перед строкой превращают чтение в повторение за образцом: ошибок чтения (не тот знак) станет
   меньше не потому, что ученик научился. Блок исследования показывает «Услышано» — ещё одна разница в обратной
   связи. Чтобы попытку можно было интерпретировать (QAS-09), должно быть видно, при каких настройках она сделана.

## Решение (предлагается)
1. **Таблица `learner_settings`** (миграция 0008, 1:1 с `learners`, `learner_id` — PK и FK с `ON DELETE
   CASCADE`). Две группы колонок с типами, без JSON:
   - *настройки ученика:* `how_to_read` (`spoiler` | `shown` | `hidden`, CHECK), `auto_reference`,
     `daily_opening`, `large_font`, `research_block` (boolean), `reminder_minute` (минута местных суток,
     NULL — выкл., CHECK 0…1439), `utc_offset_min` (NOT NULL, по умолчанию 180 — это умолчание, а не ответ ученика; CHECK −720…840; агент 2026-10-21);
   - *состояние экрана и начала занятия (TD-FN-90):* `screen_item_id` (NULL — меню), `screen_opening`,
     `opening_resume_item`, `opening_day`, `opening_skipped_on`, `reminder_sent_on` (местные даты);
   - `updated_at`.
   Telegram ID в таблице нет: роль просмотра видит её целиком, `make db-roles` повторять не нужно.
   Умолчания — как бот работает сейчас, кроме того, что решит автор (вопросы В2–В5).
2. **Слои.** `domain/settings.py` — `LearnerSettings`, `HowToRead`, чистые правила: местная дата по смещению,
   «пора ли напомнить», «нужно ли начало занятия» (переносится из `presentation/telegram/opening.py`).
   Порт `LearnerSettingsRepository` (application) и `SqlLearnerSettingsRepository` (infrastructure). Сценарии
   `ChangeSetting`, `ScreenState` (заменяет FSM-ключи `on_screen` и `opening_*`), `DueReminders`. Каждая смена
   настройки пишет событие `setting_changed` (`{"name", "value"}`), автозвук — `reference_played` с
   `"auto": 1`: настройки на момент попытки восстанавливаются по журналу (QAS-09).
3. **Часовой пояс — смещение по ответу «который у тебя час?».** Спрашивается при включении напоминания:
   кнопки с текущим временем для UTC+2…UTC+12, ученик нажимает ту, где его время. Хранится только смещение
   в минутах — не город и не геопозиция (`privacy.md`: «геолокация не собирается» остаётся верным). До ответа —
   смещение по умолчанию (В3) для «сегодня» начала занятия и серии дней.
4. **Напоминания — фоновая задача в процессе бота** (`asyncio`, запускает `bootstrap/main.py`, в режиме
   `--test` не запускается). Раз в минуту: одна транзакция выбирает учеников с напоминанием, не
   заблокировавших бота, у которых местное время ≥ выбранного, не позже окна догоняния (В4), сегодня ещё не
   напоминали и не занимались; ставит `reminder_sent_on` и коммитит **до** отправки (не больше одного
   напоминания в день даже при сбое). Отправка — `presentation/telegram/reminders.py`: не чаще 20 сообщений в
   секунду; 429 — ждать `retry_after`; `TelegramForbiddenError` → `blocked_bot = true` (снимается, когда ученик
   снова пишет боту). Любая ошибка тика — в лог (без Telegram ID: только число отправленных и
   псевдонимы при сбое) и следующий тик; задача не роняет polling.
5. **Экран настроек — одно окно (ADR-0024)**, переключатели меняют экран на месте. Автозвук — отдельное
   голосовое перед карточкой (в одно сообщение картинку, звук и кнопки Telegram не собирает); предыдущее
   автоголосовое удаляется при переходе дальше (по номеру в `Display`; после перезапуска — остаётся, это
   допустимо).
6. **Крупный шрифт** — множитель размера в `render.py`, ширина по-прежнему ≤ 900 px (ADR-0059); ключ кэша
   картинки (`Display.file_ids`) включает размер.
7. **Учитель и разметчик** (эталон, исправление фонем) остаются в FSM в памяти — TD-FN-70 не закрывается.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| **A. Одна таблица `learner_settings`: настройки + состояние экрана колонками; напоминания — задача asyncio в процессе; смещение «который час»** | одна миграция, один репозиторий, каскад удаления «бесплатно»; нет Telegram ID и новых зависимостей; правила начала занятия уходят из presentation в domain (замечание ревью пакета А); всё тестируется на SQLite с поддельными часами и ботом | в одной строке живут и выбор ученика, и часто меняемое состояние экрана; учитель и разметчик по-прежнему теряют шаг (TD-FN-70) | **предлагается** |
| B. `learner_settings` только для настроек + своё SQL-хранилище FSM aiogram (`fsm_states`, `BaseStorage` поверх SQLAlchemy, без новой библиотеки) | обработчики почти не меняются — обещание ADR-0049 «хранилище заменяемо»; заодно закрывается TD-FN-70 | в таблице Telegram ID (ключ FSM) — скрывать от роли просмотра, удалять при «Удалить мои данные» отдельно, без внешнего ключа; данные — нетипизированный JSON, отчётом не прочитать; правила начала занятия остаются в presentation; решает T3-долг раньше времени | отклонить (можно вернуться, если TD-FN-70 поднимут до T1) |
| C. Готовые библиотеки: сторонний SQL-storage для FSM + APScheduler + часовой пояс по городу (IANA, `zoneinfo` + `tzdata`) | стандартные механизмы; летнее время учтено, если его вернут | 2–3 новые зависимости (ADR-0046); APScheduler создаёт свою таблицу задач вне Alembic, а у бота нет прав на DDL (ADR-0054); задача на каждого ученика дублирует данные БД; город — уже данные о местоположении | отклонить |
| Напоминания внешним cron/launchd (`muallim-remind` раз в минуту) | бот проще, сбой рассылки не трогает polling | ещё одна точка развёртывания на ноутбуке и в Docker; тот же код и токен в двух процессах | отклонить |
| Часовой пояс по геопозиции | точно | геопозиция — персональные данные, `privacy.md` обещает её не собирать; нужна библиотека «координаты → пояс» | отклонить |
| Часовой пояс — ввод времени текстом | ничего лишнего | новичку проще кнопки; ошибки ввода | отклонить |
| Снимок настроек в каждой попытке (`attempts.view_settings`) | интерпретация попытки без журнала | меняет главную таблицу исследования; то же восстанавливается по `setting_changed` | решает автор (В6); по умолчанию — журнал |

## Последствия
- Миграция 0008, `tables.py`, `docs/data/data-dictionary.md`, `docs/security/privacy.md` (настройки, смещение,
  время напоминания — данные работы сервиса, не исследования; согласие на исследование не нужно, напоминание
  включает сам ученик), удаление ученика — каскадом (тест `test_delete_learner_cascades` дополняется).
- QAS-05 расширяется: после перезапуска сохраняются курсор, экран и начало занятия. NFR-REL-01 до этого — 🟡.
- Новые события `setting_changed`, `reminder_sent`; отчёт R-08 «вернулся ли после напоминания» становится
  возможным (SRC-091), но в эту итерацию не входит.
- ADR-0029 (спойлер), ADR-0050 (начало занятия всегда), ADR-0057 (блок только staff) становятся умолчаниями
  настроек — после принятия отметить «уточняется ADR-0061».
- TD-FN-90 п. 2–6 решаются без схемы — отдельными шагами.
- Остаётся: TD-FN-70 (учитель, разметчик); интервальное повторение (итерация 10, пакет В) может переиспользовать
  тик, но здесь не проектируется.

## Как проверить
- test_settings_rules.py (будет) (Hypothesis): местная дата и «пора напомнить» для смещений UTC+2…+12 на
  границах суток; не больше одного напоминания в местный день.
- test_screen_state.py (будет): новый контейнер и диспетчер на той же БД (имитация перезапуска) —
  экран, начало занятия и «пропустил сегодня» сохранились; голосовое на истиазе оценивается по истиазе.
- test_reminders.py (будет): поддельный бот и часы — отправка в окне, пропуск после занятия,
  `TelegramForbiddenError` → `blocked_bot`, 429 → повтор после паузы, сбой БД не останавливает задачу.
- test_settings_bot.py (будет): каждая настройка меняет экран (спойлер / сразу / скрыто, блок
  исследования, крупный шрифт ≤ 900 px, без начала занятия); `make try` — главная из четырёх рядов.
- `tests/architecture/test_logging.py`: в логах рассылки нет Telegram ID.

## Последствия реализации (круг 2, 2026-10-21)
- Ученики без строки `learner_settings` (все текущие — сразу после миграции 0008) считаются стоящими на меню:
  первое голосовое без нажатия кнопки не оценивается — бот просит открыть урок. Один раз на ученика.
- Переход экрана пишет только изменённые поля (`LearnerSettingsRepository.change`): два быстрых нажатия не
  затирают начало занятия; нарушение CHECK/FK при первой записи не теряется молча.
- `utc_offset_min` — данные работы сервиса: в датасет, отчёты и `interaction_events` значение не выгружается
  (событие `setting_changed` для смещения — без значения).
