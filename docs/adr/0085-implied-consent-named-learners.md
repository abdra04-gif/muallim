# ADR-0085: Согласие без отдельного шага, записи всегда, ученик под своим именем

- **Статус:** Предложено, **[утвердить]**; в коде бота ещё не сделано, сейчас есть только в демо (`docs/site/lessons.*`)
- **Дата:** 2026-11-15
- **Кто решил:** автор (замечание 2026-11-15); варианты и риски записал агент
- **Связано:** ADR-0010 (заменяет его части), ADR-0038, ADR-0081, ADR-0082, OQ-01, `docs/security/privacy.md`

## Контекст
Сейчас при /start бот показывает экран согласия: записи хранятся под псевдонимом `L-xxxxxxxx`,
можно заниматься и без сохранения записей (ADR-0010). Автор считает этот экран лишним и странным
для ученика. Он хочет видеть каждого ученика по имени и отслеживать его результаты.

## Решение (предложено автором)
1. **Нет экрана согласия.** Приветствие → язык (русский / English) → имя из Telegram (✅ «Да, так» или
   ✏️ «Другое имя») → пять вопросов в одно касание → главный экран, а не урок.
2. **Записи сохраняются всегда.** Переключателя «Сохранять мои записи» в настройках нет.
3. **Ученик под своим именем.** Учитель и автор видят имя и всю историю ученика.

## Что агент рекомендует оставить (минимум, без отдельного шага)
- **Одна строка в первом сообщении:** «Пользуясь ботом, вы соглашаетесь, что ответы и записи сохраняются
  для обучения и исследования · /privacy». Без кнопки, она ничего не останавливает. Без неё сбор голоса
  и ответа про намаз (религиозные сведения) не имеет никакого основания. ADR-0010 отклонял именно
  вариант «хранить всё без согласия» как неэтичный и незаконный для исследования.
- **Псевдоним только в выгрузках для исследования.** Отслеживать ученика можно и с псевдонимом:
  `L-…` постоянен для ученика. Имя видно учителю в боте, но в датасет, отчёты для статьи и
  внешние сервисы не уходит. Так диссертация не нарушит правила публикации данных.
- **Удаление по просьбе** через /privacy остаётся. Это требование закона, а не экран в боте.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Как сейчас: экран согласия, псевдонимы (ADR-0010) | этично, проверено | лишний шаг, ученик может отказаться от записи | заменяется |
| Совсем без согласия и без строки | проще всего | нет основания для обработки голоса и религиозных сведений; риск на защите и в этическом комитете | **не рекомендуется** |
| Строка-уведомление + имя в боте, псевдоним в выгрузках | нет шага; учитель видит имя; данные исследования защищены | строка всё же есть | **рекомендуется** |

## Что поменять в коде (уровень L, через `/feature`, с решением автора)
- `presentation/telegram/texts.py` и обработчики /start: убрать экран согласия, добавить вопрос языка и строку.
- `consents`: записывать «согласие по факту использования» с версией текста (схема БД: решает человек).
- Настройки: убрать переключатель записи; `/privacy`: оставить удаление.
- Учительские экраны: показывать имя (`learner_names`, ADR-0081). Выгрузки (`research/`) по-прежнему с `L-…`.
- `docs/security/privacy.md`, FR-09/FR-10, NFR-SEC-*: переписать после утверждения.
