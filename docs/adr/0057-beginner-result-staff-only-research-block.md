# ADR-0057: Разбор попытки для новичка; служебный блок — только учителю и разметчику

- **Статус:** Принято; частично заменяет ADR-0020 (номер под каждым результатом), ADR-0024 (текст строки в
  блоке «Для исследования» у ученика), ADR-0030 п. 5 («было → стало» при неизменном балле)
- **Дата:** 2026-10-20
- **Кто решил:** автор (UX-обход бота глазами новичка, «делай все»; пакет А); реализацию и `StaffAccess`
  предложил агент
- **Связано:** FR-50, FR-25, FR-21, FR-23, US-U-06, US-U-11, US-U-12, ADR-0020, ADR-0024, ADR-0030, ADR-0049

## Контекст
Обход бота глазами ученика «с нуля» (`docs/requirements/audience.md`) показал, что на экране результата
лишнее: свёрнутый блок «🔬 Для исследования» (номер попытки, эталон и «Услышано» фонемами), строка
«Услышано: …» смешанным алфавитом, «➡️ было → стало» при том же балле. Новичку это шум и повод думать, что
он что-то сделал не так. Учителю и разметчику эти данные нужны (сверка с разметкой, жалобы). Номер попытки
нужен ученику только для одного — сослаться на попытку, когда бот ошибся (ADR-0020).

## Решение
1. Блок «Для исследования», строка «Услышано» и номер попытки на результате показываются только
   **staff** — учителю (`TEACHER_IDS`) или разметчику (`ANNOTATOR_IDS` и приглашения): сценарий
   `StaffAccess.is_staff` (`src/muallim/application/use_cases/staff.py`), передаётся в
   `screens.result(..., staff=)`. Сбой проверки разметчика (БД недоступна) = обычный ученик: результат он
   получит в любом случае.
2. Ученик видит номер попытки в «🚩 Бот ошибся» («Что не так с проверкой попытки № …?»); там же — «Отмена»
   (добавлено агентом, автор: «Оставить всё»).
3. «Было → стало» — только если балл изменился; «✨ Исправлено» — как в ADR-0030.
4. Что прозвучало у ученика он по-прежнему видит в разборе по слогам («Нужно / У тебя», M-10);
   смешанная строка «Услышано» целиком — служебная (уточнение FR-21).
5. Счётчик «✅ Прочитано верно — n из m **слогов**», на картинке — «слов верно n из m» (единица названа).
6. Тексты — `texts.py`, утверждены автором 2026-10-20.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Служебное — только staff, номер — в «Бот ошибся» | новичок видит только разбор; учитель и разметчик — всё; жалоба по-прежнему с номером | ещё один сценарий в DI; учитель видит экран не так, как ученик | **принято** (автор) |
| Оставить блок свёрнутым для всех (как было) | ничего не менять | новичок раскрывает и пугается фонем; «Услышано» смешанным алфавитом путает | отклонено |
| Убрать блок совсем | проще экран и код | учителю и разметчику не с чем сверять; номер попытки негде взять | отклонено |
| Переключатель «блок исследования» в настройках ученика | выбор у самого ученика | нужны настройки в БД — пакет Б (FR-51) | отложено: пункт FR-51 (пакет Б) |
| «➡️ было → стало» при неизменном балле (ADR-0030 п. 5) | видна сама повторная попытка | новичок читает «не изменилось» как упрёк | отклонено (заменено п. 3) |

## Последствия
- Номер попытки под каждым результатом (ADR-0020) и «текст — в „Для исследования“» (ADR-0024) больше не
  видны ученику; FR-25 уточнён: ID — в /me, номер попытки — в «🚩 Бот ошибся».
- Учитель, проверяющий бот своим аккаунтом, видит экран иначе, чем ученик — смотреть экран ученика через
  `make try` (ADR-0045) или аккаунт без ролей.
- Данные попытки в БД не меняются: изменён только показ.
