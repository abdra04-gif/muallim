# ADR-0034: Агенты качества кода и новые хуки

- **Статус:** Принято
- **Дата:** 2026-10-18
- **Кто решил:** Исмаилов (требование: агенты для кода, поиска ошибок, архитектуры и «то, о чём я не
  думал», плюс хуки). Состав агентов и хуков предложил агент.
- **Связано:** ADR-0011 (TDD с фазами), ADR-0012 (обвязка), ADR-0033 (агенты исследования),
  TD-SEC-13, TD-FN-11, Q6.1 в `docs/research/metrics-gqm.md`, SRC-027

## Контекст
Цикл `/feature` проверял код только на соответствие ADR и слоям (`architecture-guardian`):
логические ошибки, async, Unicode арабского текста и качество самих тестов не проверял никто.
Агент может написать тест, который проходит всегда (SRC-027). Не было агента, который
проектирует до кода, смотрит на бота глазами новичка, сверяет арабский текст со сканом и решает,
готов ли пилот. Хуки: зоны человека защищались правилами `permissions.ask` только для `Edit`
(`Write` и `MultiEdit` проходили, `tables.py`, `muaalem.py`, `methodology.md` не входили);
`guard.py` при сбое пропускал действие (TD-SEC-13); блокировки не записывались, и метрику Q6.1
посчитать было не из чего; `mypy` в стоп-хуке не запускался.

## Решение
**Агенты** (`.claude/agents/`): `solution-architect` (до кода), `code-reviewer` (ошибки),
`test-auditor` (качество тестов, мутанты через `uvx mutmut` без зависимости), `debugger`
(воспроизведение → корень → тест), `learner-simulator` (новичок), `book-proofreader`
(TD-FN-11), `pilot-readiness` (запуск пилота). Все, кроме архитектора, только читают.
Порядок в `/feature` — `docs/process/agent-harness.md`.

**Хуки:** `human_zones.py` (PreToolUse, `ask` с причиной), журнал `docs/journal/hooks/*.jsonl` в
`_common.block`/`log_event`, fail-closed в `guard.py`, `mypy` в `stop_gate.py`, `stub_notice.py`,
`session_context.py`, `notify.py`.

**Скиллы у автора** (глобально, вне репозитория): `systematic-debugging`,
`verification-before-completion`, `receiving-code-review` из obra/superpowers.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Готовые агенты (VoltAgent, wshobson: `code-reviewer`, `debugger`, `architect-reviewer`) | готово | общие, без правил проекта (`data/`, фазы, зоны человека), англоязычные отчёты | Отклонено (ADR-0033) |
| Trail of Bits skills (безопасность) | сильные аудиторы | в основном смарт-контракты и C; для бота есть `security-auditor` | Отклонено |
| Плагин superpowers целиком (TDD, планы, worktree) | цельная методика | дублирует `/feature` и фазы ADR-0011, git worktree без коммитов бесполезен | Отклонено; взяты 3 скилла дисциплины |
| Блокировать зоны человека (`exit 2`) вместо `ask` | жёстче | человек не может разрешить правку в моменте; агент ищет обходы | Отклонено |
| Мутационное тестирование в CI (`mutmut` в dev-зависимостях) | постоянная защита от пустых тестов | новая зависимость, минуты на прогон | Отложено: по запросу через `uvx`, решение — человек |
| Хук PreCompact (сохранять контекст перед сжатием) | история для главы 3 | промпты уже пишет `log_prompt.py`, сводки — `/session-summary` | Отклонено |

## Последствия
- `/feature` длиннее на 2–3 вызова агентов; ловит больше ошибок до человека.
- Q6.1 считается из `docs/journal/hooks/`; формат: `ts`, `hook`, `kind` (`block`/`ask`), `reason`.
- Стоп-хук дольше на время `mypy` (секунды).
- TD-SEC-13 закрыт для `guard.py`; остальные хуки при сбое по-прежнему пропускают (они не охранные).
- Тесты новых хуков подготовлены, но не добавлены: фаза `impl` замораживает `tests/`.

## Как проверить
`tests/architecture/test_hooks.py` (после фазы `tests`): `human_zones` отвечает `ask` на зоны и
`pip install`, молчит на `src/muallim/domain/assessment.py`; `guard.py` с битым `tool_input`
возвращает 2; `block` пишет строку в журнал; `stub_notice` реагирует только на заглушку.
