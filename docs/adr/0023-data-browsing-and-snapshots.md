# ADR-0023: PostgreSQL в работе с первого дня; снимок программы в БД; представления, фильтр ошибок, отчёты по книге, резервные копии

**Статус:** Принято
**Дата:** 2026-10-17
**Кто решил:** автор («переходим сейчас, и добавляй отчёт и фильтр и что ещё надо»), варианты — агент

## Контекст
Нужно хранить все ответы и ошибки, смотреть их, находить самые частые, размечать датасет и обучать
модель. Схема (ADR-0004) уже хранила попытки, ошибки и разметку, но:
- локально бот работал на SQLite;
- попытка знала только `item_id` + `curriculum_version`; связь со **страницей и строкой книги** жила
  в YAML и терялась при правках контента;
- смотреть данные можно было только SQL-запросами и общим отчётом.

## Решение
1. **PostgreSQL 16 в Docker и локально**, SQLite — только тесты. Отдельная тестовая БД
   `muallim_test` (свой пользователь) — тест PostgreSQL стирает свою БД и не трогает рабочую.
2. **Таблица `curriculum_items`** — снимок каждой версии программы (текст, урок, страница, строка,
   пометка, сверено ли). Пишется ботом при старте (`PublishCurriculum`). Если контент изменён без
   новой `version`, бот **не запускается** (`CurriculumVersionError`) — иначе попытки связались бы не с тем текстом.
3. **Представления `v_attempts`, `v_errors`** — готовые «таблицы для чтения» с псевдонимом,
   страницей/строкой и текстом строки, последней меткой разметки; без Telegram ID.
   SQL — в `infrastructure/db/views.py`, замороженная копия — в миграции 0003 (тест сверяет).
4. **Каталог ошибок с фильтрами** — `muallim-research errors` / `make errors`: буква, услышанное,
   тип, урок, карточка, страница, строка, ученик, период, пары «Обратите внимание», не размечено,
   оспорено, с записью. Вывод — таблица + CSV с путём к записи.
5. **Отчёты 08–10:** трудные строки книги, пары «Обратите внимание», ошибки по буквам.
6. **`make backup` / `make restore` / `make db-shell`.**
7. Просмотр «как в Excel» — DBeaver поверх представлений (`docs/data/browsing.md`), без своей веб-админки.

## Рассмотренные варианты
| Вопрос | Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|---|
| СУБД | **PostgreSQL** | SQL-отчёты, много учеников, `pg_dump`, стандарт | Docker | ✅ |
| | SQLite | ноль настройки | одна запись за раз, нет удалённого просмотра | только тесты |
| | MongoDB | гибкие документы | отчёты (JOIN/GROUP BY) сложнее | ❌ |
| | ClickHouse | миллиарды строк | избыточно, не для правок/разметки | отложено (докторантура) |
| Связь попытки с книгой | **снимок в БД** | SQL видит страницу/строку; история версий | +1 таблица | ✅ |
| | читать YAML в отчётах (Python) | без схемы | старые версии теряются; SQL-клиент не видит | ❌ |
| | писать page/line в каждую попытку | просто | дублирование, нет текста строки | ❌ |
| Просмотр | **представления + DBeaver + CLI** | бесплатно, фильтры, без кода | DBeaver ставить отдельно | ✅ |
| | своя веб-админка | красиво | код, авторизация, безопасность | ❌ (позже, если будут учителя) |
| | Label Studio для разметки | разметка аудио в браузере | отдельный сервис | отложено (TD-FN-13) |

## Последствия
- Миграция 0003; данные учеников не затронуты.
- Ошибки, попытки и пары книги видны в DBeaver одной таблицей.
- Резервные копии содержат голоса — хранение вне git и с шифрованием (TD-SEC-17).
