# ADR-0080: Разметка 3.0 — «Бот прав», шесть главных видов, строка для обучения из каждой отметки

> С 2026-11-07 — семь главных видов, столбец `heard`, исправления строки: раздел «Дополнено 2026-11-07».

- **Статус:** Предложено 2026-11-07; **[утвердить]** автором
- **Дата:** 2026-11-07
- **Кто решил:** автор (2026-11-07, по заметкам встречи с научным руководителем: «модель сама, учитель
  говорит верно или нет», «бот максимально простой, минимум кликов», «схема разметки гибкая»; по
  разбору статей `docs/research/quran-mdd-papers-analysis.md`). Формулировки и устройство — агент.
- **Связано:** ADR-0079 (разметка по слогам) — **частично меняет**; ADR-0040, ADR-0041, ADR-0043,
  ADR-0065; FR-62, FR-63; QAS-01; SRC-002, SRC-162; `preregistration.md` §5

## Контекст
1. Данные собираются, чтобы потом проверять и дообучать модель. Для обучения нужна строка «что
   прозвучало». По ADR-0079 она выводится только для «Буква» (с буквой) и «Пропуск»; остальные виды
   дают метку по клеткам, но не строку — большая часть разметки не пригодна для обучения.
2. Руководитель хочет, чтобы учитель только подтверждал ответ бота: «верно или нет». ADR-0079 п. 0
   отклонил «ошибки бота уже отмечены» (путаница и привязка к ответу бота). Автор 2026-11-07
   пересмотрел это решение осознанно.
3. Глава об угрозах: подсказка бота (⚠️ «!» и теперь «Бот прав») завышает согласие между двумя
   учителями (`preregistration.md` §5, TD-FN-132).
4. Очередь разметки сортирует по `created_at DESC`: два разметчика, заходящие в разное время,
   получают разные записи, а оценивать согласие можно только по общим.

## Решение
1. **«Бот прав»** (`confirm_bot`): метка `agree`, `corrected_phonemes` = `bot_heard`,
   `phonemes_source = 'confirmed'`, отметки — из ошибок бота (`marks_from_bot`), `bot_flagged = true`;
   следующая запись показывается сразу. «Чисто» — `corrected_phonemes` = эталон, `phonemes_source =
   'reference'` (остаётся всегда: если бот ошибок не нашёл, итог тот же, что у «Бот прав», разница — только в
   источнике; так прежние сценарии и привычка разметчиков не ломаются). «Исправить» — виден, когда бот нашёл
   ошибки и черновик пуст: черновик заполняется отметками бота, дальше «Готово» как раньше (`phonemes_source = 'marks'`).
2. **Шесть главных видов** (с 2026-11-07 — семь: см. «Дополнено», п. 3) с вопросом «что прозвучало» там, где это нужно для строки; шесть прочих
   видов — за «Ещё». Виды хранятся в `MarkKind`; добавлены `shadda` и `sukun`; `shadda_sukun`
   остаётся допустимым для прежних меток и на экране не показывается.
3. **Хранение «что прозвучало» в `annotation_marks.heard_letter`** (с 2026-11-07 — `heard`, миграция 0014: «Дополнено», п. 6) (имя столбца не меняем — слишком
   много мест): `letter` — согласная; `vowel`, `sukun` — гласная (َ ِ ُ), у `vowel` ещё `-` («никакой»);
   `extra` — вставленный звук; `missing` — пропущенный звук, `NULL` — весь слог; `shadda` — пусто.
4. **`apply_marks`** выводит строку для шести видов (с 2026-11-07 — и для «Длина»), если в слоге ровно одна отметка и она однозначна;
   иначе (в том числе любой из «Ещё» или две отметки в слоге) — `None`, как раньше.
   Допущения (стоит проверить у преподавателя): «лишний звук» вставляется после звуков слога;
   «шадда» переворачивает удвоение единственной согласной слога.
5. **БД (миграция 0012):** `annotations.phonemes_source` VARCHAR(16) NULL, CHECK `typed|marks|confirmed|reference`;
   в CHECK `annotation_marks.kind` добавлены `shadda`, `sukun`. Прежние строки — `NULL`.
6. **Очередь:** сначала записи, уже размеченные другим разметчиком (пары закрываются), потом прежний
   порядок. В отчёт `make report` — доля попыток, размеченных ≥ 2 разметчиками, и число меток по видам
   ошибки; в датасет и выгрузку — `phonemes_source`.
7. **Подсказка бота остаётся для всех записей** (решение автора 2026-11-07). Слепой режим для части
   записей (было предложено ~20 %) автор отклонил: смещение согласия — ограничение работы (TD-FN-132),
   его описывает глава об угрозах. `bot_flagged`, `seconds_spent` и `phonemes_source` позволяют оценить
   эффект задним числом.

## Дополнено 2026-11-07 (решения автора; TD-FN-150)
Две параллельные сессии сделали разметку по-разному; автор взял эту версию (FR-63) и велел
перенести из второй лучшее и исправить ошибки:
1. **Исправлено: огласовка в долгом слоге.** «Огласовка → кясра» в «لَّ» давала `لِاا` (кясра +
   долгая «а») — невозможная запись, модель училась бы на ней. Теперь долгая — того же звука (`لِۦۦ`);
   «никакой» у долгого слога строки не даёт.
2. **Исправлено: огласовка, которая и так написана**, не предлагается и отклоняется `check_marks` —
   отметка «ошибка» со строкой «ошибки нет» противоречила сама себе.
3. **«Длина» — на главном экране** (7 видов, за «Ещё» — 5): книга учит мадд, руководитель — «3
   огласовки, сукун, шадда» (протокол 2026-11-06). Строка выводится: долгий → краткий, краткий →
   долгий на 2 харакята.
4. `MarkGroup.READING` → `FLUENCY` («как читает» ≠ «ошибка чтения» RQ-1).
5. α по виду — по 12 видам экрана, без `shadda_sukun` (её «не отмечено» завышало согласие).
6. Миграция 0014: `annotation_marks.heard_letter` → `heard` (там и гласные, и звуки).

## Последствия
- Для обучения пригодны попытки с `corrected_phonemes` (все `confirmed`, `reference`, `typed`, часть `marks`).
  Согласие учеников на обучение и публикацию записано отдельной задачей — TD-FN-145 (TD-SEC-02/16; **блокирует обучение**).
- «Длина» (до 2026-11-07), «Твёрдость», «Гунна», «Калькаля», «Запинка», «Пауза не там» строку не дают; они остаются для
  оценки бота и будущего обучения признаков (у Muaalem они отдельные выходы — SRC-002).
- Согласие «учитель с учителем» теперь завышено подсказкой — описать в главе об угрозах; κ «модель–учитель»
  и «учитель–учитель» сравнивать с оговоркой.
- Руководство по разметке → 3.0 (`GUIDE_VERSION`), текст — на утверждение автору (TD-FN-137).
- Очередь «сначала записи, уже размеченные другим» рассчитана на **двух** разметчиков; при трёх и
  более пары не гарантируются.
- Метрики по клеткам и α пока **не отделяют** метки «Бот прав» (`confirmed`) от остальных: отметки из
  ошибок бота завышают recall и согласие. Считать отдельно или исключать из recall/α — TD-FN-146.
- `phonemes_source` описывает, как сделана строка учителя. Если отметки учителя совпали с ошибками
  бота (`agree`), хранится строка бота — она отличается от строки учителя разве что калькалей при
  остановке (не ошибка, M-03).
- Двойное нажатие «Бот прав» двумя быстрыми запросами может записать две метки; в данных берётся
  последняя, как с «Готово» (TD-FN-136).
