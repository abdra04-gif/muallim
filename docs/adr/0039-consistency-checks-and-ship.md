# ADR-0039: Сверка документов с кодом и безопасные коммиты — doc_sync, git_guard, /ship

- **Статус:** Принято
- **Дата:** 2026-10-18
- **Кто решил:** Исмаилов (требование: «проверять документацию и всё, что нужно, после изменения
  кода; проверять архитектуру; чтобы ничего не потерялось и не было расхождений; делать нормальные
  коммиты и push; чтобы туда не попало секретное»). Механизм предложил агент.
- **Связано:** ADR-0012, ADR-0034, ADR-0036, ADR-0037, NFR-TR-*, `docs/process/git.md`

## Контекст
Тесты `tests/architecture/test_docs.py` проверяют ссылки и пути, но не связки «изменили X —
обнови Y». При первой же проверке нашлись два реальных расхождения:
1. `.gitignore` с правилом `data/` молча прятал `docs/data/` (словарь данных, руководство по
   разметке, описание отчётов) — эти файлы не попали ни в один коммит и не были на GitHub.
2. Новые хуки не были описаны в `agent-harness.md`.
Коммиты делал человек вручную; правила сообщений не было; push шёл без проверок.

## Решение
- **Хук `doc_sync.py` (Stop)** — механические правила относительно последнего коммита: код →
  CHANGELOG; `tables.py` → миграция и словарь данных; миграция → словарь; новый SQL → `reports.md`;
  новый агент/хук/команда → `agent-harness.md`; `.mmd` → перерисованные `.png`/`.svg`;
  текст согласия/анкеты → поднята версия; новый FR → строка трассировки; файлы проекта,
  скрытые `.gitignore`. Блокирует завершение один раз со списком.
- **Хук `git_guard.py` (PreToolUse, Bash)** — `git add -f` запрещён; `add` и `commit` раздельно;
  коммит без запрещённых путей и с чистым gitleaks; push — только при зелёных архитектуре,
  типах и тестах.
- **Агент `consistency-auditor`** — смысловая сверка (описание поведения, цифры в документах,
  схемы ↔ код), только отчёт.
- **Команда `/ship`** — проверки → сверка → трассировка → коммит по правилам `docs/process/git.md`
  (`тип(область): что изменилось`, `Refs: FR/ADR/TD`) → push. Человек подтверждает коммит и push.
- `.gitignore`: `/data/` вместо `data/`.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Только агент, без хука | понимает смысл | его можно забыть вызвать | Отклонено: механическое — хуком, смысл — агентом |
| Только тесты в `tests/architecture` | работают и в CI | не знают, что изменилось с последнего коммита | Оставлены для постоянных правил; связки «изменили — обнови» — хук |
| Push без проверок, полагаться на CI | быстрее | сломанное уже в репозитории, когда CI покраснеет | Отклонено |
| Коммиты автоматически после каждого ответа | ничего не потеряется | шум, нет смысловых коммитов, человек не видит, что уходит | Отклонено: `/ship` по запросу |
| Блокировать любую правку `.gitignore` | защита | мешает исправить ошибку вроде `data/` | Отклонено: `.gitignore` — в зоне человека (`human_zones`), ошибки ловит `doc_sync` |

## Последствия
- Завершение ответа дольше на секунды (`git status`, `git diff`); push — на время тестов (~20 с).
- Ложное срабатывание `doc_sync` возможно (например, правка кода без видимого эффекта и без
  CHANGELOG) — агент добавляет строку в CHANGELOG или объясняет человеку; правило не обходится.
- Срабатывания пишутся в `docs/journal/hooks/` — данные для главы 3 (Q6.1).

## Как проверить
`tests/architecture/test_hooks.py`: `doc_sync` блокирует правку `tables.py` без словаря данных и
пропускает согласованное изменение; находит файл, скрытый `.gitignore`; `git_guard` блокирует
`git add -f`, коммит с `.env` или `data/`, `add && commit` в одной команде.
