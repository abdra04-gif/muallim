# ADR-0001: Записывать архитектурные решения, включая отклонённые

- **Статус:** Принято
- **Дата:** 2026-10-17
- **Кто решил:** Исмаилов (требование: «сохранять, что предлагали, но убрали, и причину»)
- **Связано:** NFR-TR-02

## Контекст
Проект — основа магистерской и, далее, докторской работы. Через годы нужно понять не только *что*
сделано, но и *почему*, и какие альтернативы отбросили. Git хранит изменения кода, но не причины.

## Решение
Каждое значимое решение — отдельный файл `docs/adr/NNNN-название.md` по шаблону `0000-template.md`
(формат Architecture Decision Record, Nygard, 2011 — SRC-010). Отклонённые идеи тоже получают ADR
со статусом **Отклонено** и причиной. ADR не переписываются: если решение меняется, пишется новый
ADR, а старый получает статус «Заменено ADR-XXXX». Индекс — `docs/adr/README.md`.

## Последствия
- Глава диплома «Проектирование» собирается из ADR почти напрямую.
- Агент `thesis-scribe` обязан предлагать ADR при каждом архитектурном изменении.

## Как проверить
`tests/architecture/test_docs.py` проверяет, что у каждого ADR есть статус и дата и что все ADR
перечислены в индексе.
