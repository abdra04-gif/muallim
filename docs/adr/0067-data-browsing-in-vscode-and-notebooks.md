# ADR-0067: Просмотр данных в VS Code и Jupyter-ноутбуки для автора исследования

- **Статус:** Принято
- **Дата:** 2026-10-22
- **Кто решил:** автор («настрой PostgreSQL в VS Code»; «давай сейчас установи [Jupyter] и чтоб пользоваться
  мог в VS Code»); варианты и реализацию предложил агент
- **Связано:** ADR-0023 (просмотр данных), ADR-0036 (воспроизводимость цифр), ADR-0054 (вход только для
  чтения `muallim_reader`), `docs/data/browsing.md`, `docs/data/sql-guide.md`, `notebooks/README.md`, TD-FN-99

## Контекст
Автор смотрел данные через `make report`, `make errors` и DBeaver. Хотел делать запросы прямо в VS Code,
где уже стояли расширения PostgreSQL (Microsoft) и Jupyter, и строить графики для главы 4.

## Решение
1. **Расширение PostgreSQL (`ms-ossdata.vscode-pgsql`)**: подключение «muallim (просмотр)» прописано в
   `.vscode/settings.json` (папка вне git) — вход `muallim_reader`, пароль не в файле, а в связке ключей
   macOS. Поля `id` и `groupId` обязательны: без них расширение 1.32 молча не показывает подключение.
   Личные запросы — `.vscode/queries.sql`; учебник — `docs/data/sql-guide.md`.
2. **Jupyter-ноутбуки**: группа зависимостей `notebook` (`ipykernel`, `pandas`, `matplotlib`) в
   `[dependency-groups]`, включена в `default-groups` — иначе `uv sync` её удалит. Бот и `src/` её не
   импортируют (deptry проверяет `src`). Подключение — `notebooks/db.py` через уже имеющийся `asyncpg`,
   тем же входом только для чтения; пароль читается из `.env` при запуске.
3. **`*.ipynb` вне git**: в результатах ячеек — данные учеников (псевдонимы, тексты попыток). Цифра для
   диссертации переносится в `analytics/sql/` (ADR-0036), ноутбук — черновик.
4. Все запросы отбрасывают `model_version = 'stub'`, как отчёты `analytics/sql/`.

## Рассмотренные варианты
| Вопрос | Выбрано | Отклонено и почему |
|---|---|---|
| Где смотреть данные | расширение Microsoft (уже стояло) + DBeaver как был | SQLTools, Database Client и др. — те же возможности, лишняя установка |
| SQL в ноутбуке | своя функция `sql()` на `asyncpg` | JupySQL (`%%sql`) — ещё зависимость и драйвер `psycopg`; выгода — только короче запись |
| Где хранить зависимости ноутбука | отдельная группа `notebook` | в `dev` — смешало бы инструменты проверки и анализа; extra `[project.optional-dependencies]` — попали бы в описание пакета бота |
| Ноутбуки в git | нет (`*.ipynb` в `.gitignore`) | в git с очисткой вывода (`nbstripout`) — ещё зависимость; ошибка настройки = данные учеников в истории git |

## Последствия
- CI ставит группу `notebook` вместе с `dev` (`uv sync --frozen`): несколько секунд дольше.
- Проверка базы при настройке (2026-10-22) нашла, что выход модели хранится текстом `repr()` — TD-FN-99.
