# ADR-0036: Трассировка исследования, предрегистрация и отпечаток версии без git

- **Статус:** Принято
- **Дата:** 2026-10-18
- **Кто решил:** Исмаилов (требование: «чтоб было трейсабилити и что ещё понадобится»). Состав
  предложил агент; гипотезы и план анализа — черновик, утверждают автор и руководитель.
- **Связано:** ADR-0019 (след решения у попытки), ADR-0026 (GQM), QAS-09, TD-FN-24, TD-FN-27,
  TD-FN-42…44, NFR-TR-*

## Контекст
Трассировка требований есть и проверяется тестами (`docs/requirements/traceability.md`,
`tests/architecture/test_docs.py`). Не хватало четырёх звеньев:
1. **Исследование**: RQ → гипотеза → метрика → расчёт → рисунок в главе нигде не сведены вместе.
2. **Рисунки и таблицы**: неизвестно, из какого отчёта, когда и на каком n построена цифра.
3. **Версия**: коммитов нет (TD-FN-27) — нельзя доказать, каким кодом получен отчёт.
4. **Гипотезы до данных**: без фиксации оппонент вправе спросить, не подогнаны ли метрики.
Плюс матрица говорит, какой файл тестов проверяет требование, но не проходит ли он сейчас.

## Решение
- `docs/research/traceability.md` — матрица RQ → H → Q (GQM) → расчёт → статус → ID результата.
- `docs/thesis/figures.md` — реестр Р-NN / Т-NN с источником и паспортом.
- `docs/research/preregistration.md` — черновик гипотез H1.1…H3.2, исключений, плана анализа;
  заморозка — SHA-256 файла в `research-log.md` (+ OSF по решению человека).
- `scripts/trace.py`, `make trace` → `docs/requirements/verification-status.md`: требования ↔
  результат тестов сейчас; сводка исследования; **отпечаток версии** — SHA-256 кода, программы,
  SQL, миграций, `uv.lock`, предрегистрации.
- Агенты `thesis-writer` и `asr-evaluator` обязаны ссылаться на ID и паспорт.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Git-коммит как версия | стандарт | автор решил пока без git (TD-FN-27) | Отложено; отпечаток совместим — потом рядом встанет хеш коммита |
| DVC / audb для версий данных | версии датасета | инфраструктура до появления данных (OQ-06) | Отложено |
| Маркеры `@pytest.mark.req` сразу | трассировка до функции | правка `tests/` в фазе `impl` запрещена | Отложено (TD-FN-42) |
| Паспорт в шапке `make report` сразу | цифры отчёта воспроизводимы | код в `src/` — только через `/feature` | Отложено (TD-FN-43, T2) |
| Генерировать матрицу требований из кода | не устаревает | теряются ручные пометки 🟡 и причины | Отклонено: матрица ручная, статус — генерируется |

## Последствия
- Перед сдачей главы: `make trace` → отпечаток в паспорт каждого 🔄-рисунка.
- `verification-status.md` — генерируемый файл, руками не правится; устаревает до следующего
  `make trace`.
- Предрегистрация требует решения руководителя до пилота — добавлено в повестку встреч.

## Как проверить
Проверки в `tests/architecture/test_docs.py` (после фазы `tests`): каждый Q из `metrics-gqm.md`
есть в `docs/research/traceability.md`; каждый ID результата есть в `figures.md`; файлы рисунков
со статусом ✅ существуют; `scripts/trace.py --no-tests` отрабатывает.
