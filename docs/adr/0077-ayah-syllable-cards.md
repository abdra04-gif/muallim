# ADR-0077: Карточка аята по слогам — разбор заранее в `curriculum/syllables/ayat.yaml`, бот только рисует

- **Статус:** Принято
- **Дата:** 2026-10-30
- **Кто решил:** автор 2026-10-30 — что показывать, «разбор заранее, не на лету», вариант A,
  непроверенный разбор показывать (как ролики), спойлер «Как читается» оставить; автор 2026-10-31
  (после ревью direction-reviewer, вердикт СТОП): показывать `unchecked` сейчас, зная, что ع и
  хамза в подписях не видны (TD-FN-119); подпись с дефисом в клетке «لا» («ли-ии», «л-ак») —
  оставить; пояснение внизу карточки — нет (автор посмотрел пример с двумя строками и отказался);
  запись вида карточки в попытке — не сейчас, до пилота (TD-FN-120)
- **Связано:** FR-61 (новое), FR-48, FR-51, FR-54, FR-43; ADR-0002, ADR-0006, ADR-0024,
  ADR-0059, ADR-0061, ADR-0068, ADR-0074; QAS-07, QAS-09, QAS-10

## Контекст
1. Уроки с `section: sura` (29 уроков L097–L125, 192 пункта с `quran`, включая басмалы) сейчас
   показываются `render.card` — строка аята целиком. Ученик читает с нуля (`audience.md`): длинный
   аят без опоры не прочитать. Автор решил: аят рисуется из **клеток-слогов прямо в слове** (буквы
   соединены, ZWJ по краям кусочка), цвет клеток чередуется (зелёный/бежевый), под клеткой — как
   звучит простой кириллицей (`application.transcription.plain`, FR-54); слово переносится только
   целиком; номер аята в кружке после последнего слова; у басмалы номера нет, кроме аль-Фатихи
   (1:1 в L097).
2. Разбор на слоги требует `quran_transcript.quran_phonetizer` (фонемы + `mappings` по символам
   текста) — это extra `ml` (ADR-0006), в боте без модели (`make run-stub`, CI, `make try`) его нет.
   Прототип (`syl_auto.py`) разбирает все 192 аята без ошибок; правила склейки (немые буквы — к
   следующей, ٱ + немая ل — с первой звучащей, гунна/мадд лин/идгам танвина в و ي — сжатие повторов,
   хуруф мукатта'а — одна клетка) — эвристики, их результат человек должен увидеть глазами.
3. Автор решил: разбор делается **заранее скриптом в файл в репозитории**, бот читает файл.
   Образец — ролики ADR-0074: генератор `scripts/video/` + `make videos` → `curriculum/video/videos.yaml`
   (поиск по тексту карточки, `status: unchecked | ok | bad`), порт `ArticulationVideoLibrary`,
   адаптер `VideoLibrary.load`, регистрация в `bootstrap/di.py`.
4. Связь по **тексту** пункта, не по id: id меняются при пересборке `scripts/book/build.py`
   (ADR-0074 п. 6). Басмала стоит перед 28 сурами с тем же текстом и `quran: '1:1'` — разбор у неё
   один, а номер зависит от урока, поэтому номер — не в файле.
5. Отклонённых ADR с той же идеей нет. ADR-0074 отклонил поле `video:` в `course.ru.yaml`
   (теряется при пересборке, зона человека) — та же причина действует здесь (вариант B).

## Решение (вариант A, выбор автора)
1. **Файл** `curriculum/syllables/ayat.yaml` (генерируемый, как `videos.yaml`):
   ```yaml
   moshaf: {rewaya: hafs, madd_monfasel_len: 4, ...}   # MOSHAF_PARAMS, с которыми разобрано
   ayat:
   - text: بِسْمِ ٱللَّهِ ٱلرَّحْمَـٰنِ ٱلرَّحِيمِ     # точный текст пункта
     status: unchecked                               # unchecked | ok | bad — ставит человек
     words:
     - [[بِسْ, бис], [مِ, ми]]
     - ...
   ```
   Одна строка на уникальный текст (басмала — одна). `status: bad` — бот рисует прежнюю карточку
   (`render.card`); `unchecked` показывается (как у роликов). Генератор сохраняет `status`, если
   `words` не изменились, иначе ставит `unchecked`.
2. **Домен** (stdlib): `SyllableCell(text, sound)` — неизменяемый тип; аят = кортеж слов, слово =
   кортеж клеток. Правило номера: `ayah_number(lesson, item) -> int | None` — `None`, если сура
   пункта не совпадает с сурой остальных пунктов урока (басмала перед сурой), иначе номер из `quran`.
3. **Порт** `AyahSyllables` (`application/ports/reading.py`, рядом с `ReadingGuide`):
   `for_text(text) -> tuple[tuple[SyllableCell, ...], ...] | None`. **Адаптер**
   `SyllableLibrary.load(path)` — `infrastructure/curriculum/syllables.py` (yaml, без
   `quran_transcript`); нет файла — пустая библиотека; строка, чьи кусочки не складываются в `text`, —
   пропускается.
4. **Генератор** `scripts/syllables/build.py` + `make syllables` (`uv run --extra ml`); логика
   прототипа `syl_auto.py`; падает, если хоть один пункт не разобран или кусочки не складываются в
   текст. Описание — `scripts/syllables/README.md`.
5. **Рисунок** `render.ayah(words, number, position, scale)` — по прототипу `render_auto.py`
   (Scheherazade New 78, PT Sans 27, холст 900 — FR-48, точки «шаг k из n» снизу, как у `render.card`).
   «Крупный шрифт» (ADR-0061): оба шрифта × `LARGE_SCALE`, слова переносятся на больше строк; если
   одно слово шире строки — масштаб карточки уменьшается до ширины (не ломаем слово).
6. **Вызов** — `screens._card_image`: для `lesson.section == "sura"` и `item.quran`, если библиотека
   знает текст, — `render.ayah`, иначе `render.card`. `screens.card(..., syllables=...)` — как `videos=`;
   передают `navigation.py` и `daily.py` через Dishka.
7. Схема БД не меняется; новых зависимостей нет (`quran_transcript` уже в `ml`, Pillow — в основных).
8. **Дополнено после ревью 2026-10-31** (до слияния, тот же вариант A):
   - **Лигатура «لا»:** ل и алиф сразу после неё (с огласовками между ними) всегда в одной клетке —
     иначе Pillow/libraqm рисует ل и ا раздельно, а в мусхафе это одна лигатура. Склеенная клетка
     подписывается через дефис: «ли-ии», «л-ак». Правило — в `scripts/syllables/build.py` (`ALIF_FORMS`), файл пересобран. Татвиль «ـ» перед алифом — не лигатура (и в мусхафе).
   - **Маленькие ۥ ۦ** (малые вав и йа, мадд сыла) — знак, не буква: при решении, соединять ли клетки,
     они не считаются отдельной буквой (пример — 106:2): `SMALL_MADD` в `build.py` и `render._joins`.
   - **Загрузчик** `SyllableLibrary.load` пропускает испорченные руками строки (неверный вид, пустые
     подписи, кусочки не складываются в текст) и нечитаемый YAML — бот стартует, для такого текста
     показывается прежняя карточка.

## Последствия
- Новая сура в программе → `make syllables` → проверить картинки → `status: ok`; тест красный, пока
  файл не пересобран.
- Изменили пункт в `course.ru.yaml` или `MOSHAF_PARAMS` → тест красный («файл устарел»), бот при этом
  показывает прежнюю карточку для изменённого текста (сбой виден, ученик не ломается).
- Подписи под клетками — текст ученику: правила склейки и `plain` утверждает автор (`status`).
- Решено автором 2026-10-30: «Как читается» под спойлером на карточке суры остаётся; `unchecked`
  показывается; `status: ok`/`bad` ставит человек (автор или преподаватель, TD-FN-30). Подписи внизу
  карточки нет (выбор агента: на каждой карточке она повторялась бы; объяснение шадды — в правиле
  «Читаем суры», текст — автору). Отклонено: подпись на каждой карточке.
- Правило «لا в одной клетке» и «ۥ ۦ — знак» — эвристики генератора, как и остальные правила склейки:
  клетки с дефисом в подписи («ли-ии») — места, которые человек проверяет глазами при `status: ok`.
- Испорченная строка в `ayat.yaml` не роняет бота, но и не видна сразу: для её текста молча рисуется
  прежняя карточка; заметить — тест данных «файл ↔ программа».
- Отложено (`docs/tech-debt.md`): рисунок синхронный в async-хендлере (TD-FN-118); ع и хамза не видны в
  подписях (TD-FN-119); `ayat.yaml` не входит в `curriculum.version` (TD-FN-120); сверка подписей — TD-FN-30.
- Карточка результата (`render.result`) и разбор ошибок (FR-54) не меняются; связать цвет ошибки с
  клетками — отдельное решение позже, не сейчас.

## Как проверить
- Тест данных (без `ml`): каждый пункт `section: sura` с `quran` есть в `ayat.yaml` по тексту; каждая
  строка файла — текст пункта программы; кусочки складываются ровно в `text`; `moshaf` == `MOSHAF_PARAMS`;
  пустых подписей нет.
- Unit: адаптер — `bad` не отдаётся, отсутствующий файл — пустая библиотека, «несклеивающаяся» строка
  пропускается; `ayah_number` — басмала L098 → `None`, 1:1 в L097 → 1, 2:5 → 5.
- Unit рисунка (при `render.available()`): **выборка трудных аятов** (3 самых длинных, 3 с самым
  длинным словом, самый короткий) в обоих масштабах — ширина 900, ни одно слово не шире строки; номер рисуется только
  при `number`. Не все 192 × 2: прогон всех занимает больше лимита тестов (< 10 с, `CLAUDE.md`).
  Без libraqm тест подменяет `render.rule`. Пиксели (форма букв, лигатура) тест не проверяет — глазами
  при `status: ok`.
- `tests/integration/test_syllable_library.py`: «لا» никогда не делится между клетками; испорченные
  строки и нечитаемый YAML пропускаются, загрузка не падает. `tests/unit/test_ayah_render.py`: ۥ ۦ — не
  соединяющие буквы (106:2). `tests/unit/test_syllables_merge.py`: `status` человека сохраняется при том же
  разборе, изменённый или новый — `unchecked`.
- Screens: sura-карточка с данными → `render.ayah`; без данных или `bad` → `render.card`; ключ экрана
  учитывает масштаб, как сейчас.
- `tests/integration/test_di.py`: `AyahSyllables` зарегистрирован; import-linter зелёный.
