# ADR-0079: Разметка учителем по слогам и буквам — кнопки-клетки, вид ошибки, таблица `annotation_marks`

- **Статус:** Принято
- **Дата:** 2026-10-31
- **Кто решил:** предложил агент (архитектор); утверждает автор (ADR-0021). Уже решено автором
  2026-10-31: поток «клетка → вид → (буква)», 11 видов в трёх группах без «не уверен», клетки
  по `ayat.yaml` для сур и по буквам для остальных строк, ⚠️ на клетках бота, «⌨️ Ввести вручную» остаётся, карточка по слогам у ученика больше не прячется при `bad`.
  Автор 2026-10-31 после предложения: вариант A (отдельная таблица — удобнее собирать примеры для
  обучения и проверки модели); в одной клетке — несколько видов; «пропустил» = не прочитана вся
  клетка; первый экран — учитель **оценивает чтение ученика**, а не бота: «✅ Прочитал чисто» /
  «✏️ Есть ошибки — отметить»; согласие с ботом считается автоматически (вариант «оценивает бота»
  и «ошибки бота уже отмечены» — отклонены: путаница и привязка к ответу бота).
- **Связано:** FR-62 (новое), FR-17, FR-61, FR-55; ADR-0002, ADR-0040, ADR-0041, ADR-0043,
  ADR-0065, ADR-0072, ADR-0077; QAS-01, QAS-08, QAS-09; SRC-043, SRC-063, SRC-064, SRC-065

## Контекст
1. Сейчас разметчик в Telegram (FR-17) выбирает «✅ Бот прав» или «✏️ Бот ошибся» и **набирает
   фонемы** фонетическим алфавитом модели (`domain.annotation.check_phonemes`, руководство 2.1).
   Для преподавателя это медленно и требует знать алфавит; на длинном аяте (~40 слогов) почти
   невыполнимо.
2. Предыдущие решения: ADR-0040 отклонил «метку на каждую найденную ботом ошибку» — пропуски
   модели (FA) так не локализуются. ADR-0041 отложил «исправление кнопками "буква → как
   прозвучала"» — неточно для огласовок, мадда, лишних звуков. **Что изменилось:** (а) клетки —
   это **вся строка**, а не только ошибки бота: учитель отмечает и то, что бот пропустил, — FA
   локализуется с точностью до клетки; (б) вид ошибки покрывает огласовку, мадд, лишний звук и
   таджвид как категории; (в) точные фонемы остаются кнопкой «⌨️ Ввести вручную»; (г) появилась
   раскладка аята по слогам (ADR-0077, порт `AyahSyllables`). Цена: точные фонемы (данные для
   дообучения) получаются только из части меток — см. «Последствия».
3. Метрики RQ-1/RQ-2 (`research/metrics.py`) считаются по фонемам эталона из
   `annotations.corrected_phonemes` (схема MDD TA/FR/FA/TR, SRC-064; L2-ARCTIC SRC-063 размечает
   замену/пропуск/вставку на уровне фонемы; Iqra'Eval SRC-043). Метки по клеткам должны либо давать
   `corrected_phonemes`, либо считаться отдельной метрикой «по клеткам».
4. Ограничения: слои (ADR-0002, домен — stdlib); polling, состояние — FSM в памяти (ADR-0008,
   TD-FN-70); без Redis (ADR-0005); бот без модели (ADR-0006) — клетки строятся без `ml`;
   `callback_data` ≤ 64 байт; ≤ 100 кнопок и ≤ 8 в ряду у inline-клавиатуры; закрытый пилот.
5. Схема БД, тексты разметчику, руководство и его версия — решение человека.

## Решение (вариант A, выбор автора)
1. **Домен** (`domain/annotation.py`, stdlib):
   - `MarkKind` (StrEnum, 11 значений, у каждого `group` и короткий код ≤ 3 символов для кнопки):
     *сказал неправильно* — `letter` (не та буква), `vowel` (огласовка), `madd` (коротко/долго),
     `shadda_sukun`, `missing` (пропустил), `extra` (лишний звук); *таджвид* — `tafkhim`
     (твёрдо/мягко), `ghunna` (ихфа, идгам), `qalqala`; *как читает* — `halting` (запнулся/по
     буквам), `wrong_stop` (остановился не там).
   - `Cell(index, start, end, piece)` — кусочек строки `item_text` с позицией в символах;
     `annotation_cells(text, syllables | None) -> tuple[Cell, ...]`: при раскладке аята — клетки
     из `ayat.yaml` в порядке чтения, иначе — по одной на `domain.arabic.clusters(text)` (буква со
     знаками). Кусочки без пробелов складываются ровно в текст.
   - `bot_cells(text, reference, heard, cells) -> frozenset[int]` — клетки, где ошибку нашла модель:
     `phoneme_errors(reference, heard)` → согласная эталона → `arabic.owners` → кластер → клетка
     (тот же разбор, что у бота; вставка — к клетке предыдущей согласной).
   - `Mark(cell, kind, heard_letter: str | None)` и `apply_marks(text, reference, cells, marks) -> str
     | None` — `corrected_phonemes` из меток, **где это однозначно**: нет меток → эталон;
     `letter` с выбранной буквой в клетке ровно с одной звучащей согласной → эта согласная
     (обе половины шадды) заменена; `missing` → удалены все фонемы клетки (согласные и их
     огласовки). Любая другая метка (огласовка, мадд, шадда, лишний звук, таджвид, «как читает»,
     `letter` без буквы или в слоге с двумя согласными) → `None`.
   - `marks_status(bot_heard, reference, actual, marks)`: учитель оценивает чтение, а не бота;
     «✅ Прочитал чисто» = эталон без меток. Метка `agree`, если чтение по учителю совпало с тем,
     что услышал бот (нет меток и бот не нашёл ошибок; или метки сводятся к фонемам, равным
     `bot_heard`), иначе `fix`. `check_marks`: клетка в пределах раскладки, `heard_letter` только у `letter` и только
     согласная фонетического алфавита. `GUIDE_VERSION = "3.0"` (после утверждения руководства).
2. **Порт и сценарий:** `AnnotationTasks.add(label, marks)` пишет метку и её клетки в одной
   транзакции; `SubmitMarks` (или расширение `SubmitAnnotation` параметром `marks`) — права, время,
   «сам исправился», статус по правилу выше. `AnnotationTask` дополняется `cells` и `bot_cells`
   (строит `NextAnnotation` через порт `AyahSyllables`, ADR-0077). Регистрация — `bootstrap/di.py`.
3. **БД** (миграция `0011_annotation_marks`):
   - новая таблица `annotation_marks`: `id` PK; `annotation_id` FK → `annotations.id`
     **ON DELETE CASCADE**, индекс; `cell` SMALLINT (номер клетки с 0); `layout` (`syllables` |
     `letters`, CHECK); `char_start`, `char_end` SMALLINT — позиция кусочка в `item_text` (не
     зависит от пересборки `ayat.yaml`, TD-FN-120); `piece` TEXT — кусочек, как его видел учитель;
     `kind` VARCHAR(32) CHECK по `MarkKind`; `heard_letter` VARCHAR(4) NULL (фонема; NULL — не
     указал или «не знаю»); `bot_flagged` BOOLEAN — стояла ли на клетке ⚠️ (для угрозы подсказки,
     `preregistration.md` §5); UNIQUE(`annotation_id`, `cell`, `kind`).
   - `annotations.entry` VARCHAR(16) NULL: `cells` | `phonemes` (NULL — до миграции, Excel);
     `annotations.corrected_phonemes` у `fix` может быть NULL, если `entry = 'cells'` и метки не
     сводятся к фонемам.
   - Удаление по отзыву согласия: `delete(annotations)` в `repositories/attempts.py` уже есть —
     клетки уходят каскадом (SQLite в тестах — `PRAGMA foreign_keys=ON`, `engine.py`); тест
     `/delete` проверяет, что строк `annotation_marks` не осталось. `docs/security/privacy.md`,
     `docs/data/data-dictionary.md` — новые поля.
4. **Telegram** (`presentation/telegram/annotation.py`, тексты — `annotator_texts.py`, утверждает
   автор): одно сообщение-карточка, клавиатура меняется на месте (`edit_reply_markup`):
   - первый экран: запись, карточка, подсказка бота («бот: ошибка в „на“»), кнопки «✅ Прочитал
     чисто», «✏️ Есть ошибки — отметить», «🔊 Как правильно», «🔁 Сам исправился», «🔇 Плохая
     запись», «🙅 Читал не то», «⏭»;
   - шаг «клетки»: по ряду на слово, ≤ 8 кнопок в ряду (длинное слово — на два ряда), порядок в
     ряду справа налево; на кнопке кусочек (`ZWJ` по краям, как в `render.ayah`), ⚠️ — бот нашёл,
     ❌ + код вида — отмечено; внизу «✅ Готово», «⌨️ Ввести вручную»,
     «↩️ Отмена». Самый длинный аят ≈ 40 клеток + 4 → < 100 кнопок;
   - шаг «вид»: 11 кнопок по группам (по ряду на группу; в одной клетке можно несколько видов —
     нажатый вид отмечается ✓, повторное нажатие снимает) + «🗑 Снять» (если клетка отмечена) +
     «◀️ Назад»;
   - шаг «буква» (только `letter`): что услышал бот в этой клетке, пары из
     `lexicon.pair_tips` (уже грузится как `Lexicon.pair_tips`), «другая…» (28 букв), «не знаю»;
   - `callback_data`: `AnnotateMark(prefix="am")`: `a` (UUID.hex, 32), `s` (шаг: c/k/h/d/n/m/q/x),
     `c` (клетка), `k` (код вида), `h` (буква) — самый длинный ≈ 48 байт (тест на ≤ 64);
   - черновик меток — в `Desk` (FSM): `{"marks": {attempt_hex: [[cell, kind, letter|null], …]}}`;
     «↩️ Отмена» и «⏹ Закончить» его сбрасывают; в БД пишет только «✅ Готово» / «✅ Прочитал чисто».
5. **Метрики** (`research/metrics.py`): фонемные цифры RQ-1 — как сейчас, по всем меткам с
   `corrected_phonemes` (из клеток или вручную); **новый блок «по клеткам»**: для каждой метки
   `entry = 'cells'` — исход клетки TA/FR/FA/TR (модель отметила клетку × учитель отметил
   клетку), precision/recall/F1, recall по виду ошибки учителя, α Криппендорфа по клеткам
   (ошибка/нет) и по виду (SRC-065), бутстрэп по ученикам — тот же `cluster_bootstrap`. В отчёте —
   отдельно от фонемных цифр и с пометкой, что единица крупнее фонемы (с Iqra'Eval не сравнивать
   напрямую).
6. **Экспорт:** датасет (`research/dataset.py`) — у каждой метки `entry` и список `marks` (cell,
   char_start, char_end, piece, kind, heard_letter, bot_flagged); плоская выгрузка — колонка
   `marks` строкой. Пакет Excel (`research/annotation.py`) **не меняется**: импорт по-прежнему
   фонемами, `entry = 'phonemes'`.
7. **Ученик (FR-61, поправка ADR-0077 п. 1):** `status: bad` в `ayat.yaml` больше не прячет
   карточку по слогам — только пометка «поправить разбор»; `SyllableLibrary.load` отдаёт `bad`.
   Меняются тесты «bad → прежняя карточка» (`test_syllable_library.py`, `test_di.py`, тест экрана) —
   через `scripts/phase tests` с согласия автора.


## Дополнено 2026-11-01 (после ревью и прохода по боту; решения автора)
Размечают профессора — экран строгий и короткий:
1. **Один экран** (вместо шагов «первый экран → клетки → вид»): сверху слоги (ряд на слово, первый
   слог справа), под ними — «Что не так в «…»» для выбранного слога, внизу — действия. Нажал слог →
   он выбран; нажал вид → отметка (в слоге несколько, повторное нажатие снимает); нажал другой слог →
   отмечает его. Сообщение над кнопками называет выбранный слог и всё отмеченное.
2. **Без смайликов**, короткие слова: «Чисто», «Готово», «Эталон», «Сам исправился», «Комментарий»,
   «Плохая запись», «Читал не то», «Фонемы вручную», «Пропустить»; виды — «Буква», «Огласовка»,
   «Длина», «Шадда/сукун», «Пропуск», «Лишний звук», «Твёрдость», «Гунна», «Калькаля», «Запинка»,
   «Пауза не там»; по 2 в ряд. Отмеченный слог — «×», выбранный — в квадратных скобках, где ошибку
   нашёл бот — «!» (подсказку бота **показывать** — решение автора).
3. «Готово» без отметок — подсказка «Отметьте слог или нажмите «Чисто»», ничего не сохраняется.
4. **«Комментарий»** — необязательный текст к записи («сомневаюсь», «шум»), поле `annotations.comment`.
5. **Исправления данных (ревью кода):** в раскладке по буквам долгая буква мадда (ا و ي без
   огласовки) и немые буквы — в одной клетке со своей согласной («بَا»), как в слогах сур: в клетке
   всегда есть звук, «Пропуск» и «Длина» не теряются и бот с учителем отмечают одну и ту же клетку.
   Правило «бот прав» одно для клеток и ручного ввода (равны ошибки относительно эталона); при
   `agree` в `corrected_phonemes` пишется то, что услышал бот (`check_label`, как в Excel).

## Последствия
- Разметка аята — нажатия вместо набора фонем; ручной ввод остаётся для точных данных.
- Фонемные метрики RQ-1 считаются только по меткам, сводимым к фонемам (замена с буквой, пропуск,
  «ошибок нет», ручной ввод); остальные — только на уровне клеток. Выборка для фонемных цифр
  смещена к простым ошибкам — описать в главе об угрозах (TD-FN-131).
- Учитель видит ⚠️ бота — эффект подсказки сильнее, чем при наборе фонем (ADR-0065 принял
  подсказку); `bot_flagged` позволяет оценить его (TD-FN-132).
- Руководство разметчика → 3.0: определения 11 видов, правило «пропустил = не прочитана вся
  клетка», когда вводить вручную. Текст готовит агент, утверждает автор.
- Ученик видит слоги и при `bad`: неверный разбор аята дойдёт до новичка, пока его не поправят —
  осознанный выбор автора 2026-10-31.
- Отложено (`docs/tech-debt.md`): TD-FN-129 черновик меток в памяти теряется при перезапуске
  (вместе с TD-FN-70); TD-FN-130 пакет Excel без клеток; TD-FN-131 фонемы не выводятся для 9 видов и
  для «не та буква» в слоге с двумя согласными (смещение выборки); TD-FN-132 эффект подсказки ⚠️ —
  слепой режим или доля слепых меток; TD-FN-133 метрика по клеткам не сравнима с фонемной Iqra'Eval
  — в диссертации отдельной таблицей. После прохода 2026-11-01: TD-FN-134 `make try` не играет
  разметчика; TD-FN-135 разметчик-ученик может подделанной кнопкой разметить свою попытку; TD-FN-136
  гонка двойного «Готово»; TD-FN-137 руководство 3.0 и `GUIDE_VERSION` ждут утверждения
  (черновик агента ещё не в репозитории); TD-FN-138 плоская выгрузка без колонки `marks`.

## Как проверить
- Unit домена: `annotation_cells` — кусочки складываются в текст, по буквам = `clusters`;
  `bot_cells` на примерах с заменой/пропуском/вставкой; `apply_marks` — замена, пропуск (с
  шаддой), «нет меток» → эталон, недоопределённые → `None`; `marks_status`; `check_marks`;
  `MarkKind` — 11 видов, 3 группы, коды уникальны.
- Клавиатуры: для самого длинного аята программы — ≤ 100 кнопок, ≤ 8 в ряду; все `callback_data`
  ≤ 64 байт (UTF-8).
- По дополнению 2026-11-01 экран один — актуальные сценарии в `tests/integration/test_annotator_marks_bot.py`. Исходный план:
  `tests/integration/test_annotator_bot.py`: «✏️» → клетка → вид → буква → «✅ Готово» сохраняет метку
  и клетки; «✅ Прочитал чисто» → эталон (`agree`, если бот тоже не нашёл ошибок, иначе `fix`); «⌨️» → прежний ввод;
  «↩️ Отмена» ничего не пишет; чужая/старая кнопка — молча.
- Миграция: upgrade/downgrade (`tests/architecture/test_migrations.py`), FK с каскадом; `/delete`
  удаляет клетки.
- Метрики: блок «по клеткам» на синтетических метках; фонемные цифры не меняются для старых меток.
- Экспорт: датасет содержит `marks`; пакет Excel — прежние колонки.
- `tests/integration/test_di.py`: сценарий зарегистрирован; import-linter зелёный.
