# ADR-0076: Сура целиком и чтение наизусть

- **Статус:** Принято 2026-10-31 (реализация — по TDD, FR-57…FR-60)
- **Дата:** 2026-10-31
- **Кто решил:** автор — все пункты «Решение» (обсуждение 2026-10-30/31); устройство проверки и
  нарезка записи — агент
- **Связано:** FR-57…FR-60, ADR-0007 (васл и вакф), ADR-0019 (след решения), ADR-0022 (строка книги),
  ADR-0043/0044 (самоисправления в разметке и метриках), ADR-0052, ADR-0064 (RQ), TD-FN-10, TD-FN-114…117

## Контекст
Суры — уроки 97–125, одна карточка = один аят; длинные суры разбиты на части (1/2, 2/2…). Автор:
ученик должен уметь прочитать суру **целиком, без остановки**, одним голосовым и сразу получить
разбор; и читать суру **наизусть** — текст пропадает, когда ученик готов. Наизусть — ещё и данные
исследования: где забывают, где путают, где произносят неверно.

Замер 2026-10-30 (временная папка, чтение аль-Афаси): одним проходом модель на 40 с звука
(аль-Фатиха) не уложилась в 8 ГБ памяти — около часа без результата. Нарезку замерить не успели
(автор остановил замеры).

Фонетизатор quran-transcript ставит остановку только в конце текста; если склеить аяты, чтение с
остановкой в конце аята (так читают почти все) даст ложные ошибки на окончаниях. Модель Muaalem
распознаёт фонемы без эталона (жадный CTC), эталон нужен ей только для сифат.

## Решение
1. **«📖 Вся сура»** — кнопка в каждом уроке суры (и в каждой части): текст всех аятов суры, 🔊
   аль-Афаси целиком, одно голосовое, разбор **по аятам** (итог «чисто N из M», ниже только аяты
   с ошибками, у каждого — «повторить аят» на обычную карточку).
2. **Зачёт «всё или ничего»:** все аяты чистые (тот же порог `GradingPolicy`) → засчитаны все уроки
   суры со всеми частями; хоть одна ошибка → ничего не засчитано.
3. **«🧠 Наизусть»** — в главном меню (список всех сур) и в каждом уроке суры; **доступно всегда**,
   даже если сура не начата. Название суры и текст → «Готов» → бот **удаляет текст**, остаётся
   название → голосовое → разбор по аятам. Все аяты чистые → отметка «🧠 наизусть» у суры;
   **уроки не засчитываются**.
4. **Самоисправление — не ошибка** (ошибся и тут же сам прочитал верно); **молчание — не ошибка**.
   И то и другое сохраняется событием для исследования. Длина «долгой паузы» — настройка, значение
   не утверждено (TD-FN-116).
5. **Проверка длинной записи:** запись режется на куски 6–10 с в самой тихой точке (numpy, без новых
   зависимостей) — внутри адаптера модели; фонемы кусков склеиваются; эталон — аяты по отдельности,
   каждый с остановкой в конце (фонемы и сифат склеиваются); ошибки раскладываются по аятам по
   позиции в эталоне.
6. **Данные — новые таблицы, старые не меняются:**
   - `sura_readings` — одно голосовое: ученик, сура, режим (`text`/`memory`), номер попытки этой суры
     в режиме, дней с прошлого чтения суры, проходил ли суру по тексту, аятов чисто / всего, балл,
     итог, длина записи, время проверки, версия модели и программы, `audio_sha256` (только с согласия);
   - `sura_reading_chunks` — кусок 6–10 с: начало и конец (мс), какой аят и слова покрывает, что
     услышано — **строка для разметки и датасета** (как обычная попытка);
   - `sura_reading_ayahs` — аят: итог (`clean`/`pronunciation`/`forgot_part`/`skipped`/`not_reached`),
     балл, число забытых, лишних, ошибок произношения;
   - `sura_reading_events` — ошибка, заминка, самоисправление: аят, слово, вид, нужно / прозвучало,
     длина паузы.
   Удаление данных ученика стирает и эти таблицы.
7. **Исследование:** записи сур — отдельная часть датасета; в главные цифры RQ-1/RQ-2 по строкам книги
   не входят (их данные — строки книги; оговорку в `docs/research/preregistration.md` вносит автор), сравниваются отдельно; чтение наизусть через дни — мера удержания для
   RQ-3.

## Рассмотренные варианты
| Вопрос | Вариант | Итог |
|---|---|---|
| Проверка | одним проходом | Отклонено: 40 с не уложились в 8 ГБ |
| Проверка | резать по паузам (silero-vad) / выравнивание (ctc-forced-aligner) | Отклонено: новая зависимость; ученик читает без пауз |
| Проверка | **куски 6–10 с в самой тихой точке** | **Принято** |
| Зачёт по тексту | засчитывать чистые аяты | Отклонено автором |
| Зачёт по тексту | только упражнение | Отклонено автором |
| Зачёт по тексту | **всё или ничего** | **Принято** |
| Наизусть | засчитывать и уроки | Отклонено: можно «пройти» суру, не открыв текст; смешивает данные |
| Наизусть | **отдельная отметка 🧠** | **Принято** |
| Скрыть текст | в момент записи | Невозможно: Telegram не сообщает боту о начале записи |
| Скрыть текст | спойлер | Отклонено: открытый спойлер не закрыть |
| Скрыть текст | мини-приложение | Отклонено: отдельная большая работа |
| Скрыть текст | **кнопка «Готов» — бот удаляет текст** | **Принято** |
| Подсказка | кнопка «💡 подсказка» во время чтения наизусть | Отклонено автором |
| Вопрос «как ощущения» | после чтения наизусть | Отклонено автором: новичок устанет, пользы мало |
| БД | попытка на аят + два столбца в `attempts` | Отклонено: смешивает с попытками по карточкам |
| БД | одна попытка `SURA-NNN` с JSON | Отклонено: отчёты и разметка не видят аяты |
| БД | **новые таблицы** | **Принято** |
| Заминки | ошибка | Отклонено автором; как у руководителя (@recitobot, со слов автора) и DIBELS |

## Дополнение (агент, 2026-10-31, по ревью архитектуры и безопасности)
8. *Зачёт суры в прогрессе:* засчитанные карточки (`sura_readings.credited`, `passed`) входят в лучшие
   баллы строк как 100 (`SqlAttemptRepository.best_scores`): от этого зависят прогресс, курсор,
   повторение, «урок пройден», выбор букв «Закрепления». В метрики FR-55 (из `attempts`) не входят
   (п. 7). Отклонено: синтетические строки в `attempts` (смешало бы данные, п. 6); отдельный «прогресс
   сур» (ученик видел бы пройденную суру непройденной).
9. *Экран суры* хранится в `learner_settings.screen_item_id` как `sura:N:text|look|memory`, без нового
   столбца. Отклонено: новый столбец (изменение схемы ради состояния экрана); FSM aiogram в памяти
   (теряется при перезапуске, ADR-0061).
10. *Порт `SuraRecognizer`* реализуют те же `MuaalemRecognizer`/`StubRecognizer`: модель грузится один
    раз. Отклонено: отдельный адаптер (вторая копия модели, памяти не хватает уже на 8 ГБ); метод в
    `PronunciationRecognizer` (лишний метод в узком порте).
11. *Нарезка* — numpy внутри адаптера (`infrastructure/asr/chunks.py`), без порта: деталь
    распознавания, не внешняя зависимость.
12. *Записи голоса сур* учитываются везде, где учитываются записи попыток: отзыв согласия,
    /delete, повтор журнала удалений (`SqlAttemptRepository`), сверка хранилища `verify` и
    `--delete-orphans` (`research/integrity.py`, список таблиц с голосом — `_VOICE_TABLES`).
13. *Значок «Наизусть» — 🎯*, а не 🧠 из п. 3: 🧠 уже у «Закрепления»; отметка выученной суры в списке — ✅
    (черновики, TD-FN-117).
14. *Без ограничения длины записи суры* (решение автора 2026-10-31: «суры бывают больше минуты, я за то,
    чтоб не было ограничений»): `decode_to_pcm(max_seconds=None)` только для суры целиком; карточка
    строки по-прежнему режется на 60 с (NFR-SEC-05). Сверху длину ограничивает сам Telegram (бот
    скачивает файлы до 20 МБ); память — нарезка по 10 с. Отклонено: 60 с для всех (аль-Алак и
    аль-Баййина не сдать), отдельный лимит 180 с.
15. *Необязательное начало перед сурой* — истиаза (карточка L001-02) и басмала, вместе, по отдельности
    или ничего: урок 1 учит начинать с них (ревью кода 2026-10-31). «صدق الله العظيم» в конце не
    предусмотрено — вопрос автору.
16. *Самоисправление* — только лишний кусок размером со слово (≥ 3 звуков с согласной), похожий на
    соседнее слово; один лишний знак (قُل → قُلُ) — ошибка. Звуки, случайно совпавшие с пропущенным
    аятом, отдаются соседнему прочитанному аяту.
17. *Решения автора 2026-10-31 по итогам ревью:*
    - сдал суру целиком по тексту — «▶️ Продолжить» переносится на урок после суры (если ученик был в
      ней или раньше; назад не двигаем);
    - чтение суры (любой режим) идёт в серию дней и «сегодня попыток» (`SqlAttemptRepository.activity`);
      в «всего попыток» и метрики FR-55 — нет;
    - порог `GradingPolicy` сохраняется в каждом чтении (`sura_readings.policy`, ADR-0019);
    - гонку «отозвал согласие, пока сура проверяется — голос сохранится» **оставили** (как у карточек;
      риск мал). Отклонено: перечитывать согласие в транзакции перед сохранением голоса.

## Последствия
- Время ответа на длинных сурах не измерено — проверить в Telegram (TD-FN-114).
- Разметка учителем — по кускам 6–10 с (TD-FN-115).
- Тексты экранов — черновики агента, утверждает автор (TD-FN-117).
- Схема БД — миграция и `docs/data/data-dictionary.md`; персональные данные — `docs/security/privacy.md`.
- Источник о разметке заучивания: arXiv 2609.12085 — завести SRC после проверки (`/source`, TD-FN-126).
