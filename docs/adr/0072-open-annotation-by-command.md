# ADR-0072: Разметка открыта по команде /annotate — без ID и приглашений

- **Статус:** Принято
- **Дата:** 2026-10-24
- **Кто решил:** автор («чтоб любой, кто знает эту команду, мог размечать»; разметчики — не
  айтишники, ученики про команду не знают); варианты предложил агент
- **Связано:** частично заменяет ADR-0041 (доступ только списком и приглашением); FR-17, ADR-0057,
  TD-SEC-20, TD-SEC-21, TD-SEC-24

## Контекст
По ADR-0041 в разметку попадали двумя путями: Telegram ID в `ANNOTATOR_IDS` (перезапуск бота) или
одноразовый код из `muallim-research annotator-invite`. Разметчики автора — преподаватели, не
айтишники: узнать свой ID или ввести код для них трудно. Автор раздаёт бота только своим людям.

## Решение
1. Кто написал `/annotate`, тот разметчик: бот сам выдаёт код `A<n>` (номер после наибольшего из
   кодов в настройках, `annotators`, `annotator_invites`, `annotations`; дыры не занимаются),
   привязывает его к Telegram ID и сразу показывает запись. При первом входе — приветствие
   с инструкцией по шагам.
2. Отзыв остаётся: `annotator-revoke` закрывает код навсегда, `/annotate` его не возвращает
   (у отозванного бот ведёт себя как с учеником).
3. `ANNOTATOR_IDS` и приглашения работают как раньше (для заранее выбранного кода).
4. Кнопка «↩️ Переделать» под «✅ Сохранено» показывает ту же запись снова; новая метка ложится рядом,
   в данных берётся последняя метка разметчика (как и раньше в `dataset.py`, `metrics.py`).
5. Оспоренные учеником записи по-прежнему первыми в очереди (`queue_query`, ADR-0020) — не менялось.
6. Свои попытки разметчик не размечает: очередь исключает попытки ученика с тем же Telegram ID, что
   привязан к коду (иначе ученик подтверждает свой же спор). Для кодов только из `ANNOTATOR_IDS`
   привязки в БД нет — им свои попытки видны (доверенные люди автора).
7. «↩️ Переделать» не сбрасывает начатое исправление текущей записи; после ответа на повторно
   показанную запись следующая не присылается («продолжайте с записью выше»).
8. Слово после `/annotate` считается приглашением, только если похоже на код (`KQ7M-29FX-HT3P`);
   иначе — обычный открытый вход.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Заявка + кнопка «пустить» у автора | без ID и кодов; безопасно и на пилоте с незнакомыми | каждого нового автор подтверждает нажатием | отклонено автором (рекомендовал агент) |
| **Полностью открыто** | проще некуда | любой, кто узнал команду (в т. ч. ученик), слышит чужие голоса и пишет метки в данные исследования | **принято** |
| Открыто с выключателем `ANNOTATION_OPEN` | просто сейчас | легко забыть выключить перед пилотом | отклонено |
| Общий пароль | без участия автора | пароль утечёт, не узнать через кого | отклонено |
| Команда в меню только у разметчиков | не надо помнить команду | отдельный список команд на чат | не выбрано автором |
| Управление разметчиками из бота (`/annotators`) | без терминала | вторая роль «владелец» в боте | не выбрано автором |

## Последствия
- **Закрыть доступ можно только `annotator-revoke`**: удаление из `ANNOTATOR_IDS` больше не закрывает —
  человек войдёт по `/annotate` с новым кодом. Приглашение выпускать только на новый код.
- Telegram ID вошедшего ученика остаётся в `annotators` после удаления его данных — TD-SEC-25.
- Защита держится на том, что команду знают только свои: она не показывается в меню и в справке.
  Перед пилотом с незнакомыми учениками это нужно пересмотреть — **TD-SEC-24 (T1)**.
- Метки случайного человека попадут в данные под своим кодом; их видно по `annotators.created_at` и
  событию `annotator_joined` и можно исключить из анализа (код ≠ человек из списка автора).
- TD-SEC-21 (обязательство разметчика) теперь нельзя выполнить «до выдачи доступа» — доступ выдаётся
  сам; подписывать до того, как сообщить человеку команду.
- `StaffAccess` (ADR-0057): вошедший по `/annotate` видит служебный блок «Для исследования».
- Схема БД не менялась: `annotators` уже хранит код и Telegram ID.

## Как проверить
`tests/unit/test_annotation.py` (код по порядку, повторный вход, отзыв, коды из Excel и приглашений,
«переделать»), `tests/integration/test_annotators_sql.py` (выдача кода на SQL, отозванный код не
выдаётся снова), `tests/integration/test_annotator_bot.py` (вход по `/annotate`, приветствие один раз,
кнопка без входа, отозванный не возвращается, «↩️ Переделать»).
