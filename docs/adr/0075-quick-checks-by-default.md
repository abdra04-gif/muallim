# ADR-0075: Полная проверка только для кода и только по слову автора

- **Статус:** Принято 2026-10-30
- **Дата:** 2026-10-30
- **Кто решил:** автор (просьба и выбор «CI только для кода»); устройство — агент
- **Связано:** ADR-0039, ADR-0071

## Контекст
Перед каждым push хук `git_guard` гонял mypy и все тесты, `/ship` требовал `make check`, а CI на
GitHub запускался на любой push. На правке документа или навыка автор ждал несколько минут, хук
падал по времени и push не уходил. Автор: «при небольших изменениях полная проверка не нужна».

## Решение
- **Перед push** (`git_guard`): по умолчанию быстрая проверка, то есть import-linter, ruff и
  тесты только изменённых файлов. Если push меняет `src/`, `migrations/`, `curriculum/`,
  `pyproject.toml`, `uv.lock`, `Dockerfile`, хук останавливает push, и агент **спрашивает автора**:
  «да» → `CHECK=full git push` (mypy и все тесты), «нет» → `CHECK=quick git push`.
- **`/ship`**: `make check` запускается только по согласию автора; иначе нужны быстрые проверки
  изменённых файлов.
- **CI** запускается только на те же пути кода (плюс `tests/`, `.github/workflows/`). Документы,
  диплом и обвязка агента CI не запускают.
- Хук срабатывает только на команду, которая начинается с `git push`: текст «git push» внутри скрипта
  или документа push не запускает.

## Отклонено
- **Убрать CI совсем.** Тогда поломка бота при «нет» на полную проверку не видна до запуска.
  CI идёт на GitHub в фоне и автора не задерживает. Автор выбрал вариант «только для кода».
- **Оставить полную проверку на каждый push, увеличив время хука.** Автор ждёт минуты на
  правке опечатки.
- **Решать «важно или нет» агенту без вопроса.** Автор просил спрашивать его.
