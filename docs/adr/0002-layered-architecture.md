# ADR-0002: Слоистая архитектура с проверкой зависимостей

- **Статус:** Принято
- **Дата:** 2026-10-17
- **Кто решил:** предложил агент, утвердил Исмаилов
- **Связано:** NFR-MNT-01, NFR-MNT-02, ADR-0003, SRC-009

## Контекст
Прототип (`experiments/bot.py`) — один файл на 256 строк: Telegram, SQL, модель и логика вместе.
Его нельзя протестировать без загрузки модели (~2 ГБ), а замена любой части (модель, БД, мессенджер)
требует переписывать всё. Проект будет развиваться годами (магистратура → докторантура).

## Решение
Код разделён на слои (подход «чистой архитектуры» / портов и адаптеров):

| Слой | Что внутри | Может импортировать |
|---|---|---|
| `domain` | оценка чтения, типы ошибок, уроки, пороги | только стандартную библиотеку |
| `application` | сценарии (use cases) и порты (протоколы) | `domain` |
| `infrastructure` | PostgreSQL, Muaalem, ffmpeg, файлы, YAML | `application`, `domain` |
| `presentation` | Telegram: обработчики, клавиатуры, тексты | `application`, `domain` |
| `research` | отчёты, разметка, датасет | `infrastructure` и ниже |
| `bootstrap` | конфигурация, DI-контейнер (dishka), точки входа | всё |

`presentation` и `infrastructure` друг о друге не знают; связывает их только `bootstrap/di.py`.

Правила записаны как контракты import-linter в `pyproject.toml` и проверяются автоматически.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Один файл, как в прототипе | быстро | нельзя тестировать и менять части | Отклонено |
| Django-подобный монолит | много готового | тяжёлый, ORM в домене | Отклонено |
| Слои + порты + DI | тестируемо, заменяемо | больше файлов | **Принято** |
| Микросервисы | масштаб | избыточно для одного бота и одного разработчика | Отклонено |

## Последствия
- Модель, БД и мессенджер можно заменить, не трогая домен (например, добавить веб-версию).
- 90+ тестов выполняются < 2 с без модели и без сети.
- Больше файлов; новичку нужна карта — `docs/architecture/overview.md`.

## Как проверить
`uv run lint-imports` (в CI, в pre-commit и в Stop-хуке агента) и
`tests/architecture/test_layers.py` (нет ввода-вывода в домене, нет SQL в обработчиках,
каждый сценарий зарегистрирован в DI).
