# ADR-0026: Требования качества — сценариями (QAS), метрики — по GQM

- **Статус:** Принято
- **Дата:** 2026-10-17
- **Кто решил:** предложил агент, утвердил автор
- **Связано:** NFR-PERF-01, NFR-REL-01, NFR-REL-02, NFR-USE-01, NFR-ACC-01, RQ-1…RQ-3, SRC-047, SRC-048, SRC-049

## Контекст
Нефункциональные требования записаны одной строкой («ответ ≤ 10 с», «интерфейс понятен»). По ним нельзя
сказать, в каких условиях и чем именно они проверяются. Главное качество системы — **точность проверки
на речи новичков** — вообще не было требованием. Отчёты в `analytics/sql/` есть, но не сказано, на какой
исследовательский вопрос отвечает каждая цифра и каких цифр не хватает.

## Решение
1. Важные требования качества расписываются **сценариями качества** из шести частей (источник, стимул,
   окружение, артефакт, реакция, мера; SRC-047, гл. 3) с приоритетом «важность × риск» (идея дерева
   полезности, SRC-047, гл. 19) — `docs/requirements/quality-scenarios.md`. Строки NFR остаются как
   короткие ID; сценарий их уточняет.
2. Метрики исследования и пилота выводятся по **GQM** (SRC-048): цель → вопросы → метрики → данные →
   SQL — `docs/research/metrics-gqm.md`. Цели G1–G3 = RQ-1…RQ-3.
3. Числа, которых автор ещё не утверждал, помечаются **[утвердить]**: пороги — решение человека.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| Оставить одну строку на NFR | коротко, уже есть | нет условий и меры; точность модели не требование; комиссии не видно, как проверено | отклонено |
| Только характеристики качества ISO/IEC 25010 (через 25002, SRC-049) | стандартная классификация | классификация не даёт проверяемой меры; всё равно нужны сценарии | взято как словарь атрибутов, не как формат |
| **Сценарии QAS + GQM** | проверяемая мера у каждого требования; каждая метрика привязана к RQ; видно, каких данных нет | больше текста; часть мер пока без чисел | **выбрано** |
| Продуктовая аналитика без исследовательских целей (только North Star и воронка) | просто, хорошо для удержания | не отвечает на RQ-1…RQ-3; поощряет «накрутку» | отклонено; North Star — только как G4 с контр-метрикой |

## Последствия
- Видны пробелы: сбой распознавания не записывается (TD-FN-23); для precision/recall, κ, Δ балла,
  процентилей времени и когорт нет SQL (TD-FN-24).
- Новые требования: NFR-ACC-01 (точность проверки), NFR-REL-02 (сбой виден в данных).
- Пороги [утвердить] нужно утвердить до сбора данных для эксперимента (триггер T2).

## Как проверить
- Каждый сценарий ссылается на NFR/FR и имеет непустую «Меру».
- Каждая метрика GQM указывает таблицу и SQL или пометку, почему его нет.
- По мере появления SQL статус ❌ в обоих документах меняется на ✅.
