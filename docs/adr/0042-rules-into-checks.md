# ADR-0042: Правила — в проверки: тексты ученику, async, зависимости, CI, оценщик RQ-1

- **Статус:** Принято
- **Дата:** 2026-10-18
- **Кто решил:** Исмаилов (требование: «почини что надо и исправь» после обзора
  `docs/research/linters-hooks-agents.md`). Состав проверок предложил агент.
- **Связано:** ADR-0012, ADR-0028, ADR-0034, ADR-0035, ADR-0039, TD-FN-54…TD-FN-58, TD-FN-60,
  TD-FN-62, TD-FN-67, SRC-067, SRC-076, SRC-078, SRC-083, SRC-089, SRC-093, SRC-094

## Контекст
Обзор 2026-10-18 показал: часть правил проекта была записана только прозой, а агенты такие
правила соблюдают ненадёжно, к концу сессии хуже (SRC-076); статический анализ в цикле работает
(SRC-078). Пробный запуск инструментов нашёл реальные проблемы: тексты согласия и анкеты вне
`texts.py` (зона человека не защищала их), чтение файлов в async-функции, незакреплённые GitHub
Actions, необъявленные `aiohttp` и `quran_transcript`, мёртвые тексты, тест, который портил
`docs/requirements/verification-status.md`.

## Решение
1. **Тексты ученику — только в `texts.py`** (тест `tests/architecture/test_learner_texts.py`):
   кнопки согласия, анкеты, удаления, «Мои данные», блок «Для исследования», склонения дней
   перенесены дословно. Там же: каждая константа текстов используется; каждая кнопка ≤ 64 байт.
2. **`doc_sync` различает перенос и правку** версионируемых текстов: новая константа, повторяющая
   уже показанные строки в том же порядке, версию анкеты не поднимает; новые слова или
   перепутанные пары «код → подпись» — поднимают. Словари `NAME = {…}` теперь тоже сравниваются.
3. **ruff:** добавлены `ASYNC`, `BLE`, `C4`, `PERF`, `RET`, `SLF`; файлы SQL-отчёта читаются в
   отдельном потоке; широкий `except` оставлен только там, где он нужен, с причиной в `noqa`.
4. **Зависимости:** `aiohttp` (основные) и `quran-transcript` (`ml`) объявлены явно, версии не
   изменились; `make hygiene` — deptry и zizmor с закреплёнными версиями, в CI.
5. **CI:** все `uses:` закреплены по SHA (с тегом в комментарии), `persist-credentials: false`.
6. **Оценщик RQ-1** `src/muallim/research/metrics.py` — зона человека (`human_zones`, `ask`).
7. **Агенты:** `asr-evaluator` — правила R1–R5 (SRC-067); `learner-simulator` — предел метода
   (SRC-083, SRC-085).
8. **`scripts/trace.py --out`**: тест пишет во временный каталог.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| vulture как постоянная проверка | находит мёртвый код | на чувствительности, где видны тексты, — десятки ложных (перечисления, SQLAlchemy, провайдеры dishka: `learner_and_flag` выглядит мёртвым) | Отклонено; вместо него — тест «каждый текст используется» |
| ruff `C90` (сложность ≤ 10) | короче функции | `screens.card` (12), `annotation.act` (11) — рефакторинг экранов без пользы ученику сейчас | Отложено (TD-FN-54) |
| ruff `D`, `EM`, `FBT`, `TRY` | строже стиль | сотни находок шума | Отклонено |
| Поднять `QUESTIONNAIRE_VERSION` при переносе кнопок | хук доволен без правки | ложная граница в данных: ученик видел тот же текст; версия к тому же уже «2026-10-18» | Отклонено → решение 2 |
| zizmor 1.31.1 (последний) | свежий | вышел за 3 дня до решения — риск цепочки поставок | Отклонено; 1.30.1 (2026-09-09) |
| Хуки `SubagentStop` (читающий агент ничего не изменил) и `ConfigChange` | ловят обход проверок | поля событий в документации прочитаны не полностью; без теста на настоящем событии — риск ложных блокировок | Отложено (TD-FN-60) |
| Правило `doc_sync` «тексты → прогон learner-simulator» | напоминание | агент только читает и не оставляет файла — выполнение не проверить механически | Отклонено |

## Последствия
- Правка любой подписи кнопки или блока для ученика — вопрос человеку (хук на `texts.py`).
- `make hygiene` и шаг CI добавляют ~10 с (uvx скачивает инструменты).
- Обновление Actions — вручную: новый SHA вместо тега.

## Как проверить
`make check` (599 тестов, `test_learner_texts.py`, новые случаи в `test_hooks.py`), `make hygiene`
(«No dependency issues», «No findings»); `git status` после `pytest` не показывает
`verification-status.md`.
