# Сессия 2026-11-16/17 — задание профессора: модели, датасет, согласие на публикацию

**С чем пришли.** Профессор дал техническое задание в пять фаз (модели распознавания → существующие
датасеты → установка и проверка моделей → спецификация датасета → архитектура и согласие). Автор выделил
главное: найти всё, что может расшифровать чтение новичка, определить формат датасета и сделать так,
чтобы ученик ясно понимал: нажимая «Продолжить», он соглашается на публикацию своих записей.
Запросы — `docs/journal/prompts/2026-11.md`.

**Что сделано** (всё в `docs/research/`, работа в копии `asr-phase1`, ADR-0073).
- `PHASE_1_ASR_RESEARCH.md` — модели и сервисы по семи семействам, три редакции: поиск по каталогам,
  критический разбор, лицензии сверены на страницах моделей.
- `PHASE_2_DATASET_RESEARCH.md` — датасеты, L2-KSU подробно, RetaSy по странам (938 записей из России,
  Казахстана, Узбекистана и соседних стран), вклад Muallim.
- `PHASE_3_EXPERIMENTAL_RESULTS.md` + `phase3/` — предварительный опыт: пять систем на 840 открытых
  записях отдельных букв (SRC-170). Скрипты `letters_test.py`, `summarise.py`, сырые результаты в CSV.
- `PHASE_4_DATASET_SPECIFICATION.md` — раскладка выпуска, схема, три слоя расшифровки, деление по ученикам.
- `PHASE_5_ARCHITECTURE_AND_CONSENT.md` — архитектура, требования Telegram и закона, варианты согласия,
  черновик экрана на русском и английском, отзыв согласия, риски.
- `SOLUTIONS_ARABIC.md` — как устроены существующие арабские решения (десять подходов).
- `ANSWER_TO_PROFESSOR.md` — ответ на три вопроса профессора со ссылками на отчёты; он же оформлен
  отдельной страницей для чтения.
- Источники SRC-164…SRC-181 (`sources.md`, `sources.bib`), запись в `research-log.md`.

**Главные находки.**
- Ни у одной модели нет опубликованных результатов на взрослых новичках и на наших родных языках.
  Лучшая описанная система (SRC-166) ловит 32–46 % настоящих ошибок учеников.
- Опыт на буквах: буква и огласовка верны у лучшей системы в 50,0 %, у модели бота (Muaalem) — в 39,4 %.
  Модель бота в 411 записях из 840 написала долгую гласную вместо краткой.
- Правила Telegram для ботов запрещают сбор данных для датасетов без явного активного согласия.
  Предложение ADR-0085 (без экрана согласия) с открытым датасетом несовместимо.

**Решения.** Не принято ни одного: модель согласия, текст экрана, лицензия, несовершеннолетние, страна
сервера, лицензия Quran Lab — за автором и руководителем. ADR не писались. Варианты с рекомендациями —
в `ANSWER_TO_PROFESSOR.md` §5 и `PHASE_5_ARCHITECTURE_AND_CONSENT.md` §6.

**Проверено / не проверено.**
- Запускалось: пять моделей по 840 записей на MacBook Air M1 8 ГБ; `ruff check` на скриптах `phase3/`.
- Не запускалось: `make check` (код бота не менялся), тесты, сборка LaTeX.
- Опыт фазы 3 — не оценка бота на наших учениках: записи индонезийских школьников, меток
  «верно / неверно» нет, модели без настройки.
- Не проверены: Quran Lab TajweedFormer V4 (лицензия и доступ), Azure и Gemini (записи ушли бы наружу),
  L2-KSU (доступ не запрошен), сравнение с записью учителя, классификатор букв.
- Юридическая часть — по комментариям юридических фирм, не по официальным текстам.
- У части новых источников авторы и годы помечены «проверить»; статья о L2-KSU (Springer) так и не открылась.

**Отложено / открыто.**

- Методика: считать ли ошибкой протянутую гласную на отдельной букве — решает автор.
