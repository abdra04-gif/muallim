# Итерации проектирования

Как архитектура выросла из требований качества. Метод — облегчённый ADD (Attribute-Driven Design,
SRC-047, гл. 20): за одну итерацию берётся **одна цель** и **несколько драйверов** (сценарии QAS, NFR,
ограничения), принимаются решения (ADR), а результат проверяется тестом. Полные документы итераций
для одного автора — лишняя бюрократия, поэтому итерация занимает одну строку, а подробности лежат в ADR.

Итерации 1–7 восстановлены задним числом по ADR (2026-10-17): решения принимались в этом порядке,
но итерациями их тогда не называли.

## Как вести новую итерацию
1. Цель одной фразой; драйверы — ID из `requirements/quality-scenarios.md` и `requirements.md`.
2. Варианты решений — `/decide`; выбранное и отклонённое — ADR.
3. Тест, который подтверждает решение.
4. Строку перенести из «Следующих» в «Выполненные».
