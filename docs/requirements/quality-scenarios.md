# Сценарии качества (QAS)

Нефункциональные требования из `requirements.md`, расписанные так, чтобы их можно было проверить:
кто действует, что делает, в каких условиях, какая часть системы отвечает, что она делает и **чем это
измеряется**. Формат — шесть частей сценария по Bass, Clements, Kazman (SRC-047, гл. 3, §3.3);
выбор сценариев и приоритеты — по идее дерева полезности (SRC-047, гл. 19). Решение — ADR-0026.

**Как читать «Меру».** Числа, уже утверждённые автором (в `requirements.md`), даны как есть.
Числа с пометкой **[утвердить]** — предложение агента: пороги и методика решает человек (CLAUDE.md).
**Статус:** ✅ проверяется автоматически · 🟡 проверяется вручную или частично · ❌ сейчас не измеряется.

## Приоритеты

Строки — техническая сложность (риск не выполнить), столбцы — важность для цели системы и диссертации.

| Риск ↓ / Важность → | Н | С | В |
|---|---|---|---|
| **В** | | QAS-04 | **QAS-01**, **QAS-02**, QAS-07 |
| **С** | | QAS-03 | QAS-06 |
| **Н** | QAS-10 | QAS-05, QAS-11 | QAS-08, QAS-09 |

Почему так:
- **QAS-01, QAS-02** — суть работы (RQ-1) и доверие новичка: модель обучена на чтении экспертов,
  на речи начинающих её точность не измерена (SRC-002, `literature-review.md`).
- **QAS-07** — аудитория учится с нуля (`audience.md`); риск высокий, потому что проверить можно только на людях.
- **QAS-04** — сбой модели до 2026-10-17 не записывался; теперь пишется событие `recognition_failed`.
- **QAS-08, QAS-09** — важны для этики и воспроизводимости, но уже закрыты тестами (низкий риск).

## Сценарии

### QAS-01. Вердикт бота совпадает с оценкой преподавателя
| Часть | Значение |
|---|---|
| Источник | русскоязычный ученик-новичок |
| Стимул | присылает голосовое с чтением карточки книги |
| Окружение | пилот, настоящая модель Muaalem (не заглушка), CPU/mps |
| Артефакт | `infrastructure/asr/muaalem.py` → `domain/assessment.py` → `domain/policy.py` |
| Реакция | вердикт (`excellent` / `passed` / `failed`) и список ошибок |
| Мера | по разметке (`annotations`): precision, recall, F1 обнаружения ошибок; κ «бот — преподаватель» сравнивается с κ «преподаватель — преподаватель» (roadmap 1.4–1.5). Целевое значение — **[утвердить]** после первых размеченных попыток. Ориентиры из литературы: F1 базовых систем Iqra'Eval ≈ 0,40–0,44 (SRC-043) |

**Как проверяется:** `make report`, раздел «Точность проверки» (`src/muallim/research/metrics.py`):
precision, recall, F1, FAR, FRR, κ; доли меток — `analytics/sql/05_annotation_labels.sql`. Бутстрэп-ДИ
пока нет. Метрики и формулы — `docs/research/metrics-gqm.md`, цель G1.

### QAS-02. Верное чтение засчитывается
| Часть | Значение |
|---|---|
| Источник | чтец-эталон (Хусари, SRC-042) или учитель (FR-30) |
| Стимул | эталонная запись строки отправлена как голосовое |
| Окружение | настоящая модель |
| Артефакт | тот же конвейер, что в QAS-01 |
| Реакция | попытка засчитана, ошибок нет или они мелкие |
| Мера | доля эталонных записей с вердиктом `failed` — **≤ 5 % [утвердить]**. ASR ошибается на непривычном произношении (SRC-026), поэтому сначала нужно убедиться, что на эталоне ложных ошибок нет |

**Как проверяется:** вручную 2026-10-17: верный аят — 99–100, чужой текст — 40–67 (`research-log.md`).
Автоматический прогон эталонов через модель — кандидат на тест с маркером «нужна модель».

### QAS-03. Ответ на голосовое быстрый
| Часть | Значение |
|---|---|
| Источник | ученик |
| Стимул | голосовое до 60 с |
| Окружение | обычная работа, один сервер, CPU (или mps на Mac автора) |
| Артефакт | `application/use_cases/recitation.py` (распознавание и оценка) |
| Реакция | результат с ошибками показан ученику |
| Мера | `attempts.processing_ms`: 90 % попыток ≤ 10 с **[утвердить: в NFR-PERF-01 сказано «≤ 10 с», без процентиля]** |

**Граница измерения:** `processing_ms` считает только распознавание и оценку. Загрузка файла из
Telegram, ffmpeg и отрисовка картинки в него не входят, поэтому ученик ждёт дольше. Для диссертации это
нужно оговорить или измерять от получения сообщения до ответа.
**Как проверяется:** `make report`, раздел «Время ответа» — p50, p90, максимум. Первые данные (9 попыток, mps, 2026-10-17): p50 1,7 с, p90 5,0 с.

### QAS-04. Сбой модели не ломает урок и виден в данных
| Часть | Значение |
|---|---|
| Источник | внутренний сбой: модель не загрузилась, ошибка распознавания (`RecognitionError`) |
| Стимул | ученик прислал голосовое во время сбоя |
| Окружение | пилот |
| Артефакт | `presentation/telegram/handlers/voice.py` (обработка `RecognitionError`), `errors.py` (любой сбой), журнал `interaction_events` |
| Реакция | ученик видит понятную просьбу повторить, текущая карточка не меняется; сбой записан |
| Мера | 100 % сбоев дают сообщение ученику; 100 % сбоев попадают в журнал; доля сбоев за неделю видна в отчёте |

**Как проверяется:** событие `recognition_failed` (`item_id`, этап `decode` / `model`, `processing_ms`) —
`test_recognition_failure_is_logged_and_committed`, `test_recognition_failure_keeps_current_item`,
`test_broken_audio_fails_at_decode_stage`; доля сбоев — `make report`, раздел «Сбои распознавания».

### QAS-06. Плохая запись не оценивается
| Часть | Значение |
|---|---|
| Источник | ученик |
| Стимул | слишком короткое голосовое, тишина, запись длиннее 60 с, не голосовое |
| Окружение | обычная работа |
| Артефакт | `infrastructure/audio/ffmpeg.py`, обработчик голосовых |
| Реакция | попытка не оценивается и не портит прогресс; просьба прочитать ещё раз |
| Мера | 0 попыток в `attempts` по отклонённым записям; доля меток `audio_unusable` в разметке — ориентир, сколько плохих записей всё же проходит |

**Как проверяется:** ограничение 60 с — NFR-SEC-05; отказ на коротких — с v0.6.0 (CHANGELOG).

### QAS-07. Новичок сам доходит до первой засчитанной строки
| Часть | Значение |
|---|---|
| Источник | русскоязычный, впервые учит арабское чтение (`audience.md`) |
| Стимул | первый /start |
| Окружение | без инструкции и без помощи преподавателя |
| Артефакт | экраны `presentation/telegram/screens.py`, тексты `texts.py` |
| Реакция | ученик даёт согласие (или отказ), открывает урок, читает строку, получает объяснение |
| Мера | **≥ 4 из 5** новичков в первой сессии получают засчитанную попытку без помощи **[утвердить]**; время от `learner_registered` до первой попытки `passed` — медиана **[утвердить]** |

**Как проверяется:** юзабилити-тест в пилоте (сценарий — руководство ученика, план) + события
`interaction_events`. Метрика — G4 в `metrics-gqm.md`.

### QAS-09. Любую попытку можно пересчитать
| Часть | Значение |
|---|---|
| Источник | исследователь |
| Стимул | через месяц после пилота пересчитывает вердикт с другими порогами или моделью |
| Окружение | программа и код уже изменились |
| Артефакт | след решения в `attempts` (ADR-0019), снимок `curriculum_items` (ADR-0023), аудио по SHA-256 |
| Реакция | для попытки известны эталон, услышанное, пороги, версии модели, кода и программы, строка книги |
| Мера | 100 % попыток после миграции 0002 имеют `model_version`, `app_version`, `policy`, `curriculum_version`; хеш аудио совпадает |

**Как проверяется:** FR-24, FR-26, NFR-TR-03 (тесты в `traceability.md`).
**Ограничение сейчас:** проект не в git, поэтому `app_version` — только версия пакета, без хеша кода (TD-FN-27).
