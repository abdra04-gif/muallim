# Инструменты для Telegram-бота и распознавания: обзор 2026-10-18

Что есть готового для бота на aiogram 3, обработки голоса и работы агента — и что из этого
нужно проекту (продолжение — `docs/research/linters-hooks-agents.md`). Цифры звёзд и даты — GitHub API на 2026-10-18. Решения по зависимостям и методике
принимает человек; здесь — варианты. Выбранное в обвязке агента — ADR-0035.

## Главная находка: модель уже отдаёт больше, чем мы берём
`quran_muaalem.Muaalem` возвращает, кроме строки фонем (SRC-062):
- **уверенность** по каждой фонеме (`phonemes.probs`) и по каждому признаку;
- **сифат** — 10 признаков произношения на каждую группу фонем (`tafkheem_or_taqeeq`,
  `hams_or_jahr`, `qalqla`, `ghonna`, `itbaq`, `safeer`, …), каждый с вероятностью.

Адаптер (`infrastructure/asr/muaalem.py`, `_raw_output`) сохраняет это строкой `repr` тензора, а
оценка использует только фонемы. Следствия:
- без чисел уверенности не откалибровать третий исход «не уверен» (TD-FN-02) и не построить
  ROC-кривую для RQ-1 — **TD-FN-35, закрыть до пилота**: попытки без аудио задним числом не
  пересчитать;
- сифат — это ровно ошибки русскоговорящих (твёрдые/мягкие, ق/ك, ص/س, SRC-023, SRC-034):
  объяснение «звук слишком мягкий» точнее, чем «не та буква» — **TD-FN-36**, материал для дополнительного RQ-3 (разведка; бывшая H4.2 отложена, ADR-0064).

## Обзор
| Инструмент | Для чего в проекте | Итог |
|---|---|---|
| **Тестовая среда Telegram** (`aiogram.client.telegram.TEST`, SRC-061) | стенд перед пилотом: отдельные аккаунты и бот, настоящие ученики не затронуты | TD-FN-38 |
| **Context7 MCP** (upstash/context7, ★63k, MIT) | агент читает документацию aiogram 3, SQLAlchemy, alembic нужной версии, а не по памяти | подключён: `.mcp.json`, версия 4.1.1 |
| **chigwell/telegram-mcp** (★1,8k, Apache-2.0, Telethon) | агент сам пишет боту и шлёт голосовое — сквозная проверка настоящим клиентом | скачан в `external/` (внутри проекта, вне git — ADR-0063); только с отдельным тестовым аккаунтом — TD-FN-41 |
| **silero-vad** (snakers4, ★10k, MIT) | отсечь тишину и шум до модели (QAS-06), быстрый ответ «не слышно» | скачан; TD-FN-37 |
| **CTC forced alignment** (`torchaudio.functional.forced_align`; MahmoudAshraf97/ctc-forced-aligner, ★570, BSD-2) | время каждой фонемы → точная подсветка (TD-FN-17), нарезка эталонов | скачан; TD-FN-40 |
| **Healthchecks** (healthchecks/healthchecks, ★10k, BSD-3; или healthchecks.io) | узнать, что бот упал ночью | TD-FN-39 |
| Скилл `telegram-bot` (`.claude/skills/`) | лимиты Bot API и правила проекта под рукой у агентов | создан |
| Ограничение частоты голосовых (TD-SEC-12) | защита CPU от потока голосовых | в aiogram 3 нет готового; своя outer-middleware с окном в памяти (без Redis, ADR-0005) — через `/feature` |
| Локализация kk/en (TD-FN-08) | когда языки включат | `aiogram_i18n` / Fluent — рассмотреть тогда; сейчас ADR-0009 |

## Рассмотрено и отклонено
| Что | Почему нет |
|---|---|
| **Sentry** (облако) | отчёты об ошибках уходят на серверы вне РФ/РК вместе с контекстом — конфликт с локализацией и ПДн (TD-SEC-04); если понадобится — самохостинг (GlitchTip) |
| **Локальный Bot API server** (tdlib/telegram-bot-api) | снимает предел 20 МБ на скачивание, а голосовые — сотни КБ; замедление голосовых в РФ (TD-FN-04) не решает |
| **telegram-test-api** (npm-эмулятор) | хендлеры уже проверяются подачей update в Dispatcher (`tests/integration/test_bot_flow.py`), второй эмулятор не нужен |
| **aiogram-dialog** (★0,9k) | экраны уже построены (ADR-0024); переход — переписывание интерфейса без пользы для ученика |
| **aiogram_tests** (OCCASS) | не обновлялся с 2024; подход Dispatcher из документации aiogram надёжнее |
| Webhook вместо polling | ADR-0008 |

## Ограничения Bot API (SRC-060)
~1 сообщение в секунду в один чат, ~30 в секунду разным пользователям, 20 в минуту в группе;
скачивание файла до 20 МБ, отправка до 50 МБ. Подробнее — `.claude/skills/telegram-bot/SKILL.md`.
