# Линтеры, хуки и агенты для бота; разбор @recitobot: обзор 2026-10-18

Что ещё стоит добавить в обвязку агента и проверки кода, какие статьи это обосновывают, и что
интересного в работах и боте научрука (Н. Аскарбекулы, Иннополис). Здесь только варианты:
зависимости, тексты, методика и проверки — решения человека (CLAUDE.md). Принятое пойдёт в ADR,
отложенное уже записано в `docs/tech-debt.md` (TD-FN-54…TD-FN-67). **Что принято и сделано — ADR-0042.** Продолжение
`docs/research/bot-tooling.md`.

## Главный вывод
Обвязка проекта уже богаче, чем почти во всех исследованных репозиториях: 19 агентов (на момент обзора; с `bot-driver` — 20), 10 хуков,
mypy --strict, import-linter, gitleaks. Скиллы и субагенты встречаются редко (SRC-073), так что
новые агенты почти не нужны. Статьи 2026 года сходятся в одном: файлы контекста (CLAUDE.md,
AGENTS.md) почти не повышают корректность (SRC-074, SRC-077), иногда только экономят время
(SRC-075), а соблюдение правил падает внутри длинной сессии (SRC-076, OR = 0.944 на каждую новую
функцию). Статический анализ в цикле обратной связи заметно снижает число проблем (SRC-078).
Поэтому выгоднее всего **переводить прозаические правила в механические проверки** (принцип уже
есть в ADR-0012 и ADR-0028; теперь у него есть эмпирическое обоснование для главы 3).

## Агенты
- **Новый — только `bot-driver`**, и сначала нужна функция: CLI-режим `muallim --test "/start"`
  (подача апдейтов в Dispatcher, печать экранов в терминал, SRC-090). Это требование P0 из лабы 7
  научрука (SRC-072). Агент проходит бота без Telegram и без личного аккаунта (в отличие от TD-FN-41). TD-FN-61.
- **`asr-evaluator`: чеклист R1–R5** (SRC-067) вместо нового агента: отложенная выборка и разрыв
  train/test по каждому прогону; в отчётах об ошибках нет золотых ответов; свежий клон на прогон;
  аудит памяти и глобального конфига агента; компоненты метрики отдельно, гипотезы заранее
  (уже есть `docs/research/preregistration.md`). TD-FN-62.
- **`learner-simulator`: оговорка о валидности.** Симулированные ученики систематически
  расходятся с настоящими (SRC-083, SRC-085, SRC-084): его отчёт — подсказка, не замена пилоту и
  не данные для главы 4. TD-FN-62.

## Бот научрука @recitobot и связанные работы
**Что удалось установить.** Бот «Recite Quran» (SRC-071) — запуск Mini App, «запишите чтение и
получите обратную связь», контакт @asknur. @asknur — Нурсултан Аскарбекулы (GitHub `nurlingo`,
сайт NamazApp). Сам бот не открывался: нужен вход в Telegram, в личный аккаунт автора агент не
входил.

**Как устроена проверка** (SRC-067, SRC-069): бот проверяет **заучивание**: OpenAI ASR →
транскрипт без огласовок → какие аяты прочитаны и деление транскрипта по аятам. Решение,
построенное агентом (Codex, исследование 2), работает в продакшене **за feature flag с откатом на
старый пайплайн и регрессионным гейтом в CI** — приём для смены модели Muaalem (TD-SEC-14).

**Таксономия ошибок** (SRC-068): неисправленные ошибки (`substitution/omission/insertion_mistake`),
**самоисправления** (`*_corrected`) и безобидные события (`repetition`, `spelling`,
`basmala`, `isti3adha_benign`). Огласовки и таджвид авторы явно выносят за рамки, а это как раз
предмет этого проекта. Позиция для главы 1: научрук проверяет, **что** прочитано (заучивание),
этот проект — **как** прочитано (буквы и огласовки, новичок). Для разметки (ADR-0040): у новичков
частые самоисправления и повторы — стоит ли различать их в разметке, решает человек. TD-FN-63.

**Курс «thani»** (SRC-070): 77 уроков и 656 заданий по алфавитной части; порядок букв совпадает
с книгой (ا ر ز → م ت → ن ي → ب ك → ل و → ه ف → ق ش → س ث → ص ط → ج خ → ح غ → ع د → ض ذ → ظ).
Все задания тренируют **восприятие на слух**: `fill_it_up` (вставить огласовку),
`dictant_vowel` (диктант огласовки), `dictant_both` (диктант буквы и огласовки). Этот проект
тренирует **произношение**: сочетание поддержано HVPT (SRC-044, SRC-045). TD-FN-64.

**Напоминания** (SRC-070): дни 1, 2, 3, 5, 7, 10, 13, 16, 19, 26, 34, 41, 55, 69, 99, … — «сначала
часто, потом реже». Вместе с SRC-091 (бандит Duolingo) — основа для TD-FN-18.

**Освоение буквы** (SRC-098): учитывается раздельно по звуку и по написанию, на повторение
выбираются до 4 слабых букв. TD-FN-64.

**Звуки букв.** В открытых репозиториях научрука **записей звуков букв нет**: в `content/audio`
лежат суры, зикр и дуа; курсы `thani` и `joode` — только JSON и PDF, звук зашит в iOS-приложения.
У репозитория `content` нет лицензии. Взять звуки можно только у автора — с файлами и письменным
разрешением; добавление в `curriculum/audio/` делает человек (CLAUDE.md). TD-FN-65.

## Возможности Bot API без новых зависимостей (SRC-088)
aiogram 3.31 = Bot API 10.3. `sendMessageDraft` (9.3/9.5) — «слушаю… распознаю…», пока работает
модель; цвет кнопок (9.4) — верный/неверный ответ; rich messages с голосовыми (10.1–10.2) — эталон
«как правильно» внутри разбора ошибки; викторины с несколькими верными ответами (9.6). Это тексты
и интерфейс ученика — решения человека. TD-FN-66.

## Литература по предмету (для глав 1 и 4)
- Telegram-боты для произношения: контролируемые исследования старые и про канал, а не бота
  (SRC-092, 2017); свежих работ о Telegram-ботах с автоматической проверкой произношения не
  найдено — **пробел**, который закрывает эта работа.
- IqraEval.2 (Interspeech 2026): заявленное 1-е место — F1 0.7201 против базовой 0.4414 (SRC-086);
  сверить с итоговой таблицей SRC-031 перед цитированием.
- Набор данных научрука (SRC-097) — пример публикации обезличенных данных бота (roadmap 1.9).
