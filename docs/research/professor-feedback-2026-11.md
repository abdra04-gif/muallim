# План: замечания профессоров → бот «первая версия» + сайт-описание

## Context
Профессора (письмо 2026-11) сказали: описание в начале хорошее, дальше «слишком сложное планирование деталей»; хотят **увидеть первую версию** и потом править. Фокус — только **буквы и огласовки (28 пунктов)**, без кириллической транслитерации (только арабское письмо и звук), без AI-сгенерированных звука и картинок, путь — максимально лёгкий. Параллельно автор хочет: (а) сайт с подробным описанием и схемами, удобный для правки и для проверки в ChatGPT; (б) строить бота на новом обновлении Telegram (Widgets, Bot API 10.4 — заметки в `docs/research/telegram-widgets.md`).

Уровень по CLAUDE.md: **L** (новые экраны ученику, контент, методика). Контент, тексты ученику, методика, эталонные записи, новые зависимости — **только человек**: я готовлю черновики/предложения, не вписываю арабский и методику сам.

## 2. Сайт-описание (для автора и для проверки в ChatGPT)
Цель: одно место, где подробно описано и нарисовано: путь ученика, экраны, данные, этапы, замечания профессоров и как они учтены, Telegram Widgets, риски, открытые вопросы.
- **Источник правды — простые файлы** `docs/site/content/*.md|yaml` (разделы), легко править руками и через ChatGPT.
- **Сборка** `scripts/site/build.py` (stdlib + уже стоящий yaml) → `index.html` в `docs/site` → build (один файл, схемы — inline SVG; светлая/тёмная тема, телефонная вёрстка) **и** `spec-for-chatgpt.md` там же (всё в одном Markdown + готовый промпт «проверь как профессор/методист/разработчик»).
- Схемы: путь ученика (видео → картинка+аудио → попытка → разбор → прогресс/серия → веха), карта этапов I/II, макеты экранов уроков 1–3 (взять из `scripts/render_mockups.py` / `docs/design/mockups.html`, `make design`), архитектура виджетов.
- Публикация: ChatGPT не открывает приватные ссылки → отдаём **файл `spec-for-chatgpt.md` + `index.html` вручную**; ссылка-Artifact — по желанию автора. Персональных данных учеников на сайте нет.
- Цель `make site` в Makefile; тест, что сборка не падает и все ссылки внутри валидны.

## 3. Бот: «первая версия» (Этап I, уроки 1–3)
Путь ученика (каждый шаг — один экран, минимум кнопок):
1. Приветствие → «Урок 1» (буквы 1–3, из книги: порядок решает человек).
2. **Видео-урок ≤5 мин** (арабская речь + русские субтитры; запись человека).
3. **Картинка со словами** урока + **голосовое-эталон**.
4. Ученик шлёт **голосовое**.
5. **Разбор** текстом/картинкой (мягко, без «провала»).
6. Прогресс: «шаг 3 из 4» в уроке + общая полоса; по концу урока — поздравление + серия 🔥.
7. После уроков 1–3 → следующие буквы до **28/28**, затем **большая веха** и открытие Этапа II.
Повторное использование: `handlers/voice.py`, `handlers/video.py`, `render.py`, `GetProgress` (`application/use_cases/progress.py`), `ShareLesson`-открытка серии (`handlers/daily.py`), `reminders.py`, `lesson_links.yaml`, `videos.yaml`. Новый сценарий → регистрация в `bootstrap/di.py`.

### Виджеты (новое обновление)
Сначала бот **без виджетов** (чтобы показать профессорам первую версию быстро), потом виджеты как улучшение через порт `application/ports` + адаптер `infrastructure` (aiogram 3.31 не умеет `sendWidget`; ждём PR #2004 или свой `TelegramMethod`; новая зависимость — решает человек). Где виджет даёт пользу: **карта 28 букв (веха)**, прогресс урока, карточка слов; не годятся: запись голоса, аудио, видео. Обязательны подпись-фолбэк и тест на старом клиенте; только личный чат (прод-ограничение). Сначала тестовый сервер Telegram, песочница `widget-sandbox` в `external/`.

## 6. Проверка
- `uv run pytest -q` + `make check` (только по вашему слову, ADR-0075); `make try a='"/start" …'` — пройти путь урока 1–3; `learner-simulator` — читает тексты глазами новичка; `bot-driver` — тупики/кнопки.
- Сайт: `make site`, открыть `index.html` на телефонной ширине, отправить `spec-for-chatgpt.md` на проверку.
- Виджеты: тест-сервер Telegram, 3 платформы (iOS/Android/Desktop), светлая/тёмная тема, размер ≤4096 B (`zlib.compress(html, 9)`).
- Telegram вручную: личный чат, старый клиент (видна только подпись).
