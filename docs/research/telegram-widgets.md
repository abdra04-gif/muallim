## 1. Что это
Виджет — маленький интерактивный блок **внутри пузыря сообщения**. Один HTML-документ (inline CSS+JS), ≤ **32 768 байт** HTML и ≤ **4 096 байт после zlib-9** (те самые «4 КБ»). Работает в песочнице QuickJS на устройстве (не WebView), **без сети вообще**. Рисуется нативно, одинаково на iOS/Android/macOS/Desktop/web. Слой API 233; старые клиенты видят «неподдерживаемое медиа» + подпись.

**Не мини-апп:** нет своего сервера на странице, нет клавиатуры, нет ввода текста, нет fetch. Только тапы, pointer-события, горизонтальные драги.

## 2. Модель: код фиксирован, меняется состояние
- HTML **не меняется после отправки** (нет метода замены). Новая вёрстка = новое сообщение.
- Состояние пишет **только бот**: `chat_data` (на одно сообщение, ≤1024 байт) и `public_data` (общее, ≤1024 байт). Виджет читает `TelegramWidget.chatData/publicData`, слушает `chatDataChanged/publicDataChanged`, перерисовывается.
- Виджет сам состояние менять не может — шлёт боту **запрос** `TelegramWidget.request(data)` (1–64 байта) → боту прилетает апдейт `widget_query` → бот отвечает `answerWidgetQuery` (≤1024 байт, **в течение 15 с**) → промис в виджете резолвится.
- Статический виджет (всё в сообщении) vs shared (`is_shared`, один объект на сервере, как опрос; пересылки следуют его состоянию).
- `allow_queries` — без него запросов нет вообще.

## 3. Где работает сейчас (подводный камень №1)
| | Тестовый сервер | **Продакшн** |
|---|---|---|
| Личный чат с ботом, запросы, кошелёк | да | **да** |
| Пересылка | да | нет |
| Группы | да | нет |
| Inline-режим | да | нет |
Каналы — нигде. В проде виджеты автоматически с `protect_content` (не переслать, не скопировать; `copyMessage` отказывает). Сроков выхода групп/пересылки Telegram не объявил. Нам для личного тренажёра хватает личного чата.

## 4. Отправка и API
`sendWidget`: `chat_id`, `html`, `width`/`height` (якоря размера, 0 = авто), `public_data`, `chat_data`, `caption` (+`parse_mode`, `caption_entities`, `show_caption_above_media`), `allow_queries`, `is_shared`, `reply_markup` (инлайн-кнопки под виджетом работают), `protect_content`, `message_thread_id`, `reply_parameters` и обычные. Возвращает `Message` с полем `widget`.
Апдейты: `Update.widget_query` (из оригинала) и `Update.shared_widget_query` (из пересылки). **Если у бота `allowed_updates` — добавить оба.**
Поля `widget_query`: `id, from, chat, message_id, chat_instance, widget_id?, data, type?` (типы для кошелька). Запрос **не несёт состояния** — держим авторитетное состояние у себя (ключ: сообщение или `widget_id`), данные проверяем как `callback_data` (недоверенные).
`from` не подделать (Telegram аутентифицирует). Ключ «один голос на пользователя» = `(widget_id, from.id)`.

## 5. Лимиты (подводные камни)
- Запросы: **5 на 5 с на пользователя+бота**, один в полёте (`BUSY`), нужен **реальный тап** (вызов синхронно в обработчике клика; не из таймера/промиса/после `await`/`pointerdown`). Один тап = один вызов (делится с `openLink/openTelegramLink/copyText`).
- Фоновые запросы: только оригинал в личном чате, пока виден: один при появлении, потом ≤1 в 5 с. Первые строки скрипта могут сразу просить свежее.
- `editMessageWidgetData` считается за **отправленное сообщение** (лимиты рассылки); shared-виджет — ≤1 правка/с → копить правки, писать ≤1 раза в секунду.
- Ответ на запрос **обязателен** (даже при ошибке — коротким текстом), иначе у виджета `TIMEOUT`. Состояние ответом не меняется — отдельными вызовами edit; нужное сразу — клади в `result`.
- Правка без изменений даёт `Bad Request: message is not modified` — считать успешной, но на запрос всё равно ответить.
- Пузырь 200–600 px шириной (проектировать под 320), высота 50–600, лишнее **обрезается**, прокрутки внутри нет, `vh` не поддерживается.
- CPU 300 мс/с, одна задача ≤500 мс, память 8 МБ, ≤2000 DOM-узлов, ≤400 CSS-правил, ≤16 «тяжёлых» элементов (blur/filter/opacity<1), канвас ≤2048×2048 суммарно, 64 таймера, 4 КБ localStorage на сообщение. Превышение → «Widget stopped», два краша подряд → мёртв до перезапуска приложения. **QuickJS без JIT** — на старых телефонах медленно.
- Ошибки отправки: `INPUT_MEDIA_WIDGET_TOO_LARGE` (≤4096 сжатых — считать Python `zlib.compress(html, 9)`, Node и gzip врут на десятки байт), `..._HTML_INVALID` (NUL/не UTF-8), `..._DATA_TOO_LARGE` (1024 **байта**, не символа: кириллица 2 байта → ~512 букв), `WIDGET_QUERY_NOT_ALLOWED`, `FLOOD_WAIT_N`, `MESSAGE_ID_INVALID`, `QUERY_ID_INVALID`.

## 6. Что внутри виджета (профиль 1)
- Есть: div/p/h1–h6/списки/таблицы/details/button, `<canvas>` 2D, inline-SVG (без clipPath/mask/filter/SMIL), `<img>` только `data:` PNG/JPEG/GIF/WebP, flex/grid, градиенты, 2D-transform, transition/@keyframes, CSS-переменные, `@media` по ширине/`prefers-color-scheme`, ES2023, DOM, Intl, localStorage, `crypto.getRandomValues`.
- Нет: поля ввода (**ни одного**), fetch/XHR/WebSocket, `<script src>`, внешние шрифты/картинки, `<audio>/<video>`, `@font-face`, именованные шрифты (**только system-ui/serif/sans-serif/monospace/ui-***), WebGL, `alert`, клавиатура, wheel/scroll, `:has()`, `clip-path`, `text-shadow`, `oklch`, `@container`, вложенный CSS, `overflow:auto`.
- Тема: `--tg-theme-bg-color`, `--tg-theme-text-color`, `--tg-theme-button-color` и др.; `prefers-color-scheme` следует теме чата. Цвета не хардкодить.
- Жесты: тап — всегда виджету; вертикальный драг — всегда чату; удержание и горизонтальный драг — по `touch-action` (auto: меню/ответ чата; pan-y: драг виджету; none: всё виджету). Левые 20 px — зона системного «назад». Hover только с мышью.
- Время сообщения рисуется приложением в нижнем углу, если нет подписи под виджетом → отступ снизу `env(safe-area-inset-bottom)`; не класть кнопки под время.
- Выход наружу: `openLink` (https, ≤256, с подтверждением, не t.me), `openTelegramLink` (t.me, без подтверждения), `copyText` (1–256), haptic (ограничен), `setResizeAnchor` (есть не во всех клиентах: проверять `typeof`).
- Вне Telegram `window.TelegramWidget === undefined` — проверять.
- Виджет **не знает** свой `widget_id`; `viewer` (id, имя, username, premium) есть только там, где разрешены запросы.
- Жизненный цикл: виджет могут уничтожить и создать заново в любой момент → рисовать из состояния + localStorage, первый кадр синхронно.
- Доступность: aria-атрибуты ничего не делают → важное дублировать в подписи.

## 7. Кошелёк / платежи (TON)
Встроенный некастодиальный Gram Wallet, форматы TON Connect: `request(data,{wallet:true})` → бот отвечает транзакцией `{valid_until, messages:[{address, amount(нано-TON строкой), payload?, stateInit?}]}` → `wallet.sendTransaction(tx, data)` → бот получает `sent_transaction` (+`msg_hash`) → **проверять в блокчейне, не по хэшу**. `wallet == null` в части стран/старых клиентов. После `TIMEOUT` платёж мог пройти — не платить повторно. Для нас платежи **не нужны** (аудитория учится бесплатно; и это Stars/ТОН-юрисдикция — отдельное решение человека).

## 8. Безопасность и приватность
- Код и public_data виджета **публичны** (пересылки их несут) — **секретов не класть**; в группе chat_data видят все.
- Боту виджет сообщает только: кто тапнул (`from`), 64 байта данных, чат/сообщение; для пересылки — только `widget_id`. Фоновые запросы выдают, что чат открыт (приватность: для учеников это персональные данные — **решение человека**, ADR).
- Известные уязвимости в первые дни: исследователи (V12, davtur19) показали выполнение кода в Android-клиенте и в старых iOS 13.2 / Desktop 7.4.0 / macOS 13.1; Telegram исправил на сервере и в клиентах, Дуров (13.11) отрицает захват «просто от сообщения». Это сообщения прессы и соцсетей (Business Upturn; X-пост NebuSec — не проверено мной). **Вывод:** виджеты — молодая поверхность атаки; для пилота с учениками — только после обновлённых клиентов и без хранения секретов.
- QuickJS-песочница проверяется: у Telegram в репо 99 «атакующих» файлов (`corpus/`) и профиль-валидатор.

## 9. Поддержка в нашем стеке (проверено 2026-11-15)
- У нас **aiogram 3.31.0** (`pyproject.toml`), это последняя версия на PyPI; **`sendWidget` в ней нет**. Идёт PR aiogram #2004 «Added full support for Bot API 10.4» (открыт, не слит), issue #2006. Другие библиотеки тоже отстают (pyTelegramBotAPI #2653, grammY — через `api.raw`).
- Варианты: ждать aiogram 3.32+ / вызывать метод напрямую (`bot.session` + свой `TelegramMethod`, либо Pydantic-тип) / свой тонкий адаптер. Новая зависимость → **только человек**; по CLAUDE.md внешний вызов = порт в `application/ports` + адаптер в `infrastructure`.
- Наш тестовый режим `--test` (`make try`, BaseSession, ADR-0043/0045) не знает `sendWidget`: придётся дописать поддельный метод, иначе bot-driver не пройдёт экраны с виджетами.
- Список обработчиков `allowed_updates` в `bootstrap` надо дополнить `widget_query`/`shared_widget_query`.

## 10. Что виджеты дают нашему боту (первые мысли, не решение)
Хорошо ложится: **карточка буквы / слога** с огласовкой крупно, подсветка ошибки в слове, прогресс-полоска урока, мини-тренажёр «выбери вариант» (кнопки без ввода), таймер/метроном для ритма мадда, переключатель «показать перевод/транскрипцию» (details), «как правильно» с копированием. Запросы — это аналог callback-кнопок, т.е. логика остаётся у бота.
**Не ложится:** запись голоса (микрофона нет; голосовое по-прежнему шлёт ученик обычным сообщением), любой текстовый ввод, воспроизведение эталонной записи (нет `<audio>`), книжные страницы-картинки (`data:` ≤1024×1024 и 4 КБ сжатого — не вмещаются).
**Арабский:** шрифты только системные; рендер харакатов/шадды зависит от системного шрифта ОС — на разных устройствах может отличаться; обязательно проверить на iOS/Android/Desktop. Арабский в UTF-8 ~2 байта/символ и плохо сжимается — бюджет 4 КБ считать заранее. Размер шрифта — `em` от размера чата.

## 12. Расхождения источников (учтено)
