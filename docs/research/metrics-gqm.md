# Метрики исследования и пилота (GQM)

Зачем считается каждая цифра. Метод «цель → вопрос → метрика» (Goal/Question/Metric, SRC-048):
сначала цель, из неё — вопросы, на которые цель отвечает, и только потом — метрики и данные для них.
Метрика без цели сюда не попадает. Решение — ADR-0026. Цели по RQ (ADR-0064): **G1 — RQ-1** (надёжность
разметки и готовых моделей против учителей, в том числе по типу ошибки «чтение / произношение»),
**G7 — RQ-2** (agentic loop-engineering против базовых подходов), **G8 + G2 — RQ-3, дополнительный**
(G8 — оценка усвоения как инструмент, G2 — динамика освоения); гипотезы RQ-2 и RQ-3 — с руководителем,
прежние H2.1–H4.2 — в `preregistration.md` §7 (отложено);
G3 и G6 — описание (объяснения — разведка E-7, обвязка — раздел методики, OQ-13); планы — `docs/roadmap.md`.

**Шаблон цели (SRC-048):** *анализировать* объект *с целью* … *относительно* фокуса качества
*с точки зрения* кого *в контексте* чего.
**Пометка [утвердить]** — предложение агента; методику и пороги решает человек.
**Расчёт:** ✅ есть — SQL в `analytics/sql/` или `src/muallim/research/metrics.py` (оба — в `make report`) · ❌ нет (TD-FN-24) · — данных пока не собираем.

## Главная метрика пилота и контр-метрика

- **Главная (North Star) [утвердить]: строки книги, впервые засчитанные учениками за неделю.**
  Строка засчитана, когда лучший балл ученика по ней ≥ порога (`GradingPolicy.is_mastered`). Метрика
  отражает то, ради чего бот существует, — ученик продвигается по книге, — и растёт только от реальных
  попыток.
- **Контр-метрика: доля ложно засчитанных попыток** — засчитанные ботом попытки, которые по
  транскрипции разметчика не засчитываются (FAR вердикта). Главную метрику легко «накрутить», снизив порог; контр-метрика сразу это
  покажет. Вторая контр-метрика — доля оспоренных попыток («Бот ошибся», FR-23).

## G1. Надёжность разметки и согласие модели с учителем (RQ-1)
*Анализировать* автоматическую проверку чтения (Muaalem + `domain.assessment` + пороги) *с целью*
оценки *относительно* согласия с преподавателем *с точки зрения* исследователя *в контексте* пилота с
русскоязычными новичками по книге SRC-040.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q1.1 Насколько найденные ботом ошибки настоящие? | по каждой фонеме эталона (SRC-064): **precision** = TR / (TR + FR); TR — ошибку слышат и бот, и разметчик, FR — только бот; **верный диагноз** = доля TR, где бот услышал то же, что разметчик | `annotations.corrected_phonemes` + `attempts.heard_phonemes` | ✅ `research/metrics.py` |
| Q1.2 Сколько ошибок ученика бот пропускает? | **recall** = TR / (TR + FA); FA — ошибку слышит только разметчик; **F1**; FAR и FRR по фонемам | `annotations` | ✅ `research/metrics.py` |
| Q1.3 Совпадает ли итог «засчитано / нет»? | вердикт учителя — та же политика оценки, применённая к его транскрипции (с порогами из `attempts.policy`); **FAR** (засчитал ошибочное), **FRR** (не засчитал верное); **доля согласия с ботом** (`agree` / (`agree` + `fix`)) по разметчику и вердикту бота | `annotations` + `attempts.verdict` | ✅ `research/metrics.py`; `05` |
| Q1.4 Бот согласен с учителем так же, как учителя между собой? | **κ Коэна** «бот — учитель» против κ «учитель — учитель» по вердикту; **α Криппендорфа** «ошибка / верно» по каждой фонеме между разметчиками (SRC-065); размечают все попытки оба (решение 2026-10-18); 95 % ДИ бутстрэпом | `annotations` с двумя `annotator` | ✅ `research/metrics.py` (κ, α, 95 % ДИ кластерным бутстрэпом по ученикам) |
| Q1.5 Где бот ошибается чаще? | precision по типу ошибки, названному ботом; recall по типу ошибки по разметке; по букве (`expected`) | `annotations` + `attempts` | ✅ `research/metrics.py` — по типу и по звуку эталона (FR-55) |
| Q1.7 Согласны ли учителя в типе ошибки? (H1.1) | **κ Коэна** «учитель — учитель» по типу: чтение / произношение / не ясно; доли типов по частям книги | `annotations` с типом ошибки (TD-FN-76) | — поля нет |
| Q1.8 Различает ли модель тип ошибки? | κ «модель — учитель» по типу (тип ошибки модели — по правилу: замена огласовки/знака или похожей на вид буквы → чтение; замена по месту образования или признаку → произношение) | `detected_errors` + `annotations` | — |
| Q1.6 Совпадают ли жалобы учеников с разметкой? | доля оспоренных попыток, где разметчик поставил `fix` | `learner_reports` + `annotations` | 🟡 `07_learner_disputes.sql` — без разметки |

Разметчик видит ответ бота (решение автора 2026-10-18): precision и κ «бот — учитель» могут быть
завышены «согласием по подсказке» — угроза валидности (`preregistration.md`, §5).
Попытки с меткой `audio_unusable` и `off_task` исключаются из Q1.1–Q1.5 и считаются отдельно (сколько
таких записей проходит фильтр, QAS-06). Попытки с отметкой `self_corrected` хотя бы у одного
разметчика (ученик ошибся и тут же сам перечитал верно) тоже не входят в Q1.1–Q1.5 — у них свой
блок «Самоисправления»: precision, recall, F1 по фонемам (ADR-0044, разведка).

## G7. Agentic loop-engineering против базовых подходов (RQ-2, ADR-0064; до него — адаптация модели, ADR-0051)
*Анализировать* лучшую конфигурацию, которую agentic loop-engineering собирает из готовых моделей и
компонентов (среди них B1 — калиброванный верификатор с «не уверен», B2 — Muaalem + LoRA), и базовые подходы
(B0 — Muaalem как есть, лучшая отдельная готовая модель) *с целью* сравнения *относительно* согласия с
«золотой» разметкой двух учителей и сохранности на чтении экспертов *с точки зрения* исследователя *в контексте*
учеников, не участвовавших в подборе конфигураций.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q7.1 Меньше ли ложных отклонений у лучшей конфигурации? | FRR и recall вердикта: лучшая конфигурация vs базовые подходы, парный бутстрэп по ученикам (гипотеза — с руководителем) | тест: «золото» + выходы B0, B1 | ❌ |
| Q7.2 Лучше ли лучшая конфигурация находит ошибки? | precision, recall, F1 по фонемам: лучшая конфигурация vs базовые подходы (гипотеза — с руководителем) | тест: «золото» + выходы B0, B2 | ❌ (метрики — `research/metrics.py`, сравнение систем — нет) |
| Q7.3 Не разучилась ли дообученная модель (если она в конфигурации)? | PER на отложенном наборе экспертов | Хусари + тест Muaalem | ❌ |
| Q7.4 Сколько разрыва с учителем закрыто? | (κ_B − κ_B0) / (κ_учитель-учитель − κ_B0) | тест | ❌ |
| Q7.5 Можно ли верить уверенности? | ECE до и после калибровки (SRC-112); кривая «риск — покрытие», доля «не уверен» при ε = 5 % (SRC-117) | тест | ❌ |
| Q7.6 Как модель учится с ростом данных? | **кривая обучения**: F1 и FRR лучшей конфигурации при 25 / 50 / 75 / 100 % обучающих учеников (обязательный отчёт RQ-2); журнал всех опробованных конфигураций | обучающая часть + тест | ❌ |
| Q7.7 Что даёт каждый источник данных? | F1 B2: только поправки учителей; + минимальные пары книги; + оспаривания учеников «бот ошибся» (ADR-0020) — обязательный отчёт RQ-2 | то же | ❌ |
| Q7.8 Сколько работы снимается с учителя? | доля попыток, которые система решает сама при риске ≤ ε (остальные — «не уверен», учителю) | тест | ❌ |

## G8. Оценка усвоения по речи — инструмент для RQ-3 (ADR-0064; до него — отдельный RQ-3, ADR-0052)
*Анализировать* модели усвоения K0 (доля верных попыток), K1 (BKT, SRC-124) и K2 (BKT с учётом измеренного
шума распознавателя, развитие SRC-125) поверх B0 и лучшей конфигурации agentic loop *с целью* сравнения
*относительно* точности предсказания и согласия с учителем *с точки зрения* исследователя *в контексте*
тестовых учеников, не участвовавших в обучении.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q8.1 Предсказывает ли модель следующую попытку? (бывшие H3.1, H3.2 — отложены) | **AUC** предсказания «золотого» исхода следующей попытки по навыку; логарифмическая потеря; ECE (SRC-126) | тест: «золото» + выходы B0/B1/B2 + карта навыков | ❌ (TD-FN-78) |
| Q8.2 Совпадает ли оценка усвоения с учителем? (бывшая H3.3 — отложена; согласие сообщается как проверка инструмента) | **ρ Спирмена** «оценка K2 — тест учителя вслепую» по парам «ученик × группа навыков» | тест учителя (TD-FN-77) | ❌ |
| Q8.3 Улучшает ли адаптация ИИ оценку усвоения? | разница AUC и ρ: K2 на адаптированной модели − K2 на B0 | то же | ❌ |
| Q8.4 Верно ли выбраны навыки? | качество подгонки AFM с картой навыков книги против карты «одна буква — один навык» (SRC-128) | обучающая часть | ❌ |

Параметры K1/K2 и FAR/FRR для K2 оцениваются только на обучающих учениках; строки теста учителя в
обучение не входят (`preregistration.md` §2).

Правила (SRC-067, SRC-121, SRC-122): разбиение по ученикам, тестовые ученики заморожены SHA-256 до обучения,
гиперпараметры — CV внутри обучающей части, тест открывается один раз.

## Сколько данных нужно [утвердить]
- **G1:** решение о целевых значениях — после первых ≈ 100 размеченных попыток; для κ — двойная
  разметка каждой 10-й попытки (roadmap 1.4).
- **G1 (H1.1):** тип ошибки обоими учителями — на всех тестовых попытках и каждой 10-й обучающей.
- **G8:** у каждого тестового ученика ≥ 5 попыток по навыку хотя бы для половины навыков с. 10–24
