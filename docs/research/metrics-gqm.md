# Метрики исследования и пилота (GQM)

Зачем считается каждая цифра. Метод «цель → вопрос → метрика» (Goal/Question/Metric, SRC-048):
сначала цель, из неё — вопросы, на которые цель отвечает, и только потом — метрики и данные для них.
Метрика без цели сюда не попадает. Решение — ADR-0026. Цели G1–G3 — это RQ-1…RQ-3
(`literature-review.md`), планы эксперимента — `docs/roadmap.md` (1.4–1.8).

**Шаблон цели (SRC-048):** *анализировать* объект *с целью* … *относительно* фокуса качества
*с точки зрения* кого *в контексте* чего.
**Пометка [утвердить]** — предложение агента; методику и пороги решает человек.
**Расчёт:** ✅ есть — SQL в `analytics/sql/` или `src/muallim/research/metrics.py` (оба — в `make report`) · ❌ нет (TD-FN-24) · — данных пока не собираем.

## Главная метрика пилота и контр-метрика

- **Главная (North Star) [утвердить]: строки книги, впервые засчитанные учениками за неделю.**
  Строка засчитана, когда лучший балл ученика по ней ≥ порога (`GradingPolicy.is_mastered`). Метрика
  отражает то, ради чего бот существует, — ученик продвигается по книге, — и растёт только от реальных
  попыток.
- **Контр-метрика: доля ложно засчитанных попыток** — засчитанные ботом попытки, которые по
  транскрипции разметчика не засчитываются (FAR вердикта). Главную метрику легко «накрутить», снизив порог; контр-метрика сразу это
  покажет. Вторая контр-метрика — доля оспоренных попыток («Бот ошибся», FR-23).

## G1. Согласие проверки с преподавателем (RQ-1)
*Анализировать* автоматическую проверку чтения (Muaalem + `domain.assessment` + пороги) *с целью*
оценки *относительно* согласия с преподавателем *с точки зрения* исследователя *в контексте* пилота с
русскоязычными новичками по книге SRC-040.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q1.1 Насколько найденные ботом ошибки настоящие? | по каждой фонеме эталона (SRC-064): **precision** = TR / (TR + FR); TR — ошибку слышат и бот, и разметчик, FR — только бот; **верный диагноз** = доля TR, где бот услышал то же, что разметчик | `annotations.corrected_phonemes` + `attempts.heard_phonemes` | ✅ `research/metrics.py` |
| Q1.2 Сколько ошибок ученика бот пропускает? | **recall** = TR / (TR + FA); FA — ошибку слышит только разметчик; **F1**; FAR и FRR по фонемам | `annotations` | ✅ `research/metrics.py` |
| Q1.3 Совпадает ли итог «засчитано / нет»? | вердикт учителя — та же политика оценки, применённая к его транскрипции (с порогами из `attempts.policy`); **FAR** (засчитал ошибочное), **FRR** (не засчитал верное); **доля согласия с ботом** (`agree` / (`agree` + `fix`)) по разметчику и вердикту бота | `annotations` + `attempts.verdict` | ✅ `research/metrics.py`; `05` |
| Q1.4 Бот согласен с учителем так же, как учителя между собой? | **κ Коэна** «бот — учитель» против κ «учитель — учитель» по вердикту; **α Криппендорфа** «ошибка / верно» по каждой фонеме между разметчиками (SRC-065); размечают все попытки оба (решение 2026-10-18); 95 % ДИ бутстрэпом | `annotations` с двумя `annotator` | ✅ `research/metrics.py` (κ, α; бутстрэп-ДИ — нет) |
| Q1.5 Где бот ошибается чаще? | precision по типу ошибки, названному ботом; recall по типу ошибки по разметке; по букве (`expected`) | `annotations` + `attempts` | 🟡 `research/metrics.py` — по типу; по букве — нет |
| Q1.6 Совпадают ли жалобы учеников с разметкой? | доля оспоренных попыток, где разметчик поставил `fix` | `learner_reports` + `annotations` | 🟡 `07_learner_disputes.sql` — без разметки |

Разметчик видит ответ бота (решение автора 2026-10-18): precision и κ «бот — учитель» могут быть
завышены «согласием по подсказке» — угроза валидности (`preregistration.md`, §5).
Попытки с меткой `audio_unusable` и `off_task` исключаются из Q1.1–Q1.5 и считаются отдельно (сколько
таких записей проходит фильтр, QAS-06).

## G2. Какие ошибки делают новички (RQ-2)
*Анализировать* ошибки чтения *с целью* описания *относительно* букв, огласовок и строк книги
*с точки зрения* преподавателя и исследователя *в контексте* русскоязычных начинающих.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q2.1 Какие типы ошибок чаще? | частота `kind` | `detected_errors` | ✅ `03_error_kinds.sql` |
| Q2.2 Какие буквы с чем путают? | матрица путаниц `expected → heard` | `detected_errors` | ✅ `04_letter_confusions.sql`, `10_errors_by_letter.sql` |
| Q2.3 Какие строки и пары книги трудные? | средний балл, доля засчитанных, число ошибок по странице и строке; пары «Обратите внимание» | `v_attempts`, `curriculum_items` | ✅ `02`, `08`, `09` |
| Q2.4 Это ошибки учеников или ошибки модели? | те же частоты **только по подтверждённым** разметкой ошибкам (TR) | + `annotations` | ❌ |
| Q2.5 Ошибка общая или одного ученика? | число учеников с ошибкой; доля, которую даёт самый активный ученик | `detected_errors` + `attempts` | 🟡 `10_errors_by_letter.sql` — число учеников есть |

Q2.4 важен для честности: без него отчёты 03–04 описывают смесь ошибок учеников и ошибок модели.

## G3. Помогают ли объяснения (RQ-3)
*Анализировать* объяснения ошибок по-русски *с целью* оценки эффекта *относительно* следующей попытки
*с точки зрения* исследователя *в контексте* самостоятельных занятий с ботом.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q3.1 Лучше ли следующая попытка после объяснения? | Δ балла между попыткой n (`failed`) и n + 1 того же ученика по той же карточке | `attempts` по `learner_id`, `item_id`, `created_at` | ❌ |
| Q3.2 Исправлена ли именно названная ошибка? | доля ошибок, которые на следующей попытке не повторились в той же позиции | `detected_errors` двух попыток | ❌ |
| Q3.3 Помогает ли эталон «как правильно»? | Δ балла для повторов с `reference_played` между попытками и без | `interaction_events` + `attempts` | ❌ |
| Q3.4 Держится ли эффект? | балл по карточке через 1–2 недели (отложенный тест, roadmap 1.7) | `attempts` | — |

**Угроза валидности:** без контрольного условия рост балла при повторе — это и объяснение, и просто
второй раз. Поэтому в roadmap 1.7 — внутрисубъектный эксперимент: полное объяснение против
«верно / неверно» на случайной половине карточек. До него Q3.1–Q3.3 — только описательные.

## G4. Вовлечённость и путь новичка (пилот)
*Анализировать* использование бота *с целью* улучшения *относительно* того, доходят ли новички до
результата и возвращаются ли, *с точки зрения* автора *в контексте* закрытого пилота.

| Вопрос | Метрика | Данные | Расчёт |
|---|---|---|---|
| Q4.1 Доходит ли новичок до первого успеха сам? | доля учеников с попыткой `passed` в день регистрации; медиана времени от `learner_registered` до первой `passed` (QAS-07) | `interaction_events`, `attempts` | ❌ |
| Q4.2 Возвращаются ли? | доля вернувшихся на 2-й и на 7-й день; серия дней (FR-35) | `attempts.created_at` | ✅ `research/metrics.py` (другой день; ≥ 7 дней в когорте) |
| Q4.3 Где бросают? | последний урок ученика, который не заходил 7 дней; распределение по урокам | `learners.current_item_id`, `attempts` | ❌ |
| Q4.4 Двигаются ли по книге? | **главная метрика**: строки, впервые засчитанные за неделю | `attempts` | ❌ |
| Q4.5 Сколько попыток уходит на строку? | медиана попыток до первой засчитанной по уроку | `attempts` | ❌ |

## Сколько данных нужно [утвердить]
- **G1:** решение о целевых значениях — после первых ≈ 100 размеченных попыток; для κ — двойная
  разметка каждой 10-й попытки (roadmap 1.4).
- **G3:** пары «неудачная попытка → повтор» не меньше чем от 10 учеников, чтобы эффект не давал один человек.
- **G4:** закрытый пилот — описательная статистика, без проверки гипотез.
