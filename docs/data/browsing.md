# Как смотреть данные: ответы, ошибки, отчёты, резервные копии

Всё ниже работает с PostgreSQL в Docker (`make db-up`). Telegram ID в представлениях и выгрузках
нет — только псевдоним `L-xxxx`. Попытки-заглушки (`model_version = 'stub'`) в отчётах не считаются.

## 1. Быстро — командами
| Что | Команда |
|---|---|
| Сводный отчёт (10 разделов) | `make report` → `analytics/reports/report_<дата>.md` |
| Ошибки на букве ص | `make errors a="--letter ص"` |
| Что путают с ص (слышится س) | `make errors a="--letter ص --heard س"` |
| Ошибки урока / строки книги | `make errors a="--lesson L18"` · `make errors a="--page 18 --line 8"` |
| Только пары «Обратите внимание» | `make errors a="--pairs"` |
| Ошибки одного ученика | `make errors a="--learner L-7f3a9c"` |
| За период | `make errors a="--since 2026-11-01 --until 2026-12-01"` |
| Ещё не размечены / оспорены / с записью | `--unannotated` · `--disputed` · `--with-audio` |
| Все фильтры | `uv run muallim-research errors --help` |

Каждый вызов сохраняет CSV в `data/errors/errors_<дата>.csv` (открывается в Excel/LibreOffice).
Колонка `audio_path` — путь к записи: открыть и прослушать.

## 2. Удобно — в DBeaver (бесплатно, с фильтрами и сортировкой как в Excel)
1. Установить: <https://dbeaver.io/download/> (Community).
2. «Новое подключение» → PostgreSQL:
   - Host `localhost`, Port `5432`, Database `muallim`, User **`muallim_reader`** — вход только для
     чтения: ничего не изменить даже случайно, Telegram ID не виден (ADR-0054);
   - пароль — строка `READER_DB_PASSWORD` в файле `.env` (открыть самому, агенту файл не читать).
     Нет такой строки — один раз выполните `make db-roles`.
3. Схема `public` → **Views**:
   - `v_errors` — каждая ошибка: ученик, урок, страница/строка книги, текст строки, что ожидалось,
     что услышано, балл, последняя разметка попытки;
   - `v_attempts` — каждая попытка: балл, вердикт, число ошибок, оспорена ли, есть ли запись.
4. Фильтр — поле над таблицей, например `expected = 'ص' AND page = 18`; сортировка — клик по колонке.
5. Таблицы (`attempts`, `detected_errors`, `annotations`, …) **не редактировать руками** — разметка
   идёт через `muallim-research annotation-export/import` (`docs/data/annotation-guide.md`).

**То же в VS Code** (расширение «PostgreSQL» от Microsoft, `ms-ossdata.vscode-pgsql`): подключение
«muallim (просмотр)» уже прописано в `.vscode/settings.json` — тот же вход `muallim_reader`.
Значок слона слева → подключение → пароль `READER_DB_PASSWORD` из `.env` (сохранится в связке
ключей macOS, не в репозитории) → `muallim` → Schemas → `public` → Views. Свой запрос — правой
кнопкой по базе `muallim` (не по подключению) → «Создать запрос», запуск — Shift+Enter. Готовые
запросы — в личном `.vscode/queries.sql`; как писать свои — `docs/data/sql-guide.md`.

Консоль без программ: `make db-shell`, потом например
`SELECT expected, heard, COUNT(*) FROM v_errors GROUP BY 1, 2 ORDER BY 3 DESC;` (выход — `\q`).

## 4. Путь данных до обучения модели
1. Бот пишет попытки и ошибки (`attempts`, `detected_errors`) — каждая со ссылкой на строку книги.
2. `muallim-research annotation-export --annotator A1` → папка разметчика (`tasks.csv` + записи; виден
   ответ бота) → разметчик ставит `agree` / `fix` → `annotation-import` (таблица `annotations`).
   Размечают оба разметчика; правила — `docs/data/annotation-guide.md`.
3. `make report` / `make errors` — частые ошибки, трудные строки, ошибки модели.
4. `muallim-research dataset-export` → `data/exports/<дата>/manifest.jsonl` (разметка каждого и
   согласованная) + `truth.csv` / `predictions.csv` для `mdd_eval` Iqra'Eval + аудио — только ученики
   с согласием, только настоящая модель. Это вход для дообучения и оценки модели.
5. `phonemes.csv` в той же папке — **где именно и как ошиблась модель** (ADR-0056): строка на каждый
   звук эталона для каждого разметчика — `expected` (по книге), `model_heard`, `human_heard` и
   `outcome`:

   | `outcome` | что значит |
   |---|---|
   | `correct_accept` | прочитано верно, модель согласна |
   | `false_rejection` | **ложная тревога**: ученик прав, модель решила, что ошибка |
   | `false_accept` | **пропуск**: ученик ошибся, модель не заметила |
   | `true_rejection` | ошибку нашла; `same_diagnosis` = `false` — нашла, но услышала не то |

   `agrees_with_consensus` — совпал ли этот разметчик с согласованной разметкой; `self_corrected` —
   ученик ошибся и сам перечитал верно (по попытке); `comparison_version` — версия правила сравнения.
   Считается тем же правилом, что TA/FR/FA/TR в `make report`; сумма файла совпадает с отчётом после
   тех же фильтров: в файле только ученики с согласием, а главные цифры отчёта — без
   `self_corrected = true`.
   Как читать `*_heard`: где ошибки нет — стоит эталон (калькаля при остановке — не ошибка, её здесь
   не видно); вставка показана перед звуком, в конце строки — после последнего; замена нескольких
   звуков сразу — весь услышанный фрагмент у каждого заменённого звука.

## 5. Резервные копии
- `make backup` → `data/backups/<дата>/db.dump` (вся БД) + `audio.tar.gz` (голосовые) + `erasures.jsonl` (журнал удалений) + `SHA256SUMS`;
  архив проверяется, права только владельцу; при сбое — папка `<дата>-FAILED` и ошибка.
- `make migrate` сначала делает копию **только БД** (полсекунды на 50 000 попыток; записи миграция
  не трогает) и применяет миграции входом владельца схемы `muallim_owner`.
- Журнал удалений (`data/erasures/erasures.jsonl`) — вне БД: копия его сохраняет, а восстановление
  объединяет журнал копии с текущим и сразу повторяет (`muallim-research reapply-erasures`) — ученики, удалившие данные
  после копии, не вернутся.
- Восстановить: `make restore d=data/backups/<дата>` — сверит SHA-256, спросит «да», сделает копию
  текущего состояния, восстановит одной транзакцией и повторит журнал удалений. **Перезапишет** данные.
- `make restore`, `scripts/db/restore.sh` и `verify --delete-orphans` агенту запрещены хуком
  `guard.py` — их запускает только человек.
- Сверка БД и файлов: `make verify` — потерянные, лишние, повреждённые записи, записи без согласия,
  копии в пакетах разметки и выгрузках, которые больше нельзя хранить.
- Копии содержат голоса и псевдонимы: хранить на зашифрованном диске, не в облаке без шифрования,
  не в git (TD-SEC-17). Делать копию перед каждой миграцией и раз в неделю во время пилота.

## 6. Если что-то не так
- Бот не стартует с «Программа … изменилась без смены version» — правили `curriculum/course.ru.yaml`,
  но не увеличили `version`. Увеличьте — старые попытки останутся связаны со старым текстом.
- Пустые `page`/`line` в представлениях — попытки, сделанные до появления снимка программы (их нет).
