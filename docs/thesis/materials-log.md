## 2026-10-18 · правила — в проверки (ADR-0042)
- **Гл. 3, пример.** Хук сверки текстов анкеты не видел словари (`NAME = {…}`): перепутанные ответы «русский ↔
  казахский» прошли бы без новой версии анкеты. Найдено тестом, написанным до кода (TDD), — довод за проверку самих проверок.
- **Гл. 3, пример ложного срабатывания.** vulture счёл провайдер dishka `learner_and_flag` мёртвым кодом: инструмент без
  знания фреймворка ошибается; узкий тест проекта («каждый текст используется») точнее.
- **Гл. 3.** Перенос текста — не изменение: версия анкеты поднимается только при новых словах или перестановке ответов,
  иначе в данных появилась бы ложная граница «до/после».

## 2026-10-18 · проверка библиотек и ревьюер направления
- **Гл. 3 (методика).** Риск «выдуманных пакетов» (slopsquatting) при агентной разработке закрыт проверкой средой,
  а не правилом: хук `dep_check` (ADR-0046) блокирует пакет, которого нет на PyPI. Аудит: 27/27 пакетов настоящие;
  найдено, что `pip-audit` в CI не видит extra `ml` — уязвимости `transformers` (TD-SEC-23). Пример для главы:
  проверка, которая «зелёная», может просто не видеть часть зависимостей.
- **Гл. 3.** Ревьюер направления (ADR-0047): отдельная роль «то ли сделано» и правило «нет доказательства — вопрос,
  а не находка». Метрика вмешательства человека: доля вердиктов СТОП на изменение.
