# Git: коммиты, push, что нельзя в репозиторий

Репозиторий — приватный `https://github.com/abdra04-gif/muallim`, ветка `main` (ADR-0037).
Коммит и push делаются командой `/ship` (ADR-0039); человек подтверждает каждый.

## Сообщение коммита
```
<тип>(<область>): <что изменилось — словами ученика или исследователя>

<зачем и что важно знать>

Refs: FR-…, ADR-…, TD-…
```
| Тип | Когда |
|---|---|
| `feat` | ученик или исследователь видит новое |
| `fix` | исправлена ошибка |
| `research` | метрики, отчёты, разметка, предрегистрация |
| `data` | схема БД, миграции |
| `thesis` | текст диссертации (`thesis/`) |
| `docs` | документация проекта |
| `harness` | агенты, хуки, команды Claude Code |
| `test`, `refactor`, `chore` | тесты; перестройка без изменения поведения; прочее |

Строка `Refs:` связывает коммит с требованием и решением: `git log --grep FR-44` находит всю
историю требования. Один коммит — один смысл; несвязанное — разными коммитами.

## Что никогда не попадает в git
`.env` (кроме `.env.example`), `/data/` (голоса, БД, выгрузки), `*.sqlite3`, `*.db`, дампы,
`book/*.pdf` (скан, «все права защищены»), `analytics/reports/*.md` (псевдонимы). Это держат:
1. `.gitignore` — правила от корня (`/data/`, а не `data/`: иначе пропадает `docs/data/`);
2. хук `doc_sync` — файлы проекта, которые `.gitignore` прячет по ошибке;
3. хук `git_guard` — запрещённые пути в коммите, `git add -f`, gitleaks;
4. pre-commit — gitleaks, приватные ключи, большие файлы; CI — gitleaks ещё раз.

## Проверки
| Когда | Что | Кто |
|---|---|---|
| каждое завершение ответа агента | архитектура, типы, тесты (если менялся код); связанные документы | `stop_gate`, `doc_sync` |
| перед коммитом | запрещённые пути, секреты | `git_guard`, pre-commit |
| перед push | быстрая: слои, ruff и тесты изменённых файлов; правки кода бота — сначала вопрос автору, полная (`CHECK=full`) только по его «да» (ADR-0075) | `git_guard` |
| после push, если менялся код (`src/`, `tests/`, миграции, программа, зависимости) | всё, как `make check`, + gitleaks, pip-audit, `make hygiene` | GitHub Actions (`.github/workflows/ci.yml`) |
| перед коммитом, смысл | документы правдивы, ничего не потеряно | агент `consistency-auditor` в `/ship` |

## Параллельные сессии (ADR-0073)
Одна сессия Claude работает в основной папке. Каждая следующая, которая что-то меняет, работает
в своей копии `.claude/worktrees/<имя>`: там своя ветка `worktree-<имя>`, свои файлы, свои тесты
и своя фаза TDD.
- **Кто где.** Хук `session_lock` ставит метку при первой правке в основной папке. Вторая сессия
  при старте получает строку «перейди в копию», а при попытке правки или git-записи — блок.
  Чтение не блокируется. Метка снимается при выходе или через 30 минут без действий.
- **Переход** — инструмент `EnterWorktree`. `.env` копируется сам (`.worktreeinclude`),
  окружение `uv run` создаёт при первом запуске. Копия начинается от `origin/main`.
- **Хуки** проверяют копию сессии, а не основную папку (`_common.ROOT` по `cwd` события).
- **Слияние** — `/ship` в копии: коммит в ветку → `git fetch` → `git rebase origin/main` →
  проверки (ADR-0075) → `git push origin HEAD:main`. Журналы и CHANGELOG склеиваются без конфликтов
  (`.gitattributes`, `merge=union`). Два ADR с одним номером ловит `doc_sync`.
- **Общее, чего в копии нет:** бот с настоящим токеном (`make run`), миграции и база — только
  в основной сессии. В копии бот проверяется через `make try`.

## Как найти, откуда что взялось
- `git log --oneline -- <файл>` — история файла; `git log --grep ADR-0038` — по решению.
- `git blame <файл>` — кто и каким коммитом изменил строку.
- Отпечаток версии в отчётах и рисунках — `make trace` (`verification-status.md`).
