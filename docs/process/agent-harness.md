# Цикл ИИ-агентов (agent harness loop)

Идея научного руководителя — «autonomous agent loops / AI harness loop» — реализована так, чтобы
агент работал долго и самостоятельно, но **не мог** нарушить ключевые правила (ADR-0012).

## Четыре слоя
| Слой | Что | Где |
|---|---|---|
| Контекст | что агент должен знать | `CLAUDE.md`, `docs/adr/`, `docs/requirements/` |
| Принуждение | что агент не может обойти | хуки `.claude/hooks/` (их выполняет среда, а не модель) |
| Роли | изолированные субагенты с узкой задачей | `.claude/agents/` |
| Человек | решения, которые нельзя делегировать | `CLAUDE.md` → «Только человек» |

## Хуки
| Хук | Событие | Что делает |
|---|---|---|
| `log_prompt.py` | UserPromptSubmit | сохраняет каждый запрос человека в `docs/journal/prompts/ГГГГ-ММ.md` (секреты маскируются) |
| `guard.py` | PreToolUse | запрещает: читать `.env`, `data/`, дампы БД; менять `tests/` в фазе impl; менять `.agent-phase` напрямую; `--no-verify`, `push --force`, `rm -rf` |
| `format_python.py` | PostToolUse | `ruff format` + `ruff check --fix` для изменённого .py, остатки ошибок — агенту |
| `stop_gate.py` | Stop | если код изменён и не проходят `lint-imports`/`mypy`/`pytest` — агент не может закончить, получает ошибки и продолжает (это и есть «петля») |
| `human_zones.py` | PreToolUse | правка зоны человека (учебный контент, тексты ученику, пороги, `MOSHAF_PARAMS`, схема БД, зависимости, сами проверки, оценщик RQ-1 `src/muallim/research/metrics.py` — ADR-0042) и `pip/uv add` — только с подтверждения человека, с причиной (ADR-0034) |
| `dep_check.py` | PreToolUse | новая библиотека (`uv add`, `pip install`, строка в `pyproject.toml`): нет на PyPI — блок; есть — карточка (версия, возраст, репозиторий, уязвимости OSV, похожее имя) в запросе подтверждения (ADR-0046) |
| `stub_notice.py` | PostToolUse | бот запущен с заглушкой → агенту напоминание сказать об этом человеку |
| `session_context.py` | SessionStart | в контекст: TDD-фаза, установлена ли модель, открытый техдолг T1, последняя сводка сессии |
| `notify.py` | Notification | уведомление macOS, когда агент ждёт человека |
| `doc_sync.py` | Stop | изменили одно — обнови связанное: CHANGELOG, словарь данных и миграция, reports.md, этот файл, перерисованные схемы, версия текста согласия/анкеты (дословный перенос текста версию не поднимает, ADR-0042), трассировка новых FR; файлы проекта, скрытые `.gitignore` (ADR-0039) |
| `git_guard.py` | PreToolUse | `git add -f` запрещён; коммит — без запрещённых путей и секретов (gitleaks), `add` и `commit` раздельно; push — только при зелёных архитектуре, типах и тестах (ADR-0039) |

Каждая блокировка и каждый запрос подтверждения пишутся в `docs/journal/hooks/ГГГГ-ММ.jsonl`
(время, хук, причина — первая строка, без команд и данных): это данные для Q6.1 в
`docs/research/metrics-gqm.md`. `guard.py` работает по принципу fail-closed: если он сам упал,
действие запрещается (TD-SEC-13).

## Субагенты
| Агент | Задача | Может менять |
|---|---|---|
| `tdd-test-writer` | падающие тесты по требованию | только `tests/` |
| `implementer` | код до зелёных тестов | `src/`, `migrations/` |
| `architecture-guardian` | ревью diff по ADR и слоям | ничего (только отчёт) |
| `security-auditor` | ревью по модели угроз | ничего |
| `data-analyst` | SQL-отчёты, анализ | `analytics/` |
| `pedagogy-reviewer` | проверка учебного контента и методики | ничего (только предложения) |
| `thesis-scribe` | CHANGELOG, ADR, журнал, материалы диплома | `docs/`, `CHANGELOG.md` |
| `asr-evaluator` | протокол оценки модели, метрики RQ-1/RQ-2 с ДИ (RQ-2 — agentic loop против базовых подходов, ADR-0064), сопоставимость с IqraEval (ADR-0033) | `analytics/`, `docs/research/`; код — спецификацией для `/feature` |
| `thesis-writer` | черновики глав из материалов репозитория | `thesis/chapters/*.tex` (ADR-0037) |
| `citation-verifier` | сверка источников с первоисточниками, ГОСТ Р 7.0.5 | ничего (только отчёт) |
| `thesis-opponent` | чтение главы как оппонент на защите | ничего (только отчёт) |
| `solution-architect` | 2–3 варианта устройства до кода, черновик ADR (ADR-0034) | `docs/adr/` (черновик «Предложено») |
| `code-reviewer` | ошибки в коде: логика, async, транзакции, Unicode арабского, время | ничего (только отчёт) |
| `test-auditor` | ловят ли тесты ошибки: пустые проверки, тавтологии, мутанты | ничего (только отчёт) |
| `debugger` | воспроизведение → корень → падающий тест → план | ничего (только отчёт) |
| `learner-simulator` | бот глазами новичка без арабского | ничего (только предложения) |
| `bot-driver` | сам нажимает кнопки в режиме проверки `uv run muallim --test …` (ADR-0045): тупики, падения, текст не про то действие | ничего (отчёт с командой для воспроизведения) |
| `book-proofreader` | арабский текст программы ↔ скан книги, постранично (TD-FN-11) | ничего (только отчёт) |
| `pilot-readiness` | можно ли звать учеников: T1, модель, согласие, копии | ничего (только отчёт) |
| `consistency-auditor` | документы правдивы после изменения, ничего не потеряно (ADR-0039) | ничего (только отчёт) |
| `direction-reviewer` | то ли делаем, что просил автор, и в его ли полномочиях; только с доказательствами, не додумывает — при сомнении вердикт СТОП и вопросы автору (ADR-0047) | ничего (только отчёт) |

**Уровень задачи (ADR-0071).** Субагенты стоят дороже всего остального, потому что каждый
начинает с нуля и заново читает контекст. Поэтому их число зависит от уровня задачи:
**S** (нет нового поведения) — без субагентов, только `make check` и хуки; **M** (одно поведение
в одном слое, без БД, данных, зависимостей и экранов ученику) — тесты и код пишет основной агент,
ревью делает один `code-reviewer` (и `bot-driver`, если менялась кнопка); **L** — полный порядок
ниже. Уровень выбирает агент и называет одной строкой; если сомневается — берёт выше. Хуки
работают на всех уровнях одинаково. `/ship` запускает `consistency-auditor` только для L или
если в diff есть требования, ADR, схема данных, CLAUDE.md.

Порядок в `/feature` (уровень L): `solution-architect` (если затронуто больше одного слоя) →
`tdd-test-writer` → `test-auditor` → человек принимает тесты → `implementer` → `code-reviewer` →
`architecture-guardian` (→ `security-auditor`) → `direction-reviewer` (СТОП → вопросы автору) → `thesis-scribe` → `consistency-auditor` → `/ship`.
Сломалось — `debugger`.

## Скиллы и MCP проекта (ADR-0035)
- Скилл `telegram-bot` (`.claude/skills/telegram-bot/`) — лимиты Bot API, тестовая среда Telegram,
  выход модели Muaalem, правила для кода бота.
- MCP `context7` (`.mcp.json`, версия зафиксирована) — документация aiogram, SQLAlchemy, alembic и др.
  нужной версии; запросы — только названия библиотек и вопросы.

## Команды для агента
`/feature <описание>` — полный цикл; `/ship` — проверки и коммит с push (`docs/process/git.md`); `/adr <тема>` — новое ADR; `/source <ссылка>` — новый источник;
`/report` — отчёт по данным; `/thesis-note <что>` — запись в материалы диплома.
Цикл чтения статей (`docs/research/reading/README.md`): `/read-next [тема]` — что прочитать;
`/read-note <SRC> <мнение>` — карточка с оценкой автора; `/read-draft <раздел>` — текст диплома с `\cite`.
Методика и защита: `/justify [область]` — реестр обоснований (`docs/research/justification.md`);
`/supervisor повестка | итоги …` — встреча с руководителем (`docs/thesis/supervisor/`);
`/defense-drill [тема]` — тренировка защиты, банк вопросов (`docs/thesis/defense/questions.md`).

## Ограничения (честно для диссертации)
- Хук `guard.py` ловит типовые способы записи в `tests/` через shell; хитрый обход возможен —
  его ловят ревью diff и CI.
- Агент не размечает данные и не правит учебный контент: это зона ответственности человека.
