# CLAUDE.md

Telegram-бот — тренажёр чтения по учебнику «Аль-Муаллим ас-Сани» (магистерская диссертация,
дальше — докторантура). **Ученики — русскоязычные, учат арабское чтение С НУЛЯ**
(`docs/requirements/audience.md`): каждое решение проверяй этим. Ученик шлёт голосовое → модель Quran Muaalem распознаёт фонемы →
`domain.assessment` находит ошибки → бот объясняет их по-русски → попытка сохраняется для исследования.

## Команды
| Команда | Что |
|---|---|
| `make check` | ruff + mypy --strict + import-linter + pytest с покрытием (как CI) |
| `uv run pytest -q` | тесты (< 10 с, без модели и сети) |
| `make run-stub` | бот без модели |
| `make db-up` · `make migrate` · `make backup` · `make restore d=…` | PostgreSQL в Docker, миграции (сначала копия), резервная копия, восстановление (только человек) |
| `make report` · `make verify` · `make errors a="--letter ص"` | отчёты, сверка БД и файлов записей, каталог ошибок (`docs/data/browsing.md`) |
| `scripts/phase [tests\|impl\|off]` | TDD-фаза; в `impl` хук запрещает править `tests/` |
| `make trace` | требования ↔ тесты сейчас, отпечаток версии (`docs/requirements/verification-status.md`) |
| `make thesis` · `make thesis-check` | диссертация LaTeX → `thesis/build/main.pdf` |
| `/ship` | проверки → сверка документов → коммит → push (`docs/process/git.md`) |

## Кто что решает
**Только человек:** учебный контент (`curriculum/`, буквы, огласовки, переводы, подсказки), тексты
ученику (`texts.py`, `feedback.*.yaml`, включение языков), эталонные записи, методика и пороги (`domain/policy.py`, `docs/pedagogy/methodology.md`),
параметры чтения (`MOSHAF_PARAMS`), текст согласия, разметка данных, новые зависимости, изменения
схемы БД, удаление/ослабление тестов и проверок, всё про персональные данные. Коммит и push
готовит агент командой `/ship`, человек подтверждает каждый (ADR-0039, `docs/process/git.md`).

**Агент сам, с отчётом одной строкой:** имена, внутренняя структура, вспомогательные функции,
раскладка тестов, выбор между равноценными реализациями, документация.

Арабский текст и подсказки по таджвиду агент только **предлагает** со ссылкой на источник.

## Протокол решений (ADR-0021)
- Есть выбор → **не выбирай молча**: таблица из 2–4 вариантов (плюсы, минусы, рекомендация) — `/decide`.
- Выбранное и **отклонённое** с причинами → ADR (`/adr`). Отложенное → `docs/tech-debt.md`.
- В конце сессии → сводка в `docs/journal/sessions/ГГГГ-ММ-ДД.md` (`/session-summary`).

## Как вести изменение
Полный цикл — `/feature <задача>` (описание: `docs/process/agent-harness.md`).
1. Требование (FR/NFR) → если неясно, один вопрос с вариантами.
2. `scripts/phase tests` (с подтверждения) → падающие тесты → человек принимает.
3. `scripts/phase impl` → код до зелёного `make check`.
4. Ревью: architecture-guardian, при необходимости security-auditor.
5. thesis-scribe: CHANGELOG, ADR (и отклонённые варианты), трассировка, materials-log.
6. consistency-auditor: документы правдивы, ничего не потеряно (хук doc_sync ловит механическое).
7. `scripts/phase off` → сводка: что сделано, что упрощено, что проверить в Telegram → `/ship`.

## Правила кода
- Слои проверяет import-linter (ADR-0002). Нарушение = красный CI и блок Stop-хука.
- Новая внешняя зависимость → порт в `application/ports` + адаптер в `infrastructure`.
- Новый сценарий → регистрация в `bootstrap/di.py` (это проверяет тест).
- Схема БД → `tables.py` + миграция + `docs/data/data-dictionary.md`.
- Источник идеи/числа → ключ `SRC-NNN` из `docs/research/sources.md`.

## Стоп-сигналы
Остановись и спроси, если: тест кажется неверным; нужно менять контент или методику; проверка
опровергла гипотезу; хочешь повторить попытку без новой информации; задача выходит за рамки.

## Нельзя
- Читать `.env`, `data/`, дампы БД (там голоса и данные учеников) — хук заблокирует.
- Обходить хуки и проверки, `--no-verify`, force push.
- Придумывать библиографические данные и огласовки.
